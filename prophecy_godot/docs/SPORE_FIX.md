# 포자 괴물(spore) 결함 수정

2026-09-08. 사용자가 직접 플레이하고 확정한 결함 하나와 그 수정을 적는다.
여기 적힌 수치는 전부 **시험값**이며 사람이 승인한 균형값이 아니다.

- 규칙 코드: `scripts/rules/enemies.gd`(포자 절), `scripts/rules/combat_state.gd`의 `hit_protected()` 한 함수
- 시험값 표: `data/pacing.json`의 `"spore"` 블록(생성 파일인 `data/enemies.json`은 손대지 않았다)
- 검사: `tests/spore_tests.gd` (`python tools/run_suites.py --suites spore_tests`)
- 대조군 스위치: `PROPHECY_SPORE_LEGACY=1` — 수정 전 동작을 그대로 되살린다(게임 기본값 아님)

---

## 1. 수정 전 동작

사용자 관찰: **"포자가 폭발이 닿지 않는 거리에서 멈춰, 플레이어가 가만히 있어도 공격을 맞지 않았다."**

코드에서 확인한 원인은 단순한 수치 어긋남이었다.

| 값 | 수정 전 | 출처 |
|---|---|---|
| 준비를 시작하는 거리 `engageDist` | **130** | `data/enemies.json` spore |
| 폭발(구름) 반경 `cloudR` | **80** | 같은 곳 |
| 구름 피해 판정 | 중심에서 `cloudR + 플레이어 반지름 × 0.5` = **87** | `CombatState.update_zones` |

포자는 130에서 멈춰 부풀고, 그 자리에 반경 80짜리 구름을 놓았다. 판정 한계가 87이므로
**가만히 선 플레이어까지 43px이 모자랐다.** 예고 중에 따라오지도 않으니 서 있기만 하면 무해했다.
게다가 빈틈(1.6초)이 끝나면 이미 130 안이라 곧바로 다시 부풀었다 — 아무 일도 일어나지 않는 예고만 반복했다.

몸이 겹쳐도 아무 일이 없었다(이 게임의 적은 원래 접촉 피해가 없다).

## 2. 확정된 수정(사용자 결정)

1. 폭발이 겨우 닿는 바깥쪽에서 멈추지 않고 **충분히 접근한 뒤** 준비한다.
2. 준비를 시작하면 **그 위치에 멈추고** 범위를 예고한다.
3. **예고 중에는 플레이어를 따라가지 않는다** — 폭발 중심을 준비 시작 자리에 고정한다.
4. 실제 몸이 겹치면 **포자 개체별 접촉 피해**가 있다.
5. 여러 포자와 겹치면 **개체 수만큼 피해가 중첩**된다.
6. 각 포자에 **접촉 재타격 간격**을 두고 매 프레임 피해는 금지한다.
7. **회피 무적은 그대로 적용한다.**

## 3. 시험값

`data/pacing.json` → `"spore"`. 규칙 코드에 숫자를 두지 않고 이 표가 정본이다.

| 이름 | 값 | 뜻 |
|---|---|---|
| `approach_frac` | **0.5** | 준비를 시작하는 중심 간 거리 = `cloudR × 0.5` = **40**(수정 전 130) |
| `contact_damage` | **3** | 몸이 겹칠 때 포자 **개체당** 피해 |
| `contact_interval` | **1.0초** | 포자 **개체별** 접촉 재타격 간격 |

**몸 크기 반영.** 접근 거리는 `max(cloudR × 0.5, 포자 반지름 + 플레이어 반지름)`으로 잡는다.
지금 값으로는 `max(40, 18 + 14 = 32) = 40`이라 40이 이긴다. 몸이 커도 서로 파고든 자리에서
멈추라고 요구하지 않으므로 예고 원과 실제 판정이 어긋나지 않는다.
접촉 판정도 같은 몸 크기를 쓴다 — 중심 간 거리 ≤ `18 + 14 = 32`.

**멈춤.** 준비 거리 안에 들어오면 더 밀고 들어가지 않는다(수정 전에는 준비를 시작할 때까지 계속 걸어 들어갔다).
준비를 시작한 좌표를 `swell_x/swell_y`에 고정하고, 예고 원(`PEnemies.threats`)과 실제 구름이 **같은 자리**를 쓴다.

## 4. 피격 보호 처리 순서

한 프레임(`CombatState.step`)의 순서는 다음과 같다. **이 순서가 규칙이다.**

```
update_player   회피 무적 갱신 · 공통 보호(hit_prot) 남은 시간 감소
update_enemies  st.enemies 목록 순서대로 각 적을 갱신
                └ 포자: 갱신 맨 처음에 접촉 판정 → 그 뒤 상태 기계(접근/준비/빈틈)
                └ 늑대 등: 기존 그대로
update_zones    프레임 끝. 포자 구름(장판) 피해를 zone_tick(0.5초) 간격으로 계산
```

피해 한 건이 지나는 관문은 `damage_player`에서 이 순서다.

1. 죽음·전투 종료·도입부 → 막힘
2. **회피 무적**(`dodge_active`) → 막힘. **접촉 피해도 여기서 막힌다**(요구 7)
3. **공통 피격 보호**(`hit_protected`) → `"spore:contact"`만 **면제**, 나머지는 예전 그대로
4. 피해 적용 → 그 뒤 **모든 출처가** 공통 보호를 `cfg.player.hit_protect`(0.6초)로 **세운다**

여기서 나오는 결론:

- **포자끼리는 서로를 지우지 않는다.** 세 포자와 동시에 겹치면 세 번 다 들어간다(3 × 3 = 9).
  연타는 개체별 재타격 간격(1초)이 막는다.
- **포자 접촉이 먼저 계산되면** 공통 보호가 서므로 같은 프레임에 뒤따르는 늑대 물기는 **막힌다**.
- **일반 공격이 먼저 계산되면** 공통 보호가 서 있어도 포자 접촉은 면제라 **그대로 들어간다**.
- 어느 쪽이 먼저인지는 `st.enemies`의 순서(등장 순서)가 정한다. 난수가 아니라 목록 순서다.
- 접촉 재타격 간격은 **닿는 순간** 선다(막혔는지와 무관). 늑대 물기가 회피당해도 그 공격을 소모하는 것과 같은 규칙이며,
  회피 무적 중에 매 프레임 "회피!"가 뜨는 연타도 이것으로 막는다.
- 구름(장판) 피해는 이 경로가 아니라 `zone_damage` → `apply_player_damage`로 가며 예전처럼 `zone_tick`만 쓴다.

`tests/spore_tests.gd`가 이 네 가지 경우를 모두 단언한다.

> **경계 주의.** `combat_state.gd`에서 바꾼 곳은 `hit_protected()` **한 함수뿐**이다.
> 그 함수는 순환 참조(파싱) 때문에 `PEnemies.SPORE_CONTACT_SRC` 상수 대신 같은 글자 `"spore:contact"`를 직접 쓴다.
> 두 값이 어긋나면 면제가 조용히 풀리므로 `tests/spore_tests.gd`가 같은지 단언한다.

## 7. 남은 문제

1. **표시와 판정의 미세한 어긋남(예전부터 있던 것).** 구름 피해 판정은 `cloudR + 플레이어 반지름 × 0.5`(87)인데
   화면과 예고 원은 `cloudR`(80)만 그린다. `update_zones`와 `render.gd`는 이번 담당 범위 밖이라 손대지 않았다.
2. **예고 원의 출처가 두 곳이다.** 규칙 쪽 `PEnemies.threats`는 고정된 폭발 중심을 쓰지만,
   `scripts/game/render.gd`와 `scripts/rules/bot.gd`의 그림은 여전히 포자 몸 좌표(`e.x`)로 그린다.
   준비 중에는 포자가 스스로 움직이지 않으므로 보통은 같은 자리지만, 플레이어가 몸으로 밀면
   (겹침 해소 규칙) 몸만 밀리고 폭발 중심은 남는다. 두 파일 모두 이번 담당 범위 밖이다.
3. **정예 '역병 조율사'(`elite_plaguecaller`)는 손대지 않았다.** 그쪽은 포자를 플레이어 주위에 던져 놓으므로
   같은 결함이 없다(`enemies_new.gd`의 `_place_pods` 확인). 접촉 피해도 주지 않는다.
4. **접촉 피해가 세우는 공통 보호가 다른 공격을 가릴 수 있다.** 4절의 정한 순서대로지만,
   포자 무리 안에서 싸우면 늑대 물기가 자주 지워질 수 있다. 실제로 문제가 되는지는 아직 계측하지 않았다.
5. 접근 거리·접촉 피해·재타격 간격은 **첫 시험값**이며 사람 승인 균형값이 아니다(5절 참고).

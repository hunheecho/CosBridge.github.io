# 냉기·빙결·파쇄와 쌍검 집중 중첩 — 화면 표시 (2026-09-09)

자료 이름의 정본은 `docs/FROST_CONTRACT.md`다. 이 문서는 **그 자료를 화면이 어떻게 그리는가**만 적는다.
규칙·수치는 하나도 바꾸지 않았다. 모든 수치는 **시험값**이다.

## 0. 지킨 선

- **새 큰 패널·상시 설명문을 만들지 않았다.** 모든 표시는 그 개체 둘레에만 그린다.
  닿는 거리는 `PRender.mark_reach()`가 셈하고, `PRender.mark_limit()`(= 몸 반지름 ×1.4 + 18px,
  기존 냉기 둔화 점선 고리와 같은 자리) 안인지를 `tests/render_tests.gd` 7-8절이 잰다.
- **색만으로 가르지 않는다.** 중첩/최대, 빙결/보스 결빙, 무해한 잔상/실제 피해는 전부 **도형**이 다르다.
- **표시는 전투 난수(`st.rng`)를 소비하지 않는다.** 표시용 난수는 `PRender.fx_rng()`(연출의 자리·파편 수로 씨를 만든다)뿐이다.
- 새 표시는 전부 **개체 층**에서 그린다 → 적 공격 예고(`draw_telegraphs`)가 언제나 그 위다.

## 1. 쌍검 '집중 중첩' (계약 5절 · `w.focus_id` · `w.focus_n` · `w.focus_t`)

겨눈 적에게 타격이 실제로 들어갈 때마다 중첩 +1(최대 6), 중첩마다 그 적에게 주는 쌍검 피해 +8%,
대상이 바뀌거나 1.2초 동안 못 치면 풀린다 — **규칙은 그대로**이고 화면만 붙였다.

| 상태 | 그리는 것 |
|---|---|
| 중첩 0 | **아무것도 그리지 않는다** |
| 1 ~ 5 | 대상의 몸을 감싸는 **눈금 고리**(반지름 = 몸 + 7px). 칸 수 = `maxStack`(6), 채운 칸 수 = 현재 중첩. 빈 칸은 옅게 남겨 '몇 칸 중 몇 칸'이 읽힌다 |
| 6 (최대) | 눈금을 지우고 **닫힌 고리 두 겹 + 바깥 가시 여섯**으로 **모양을 바꾼다**. 고리 하나가 맥동한다 |

- 고리 맨 위의 **작은 X(7px)** 가 '이건 쌍검의 집중'이라는 표식이다 — 냉기의 점선 고리·표식(mark) 고리와 헷갈리지 않는다.
- 남은 유지 시간이 0.4초 아래면 옅어진다(곧 풀린다는 예고). 최소 투명도 0.3.
- 색은 규칙이 최대 중첩에서 내는 글자 '깊은 상처!'와 같은 계열(`#ff8a8a` / `#ffd0d0`)이라 둘이 이어져 읽힌다.
  채운 붉은 부채꼴(= 적 예고 위험)과 달리 **선만** 쓰므로 위험 표시와 섞이지 않는다.
- **갱신 시점**: 대상 변경·시간 만료·대상 사망이 규칙과 같은 순간에 반영된다.
  - 변경·만료 — `PWeapons.dagger_focus_view()`가 규칙(`dagger_focus`)과 **똑같은 식**(`st.t − f.t > window`)으로 판정한다.
  - 사망·은신 — `PRender.focus_plan()`이 그 자리에서 끊는다(규칙 값이 남아 있어도 화면은 안 그린다).

## 2. 냉기 중첩 (`chill_n`)

- 몸 왼쪽에서 위로 자라는 **서리 눈금**(0.38rad 간격, 몸 밖 2 ~ 8px). **눈금 수 = `chill_n`**.
- `chill_n == 0`이면 아무것도 안 붙는다.
- 기존 둔화(`chill`)의 **점선 고리**와는 별개다 — 뜻이 다르므로 도형도 다르다.

## 3. 빙결(`freeze_kind == "hard"`)과 보스 결빙(`"soft"`)

`freeze > 0`일 때만 그린다. **그리는 요소 자체가 다르다.**

| | 빙결 hard (일반·정예) | 결빙 soft (보스) |
|---|---|---|
| 몸 | `shell` — 몸을 덮는 **육각 얼음**(몸 ×1.25 + 4px, 채움 30% 반투명 + 밝은 테두리) | `patch` — 몸에 붙은 **서리 조각 셋**(열린 호). 덮개가 아니다 |
| 속 | `crack` — 결정 금 세 줄 | (없음) |
| 발밑 | `lock` — **실선** 서리 타원 고리 + 좌우 쐐기 = **움직임이 멎었다** | (없음) |
| 움직임 | (없음) | `drift` — 서리 알갱이 다섯이 둘레를 **돈다** = 여전히 움직인다 |

- **보스 결빙에는 `shell`·`lock`을 절대 넣지 않는다** — 몸을 완전히 멈춘 것처럼 그리지 말라는 사용자 지시다.
- 얼음 덮개는 반투명이라 실루엣과 예고 부위가 비쳐 보이고, **적 공격 예고는 그 뒤에 그려 언제나 위**다.

## 4. 파쇄 (`st.fx({"kind":"shatter", …})`, 계약 3절)

- **파쇄 표시는 이 신호에만 반응한다.** 빗나간 공격은 신호가 오지 않으므로 파쇄가 보일 수 없다.
- **그리는 파편 수 = 신호의 `shards`.** 장식 파편을 하나도 더하지 않는다(`PRender.shatter_plan()`이 그 개수만큼만 방향을 만든다).
- 파편은 **채운 쐐기** — 이 파일의 규약(점선·윤곽 = 무해한 잔상, 채움 = 실제 피해)대로 실제 피해임을 도형으로 말한다.
- 깨진 자리에는 밖으로 벌어지는 **육각 테두리** 한 겹(짧게 한 번).
- 방향은 `fx_rng`(표시 전용)로만 흔든다. 같은 연출은 매 프레임 같은 모양이라 파편이 떨리지 않는다.
- 궁 개조 '깨지는 수정'의 `shatter_burst` + `shard(mod=shatter)`는 **다른 것**이다(그대로 둔다).

## 5. 규칙 담당(work/frost)이 계약과 다르게 만들면

`scripts/game/render.gd`의 `frost_plan()`(적 필드) · `shatter_plan()`(파쇄 신호) ·
`scripts/rules/weapons.gd`의 `dagger_focus_view()`(집중) — **이 세 함수만** 고치면 된다. 그리는 코드는 계획만 읽는다.

## 6. 사람이 눈으로 봐야 할 것

'표시가 있는가'가 아니라 **'싸우면서 중첩과 대상을 알아볼 수 있는가'** 를 본다.

1. 쌍검으로 무리를 벨 때 **지금 겨눈 적이 누구인지**와 **중첩이 몇인지**가 손을 멈추지 않고 읽히는가.
2. 최대 중첩(6)에 닿은 순간이 **1~5와 확실히 달라 보이는가**.
3. 대상을 바꾸거나 1.2초 놓쳤을 때 표시가 **바로** 사라지는가(잔상이 남지 않는가).
4. 얼어붙은 일반 적이 **멎어 보이는가**. 같은 화면의 보스 결빙이 **멈춘 것처럼 보이지 않는가**.
5. 얼음 위로 적의 공격 예고가 **그대로 잘 보이는가**.
6. 파쇄가 터질 때 **맞은 순간과 파편이 같은 박자로** 보이는가. 빗나갔을 때 파쇄가 보이지는 않는가.

화면을 PNG로 남기려면: `PROPHECY_RENDER_SHOT=<폴더>`를 주고 창 모드로 `tests/render_tests.gd`를 돌린다.

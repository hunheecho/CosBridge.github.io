# 판본 규칙 (2026-09-09 사용자 확정)

> "dafc8bc 이런 식으로 하지 말고 **버전을 우리가 정하자**. 1.1.0이잖아 그거를 표시해줘.
>  앞으로 작게작게 수정하는 건 1.1.1, 1.1.2 이런 식으로 하고, 좀 큼직한 건 1.2.0 이렇게 가고."

## 1. 번호를 어떻게 올리나

| 무엇을 했나 | 어떻게 | 예 |
|---|---|---|
| 작은 수정 — 버그 고침, 문구·표시 고침, 값 조정 | 끝자리 +1 | 1.1.1 → 1.1.2 |
| 큼직한 변경 — 새 기능, 규칙 구조 변경, 눈에 띄는 개편 | 가운데 +1, 끝자리 0 | 1.1.9 → 1.2.0 |
| 완성·큰 단계 | 앞자리 +1 | 1.9.x → 2.0.0 |

**배포할 때마다 끝자리를 올린다.** 그래야 "지금 네가 보는 게 어느 판이냐"에 번호 하나로 답할 수 있다.
같은 번호로 두 번 올리면 그 질문에 답할 수 없게 된다.

## 2. 어디를 고치나 — 한 곳뿐이다

`scripts/game/game.gd`

```gdscript
const VERSION := "1.1.1"
```

이 값이 정본이다. 제목 화면·설정 화면·`version.json`·빌드 파일 이름이 전부 여기서 나온다.
다른 곳에 판본을 손으로 적지 않는다.

## 3. 화면에 어떻게 보이나

| 자리 | 보이는 것 | 왜 |
|---|---|---|
| 제목 화면 맨 아래 | `v1.1.1` | 사람이 읽고 말하기 쉬운 번호 하나 |
| 설정 화면 | `v1.1.1 · 빌드 dafc8bc` | 문제를 좁힐 때 필요한 커밋 표식 |
| `version.json`(배포) | `build`(해시) · `game_version`(번호) 둘 다 | 로더가 판을 구분할 때는 해시를 쓴다 |

**커밋 해시를 제목 화면에 붙이지 않는다.** 예전에는 `godot-1.1.0 (dafc8bc)`로 보여 줬는데,
사람이 읽고 옮겨 말하기 나빴다(2026-09-09 지적).

## 4. 해시는 왜 아직 쓰나

배포 폴더는 `b/<커밋 해시>/`로 나눈다. 이건 **캐시가 섞이지 않게** 하려는 것이고
사람에게 보여 주는 이름이 아니다. 같은 번호로 두 번 올려도 폴더가 달라 옛 파일과 새 파일이 안 섞인다.
로더와 옛 판 되돌리기(KD-10)도 해시로 판을 가른다.

## 5. 올릴 때 순서

1. `scripts/game/game.gd`의 `VERSION`을 올린다.
2. 무엇이 바뀌었는지 이 파일 6절에 한 줄 적는다.
3. 커밋한다.
4. `python tools/deploy_web.py --out ../prophecy_godot_build/deploy` → 배포.
5. 사용자에게 **번호로** 알린다("v1.1.2 올렸습니다. 제목 화면 맨 아래를 보세요").

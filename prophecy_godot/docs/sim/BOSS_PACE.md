# 보스 행동 개편 — 공격 빈도 개선 전/후 (2026-09-08, 시험값)

**이 문서의 모든 수치는 시험값이다. 사람이 승인한 균형값이 아니다.**
봇은 **가상 조작 모델**이며 사람 승률이 아니다 — **사람 보정 미완료**.
바꾼 것은 **행동뿐**이다. 보스 체력(HP)·피해량·예고 시간은 이 작업에서 손대지 않았다.

- 대상 커밋: `claude/prophecy-action-prototype-hehbeo` 073f74f 기준.
- 새 수치가 있는 곳: `data/boss_behavior.json` (하나뿐. 코드에는 숫자를 두지 않았다).
- 되돌리기: `boss_behavior.json`의 `"enabled": false` → 073f74f 행동과 완전히 같다(개편 전 계측이 그 상태에서 나온 값이다).
- 사용자 요청 원문(§6): 분당 실제 공격 개시 최소 2.5배 시험, 모든 예고·빈틈을 0.4배로 일괄 단축 금지, 근거리 대응·이동 중 공격·연계로 올릴 것, 감속장(Q)을 조용히 약화하지 말 것, 가만히 있다고 즉사 패널티를 주지 말 것.

## 0. 무엇을 바꿨나 (요약)

## 1. 고정 조건 계측 — 분당 공격 개시 (개선 전 → 후)

생성: `godot --headless --path prophecy_godot -s tests/boss_pace_tests.gd` (통과/실패 검사도 겸한다).

**측정 조건(고정 실험, 사람 조작이 아님)**: 장애물 없는 전장 `forest`, 시드 11, 60초, 보스 체력 100만(죽지 않음), 단계(phase) 고정,

## 3. 감속장(Q) 있음/없음 — Q를 약화하지 않았다는 확인

Q(감속장)는 `time_factor`로 보스의 **준비·이동·실행·빈틈 전부**를 40% 속도로 늦춘다. 이 작업에서 그 규칙을 건드리지 않았다:
- 예고 배속은 `adv = dt × time_factor × warn_speed`에서 `warn_speed`(연계 후속타 전용)만 곱한다. Q의 ×0.4는 그대로 남는다.
- `tests/boss_tests.gd`·`tests/boss3_tests.gd`가 연계를 켠 상태에서 `dt × 0.4`(빈틈·예고 모두)를 직접 확인한다.
- 보스를 Q에서 면제하지 않았고, Q 안에서 보스에게 특별 행동을 주지도 않았다.

대신 **빈틈이 오는 횟수**가 줄었기 때문에, "Q로 늘어난 빈틈에서 공짜 피해를 얼마나 뽑는가"는 자연히 줄어든다. 이것이 행동 설계로 해결한 부분이다(§1-1).

아래 표에서 읽히는 것:
- **Q를 켜면 보스의 분당 공격 개시가 실제로 줄어든다**(예: 가시갈기 상위 56.5 → 51.1, 수호자 평균 70.1 → 63.4, 파수장 상위 53.2 → 46.8). Q는 여전히 보스 행동을 늦춘다.
- **Q를 켠 쪽이 실제 체력 손실이 작다**(가시갈기 평균 20 → 0, 사냥왕 평균 80 → 0, 거수 평균 44 → 8, 추적자 평균 122 → 89). Q의 방어 가치는 살아 있다.
- **보스에게 준 실효 DPS는 Q on/off가 비슷하다**(가시갈기 57.4 → 53.5, 수호자 132.8 → 130.8, 먹는 자 160.5 → 177.6). 즉 Q는 "공짜 딜 창구"라기보다 "맞지 않게 해 주는 도구"로 작동한다. 이것이 §6에서 걱정한 "빈틈이 길어져 공짜 피해가 너무 커지는" 상태를 행동 설계로 눌러 둔 결과다.
- 정책 ①·②는 Q를 1회밖에 못 쓰고(전투가 짧게 끝난다) 차이가 거의 없다. 조작 정책(③)에서 Q 사용 2~4회 구간이 의미 있는 비교다.

## 4. 남은 것 / 사람이 판단할 것

1. **후속타 예고 0.45초 하한이 사람이 읽을 수 있는 길이인가.** 봇은 인식 지연 모델로만 판단하므로 이것을 대신 결정할 수 없다. 이 값 하나(`chain.followWarnMin`)로 난이도가 크게 움직인다.
2. **연계 최대 길이 6/8/10회가 적절한가.** 3단계에서 최대 10회 연속은 강하다. 빈틈 비율이 8~24%까지 내려간다.
3. **2.5배를 못 채운 다섯 보스**(가시갈기 2.45 · 포자 어미 2.45 · 거수 2.39 · 사냥왕 2.38 · 집행관 2.28)를 더 올리려면 실행 시간(돌진 이동·굴착 이동)이나 예고를 줄여야 한다. 요청에 어긋나므로 하지 않았다.
4. **체력(HP)과의 결합 미확인.** 검토 문서 §5의 체력 후보(가시갈기 6,000 / 수호자 15,000 / 포식자 18,000)와 이 행동 개편을 함께 넣으면 전투 시간이 크게 늘어난다. **이 문서의 계측은 현재 체력(hi 세트: 2,400 / 5,000 / 7,000)에서 한 것이다.**
5. **방패병(§7)은 이 작업 범위 밖**이다(`scripts/rules/enemies_new.gd`, 다른 작업 소유). 종말의 집행관의 호위는 그 방패병을 그대로 쓴다 — 방패병의 방어/개방 비율이 바뀌면 집행관 전투도 함께 바뀐다.
6. 사람 플레이 검증 없음. 화면 표시·소리는 새로 만들지 않았다(상태 이름과 예고 도형을 재사용했으므로 `render.gd`·`observe.gd`는 손대지 않아도 된다).

# 회차 판본(run_version) — 옛 회차를 어떻게 가르나 (2026-09-10 사용자 확정)

## 0. 사용자 확정 사항 (다시 결정 대기로 올리지 않는다)

> - 이전 회차의 장비·패시브를 새 규칙으로 **이전하는 작업은 하지 않는다.**
> - 이전 회차는 **이어하기를 막고** "대규모 업데이트로 새 회차를 시작해야 합니다"라고 안내한다.
> - 회차 호환 여부는 **명시적인 저장 판본**으로 구분한다.
>   **자료에 없는 장비가 있는지만으로 판별하지 않는다.**
> - **프로필·도전과제·처치 기록·설정까지 초기화하는 승인은 아니다.**

## 1. 판본을 어디에 적고 어디서 읽나

| 무엇 | 어디 |
|---|---|
| 현재 판본 상수 | `scripts/rules/save.gd` `const RUN_VERSION := 2` (판본 이력 주석이 같은 자리에 있다) |
| 판본을 적기 전의 파일 | `const LEGACY_RUN_VERSION := 1` — 파일에 `run_version` 이 **없으면 1로 본다** |
| 파일에 적히는 자리 | 저장 파일 맨 위: `{"schema": …, "saved_at": …, "run_version": 2, "run": {…}}` |
| 읽는 자리 | `PSave.file_run_version(doc)` → `PSave.load_result()` 가 현재 판본과 비교한다 |
| 화면 문구 정본 | `PSave.VERSION_MESSAGE` = "대규모 업데이트로 새 회차를 시작해야 합니다" |

`run_version` 은 **회차 사전 밖(doc 맨 위)** 에 적는다. 회차 사전을 건드리지 않으므로
저장 전후로 `run` 을 통째로 비교하는 기존 검사들이 그대로 성립한다.

### 판본 이력

| 판본 | 무엇이 달라졌나 |
|---|---|
| 1 | 판본을 적기 전의 모든 저장 |
| 2 | 2026-09-10 대규모 개편. 장비가 개체(`<종류>#N`)와 강화 단계(`run.equipPlus`)로 바뀌고, 수동 기술 창고(`growth.bank`)와 장비 기술(`eq_*`)이 들어왔다. 이전 회차를 이전하지 않기로 정했으므로 판본 1 은 이어할 수 없다 |

## 2. 왜 `schema` 를 올리지 않았나

`schema` 를 올리면 `PSave.load()` 가 **파일을 `.corrupt` 로 이름을 바꿔 밀어낸다.** 두 가지가 문제다.

1. 사람의 저장을 옆으로 치워 버린다. 사용자 확정은 "이어하기를 막는다"이지 "파일을 치운다"가 아니다.
2. 화면이 **"저장이 깨졌다"와 "판이 바뀌었다"를 구분하지 못한다.** 둘 다 `{}` 로 돌아왔다.

그래서 파일의 겉모양(`schema = "prophecy_save/1"`)은 **그대로 두고** 판본만 따로 적는다.
`.corrupt` 보관은 정말로 겉모양이 깨진 파일에만 남겨 뒀다(예전 동작 그대로).

## 3. 불러오기 결과는 셋(넷)으로 갈린다

`PSave.load_result()` → `{ status, run, file_version, current_version, message }`

| status | 뜻 | 파일에 무슨 일이 일어나나 |
|---|---|---|
| `PSave.LOAD_OK` (`"ok"`) | 정상 — `run` 에 회차가 있다 | 아무 일도 없다 |
| `PSave.LOAD_NONE` (`"none"`) | 저장이 없다 | 아무 일도 없다 |
| `PSave.LOAD_VERSION` (`"version"`) | **판 불일치 — 이어하기 불가** | **아무 일도 없다. 지우지도, 이름을 바꾸지도 않는다** |
| `PSave.LOAD_BROKEN` (`"broken"`) | 파일이 깨졌다 | 예전처럼 `.corrupt` 로 보관 |

기존 호출부를 위해 `PSave.load()` 는 그대로 남아 있다 — 이어할 수 있는 회차만 돌려주고 아니면 `{}`.
사유가 필요한 쪽(제목 화면·`main.continue_run`)만 `load_result()` 를 쓴다.
`PSave.continuable()` 은 "지금 이어할 수 있나" 한 줄짜리 물음에 답한다.

## 4. 옛 저장 파일은 그대로 둔다

판이 달라도 **파일을 지우거나 이름을 바꾸지 않는다.** 사람이 새 회차를 시작하면
그때 정상 저장 경로(`PSave.save`)가 덮는다 — 치우는 것이 아니라 덮는 것이다.

**프로필(`user://prophecy_profile_v1.json`)·도전과제·처치 기록(`user://prophecy_records_v1.json`)·설정은
이 흐름에서 한 바이트도 건드리지 않는다.** 판이 달라도 그대로 살아 있다.

## 5. 판별은 판본으로만 한다

"자료에 없는 장비가 들어 있으니 옛 회차겠지" 같은 짐작으로 가르지 **않는다.**
없는 장비를 걸러내는 `PSave._drop_unknown_equipment` 는 예전 그대로 남아 있고,
**없는 장비가 든 현재 판본 저장은 정리한 뒤 그대로 이어진다.**
`tests/save_version_tests.gd` [5] 가 그 장면을 값으로 못박는다.

## 6. 제목 화면

`scripts/game/screens/title.gd`

- '계속하기' 버튼을 **감추지 않는다.** 감추면 모바일에서 사라진 자리를 키로 대신할 수 없다(예전 지적).
- 자리에 그대로 두고 `disabled` 로 만든다. 글자는 `계속하기  (이어할 수 없음)`.
- 바로 아래에 사유를 글자로 붙인다 — `대규모 업데이트로 새 회차를 시작해야 합니다`.
- 그 아래 한 줄 더: `이전 회차 저장 파일은 지우지 않았습니다. 영구 성장·도전과제·처치 기록·설정은 그대로입니다.`
- '새 회차'·'영구 성장'은 그대로 눌린다 — 앞으로 갈 길이 막히지 않는다.

`main.continue_run()` 도 같은 사유를 `message()` 로 알리고 회차를 열지 않는다.

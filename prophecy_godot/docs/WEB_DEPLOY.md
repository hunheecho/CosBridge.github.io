## 4. 같은 주소에 패치를 반영하는 방법 — 캐시가 섞이지 않는다

뿌리 `index.html`은 게임이 아니라 **로더**다. 하는 일은 이것뿐이다:

```js
var r = await fetch('version.json?ts=' + Date.now(), { cache: 'no-store' });
location.replace(v.path + '?v=' + v.build);      // 예: b/cb74c6e/?v=cb74c6e
```

- **판마다 폴더가 다르다**(`b/<커밋>/`). 옛 판의 `index.wasm`과 새 판의 `index.pck`가 섞일 수 없다 — 이름이 같아도 경로가 다르다.
- 판본을 묻는 요청은 **캐시를 쓰지 않는다**(`?ts=` + `cache: no-store`). 로더 자체가 브라우저 캐시에 남아 있어도 **새 판으로 간다.**
- 이미 열어 놓고 플레이 중인 화면은 파일을 이미 받아 놓았으므로 **그대로 계속 돌아간다.** 강제 새로고침을 걸지 않는다.
- 갱신은 `tools/deploy_web.py`를 다시 돌리고 배포 저장소에 push하면 끝이다. **주소는 바뀌지 않는다.**
- 옛 판 폴더는 기본 2개(현재 + 직전)만 남기고 정리한다(`--keep`).

**한 가지 한계**: GitHub Pages는 HTML에 `Cache-Control: max-age=600`을 붙인다.
로더 껍데기 자체가 최대 10분간 캐시될 수 있다. 그래도 로더가 하는 일이 "캐시 없이 판본을 묻는 것"이라
**판이 바뀐 것은 즉시 반영된다.** 껍데기가 바뀌는 일은 거의 없다.

## 5. 화면에 판본을 표시한다

제목 화면 맨 아래에 이렇게 나온다:

```
godot-1.1.0 (cb74c6e) · 시험 빌드 (경험치 ×0.3)
```

- `godot-1.1.0` = 게임 판본(`scripts/game/game.gd` `VERSION`)
- `(cb74c6e)` = **배포한 커밋 표식.** `tools/deploy_web.py`가 내보내기 직전에만 `data/build.json`을 만들어
  pck 안에 넣고, 끝나면 지운다(소스에 남기지 않는다). `PUi.build_stamp()`가 그 값을 읽는다.
- 개발 중 실행에는 그 파일이 없으므로 예전과 같은 문자열이 나온다.

**폰에서 업데이트를 확인하는 방법**: 주소를 열고 제목 화면 맨 아래 괄호 안 표식을 본다.
새 판을 올렸다고 알린 표식과 같으면 갱신된 것이다. 다르면 **주소를 한 번 더 새로고침**한다.

## 6. 저장 데이터는 업데이트 뒤에도 남는다 — 실제로 확인했다

웹의 `user://` 저장은 브라우저 **IndexedDB**에 들어간다. IndexedDB는 **출처(origin) 단위**라
경로(`b/<커밋>/`)가 바뀌어도 같은 저장소를 본다.

말로만 두지 않고 실제로 해 봤다:

1. 배포 폴더에 판을 하나 더 복사해 두 경로를 만들었다(`b/cb74c6e/`, `b/zzfake01/` — 다음 패치를 흉내).
2. `b/cb74c6e/`에서 **새 회차를 시작**했다(1일차·검·시드 21883).
3. 브라우저를 `b/zzfake01/`로 옮겼다.
4. 제목 화면에 **`계속하기 (본편 · 10일 · 1일차 · Lv 1 · 금화 60)`** 와
   **`저장 회차: 시험 빌드 (경험치 ×0.3) · 시드 21883`** 이 그대로 떴다.

즉 **판이 바뀌어도 진행 중인 회차가 남는다.** 확인 뒤 흉내용 폴더는 지웠다.

주의: 브라우저의 사이트 데이터를 지우거나, 시크릿 창으로 열거나, 다른 브라우저로 열면 저장은 없다.
저장은 그 폰의 그 브라우저 안에만 있고 서버로 가지 않는다.

## 8. 다시 배포하는 절차

```sh
cd prophecy_godot
python tools/deploy_web.py --out ../prophecy_godot_build/deploy
cd ../prophecy_godot_build/deploy
git add -A && git commit -m "웹 시험 빌드 <판본> (<커밋>)" && git push
```

- `deploy` 폴더는 **별도 git 저장소**다(`prophecy-web-test`). 본 저장소와 섞이지 않는다.
- 본 저장소의 `.gitignore`가 `prophecy_godot_build/`를 제외하므로 빌드 산출물이 본 저장소에 들어가지 않는다.
- Pages 빌드는 push 뒤 보통 1분 안에 끝난다.

- **기존 사이트(`www.cosbridge.jp`)를 건드리지 않았다.**
- **본 저장소를 push하지 않았다.** 배포한 것은 새 저장소의 실행 파일뿐이다.
- APK 제작·Android SDK 설치는 이번 범위가 아니다.

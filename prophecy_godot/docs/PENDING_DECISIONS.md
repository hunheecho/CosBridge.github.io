# 아직 결정되지 않은 것 — 현재 동작과 제안의 차이

작성 2026-09-10 · 기준 `4d77496`(v1.3.2)

여기 있는 넷은 **사용자가 아직 정하지 않았다.** 결정 전까지
**기존 보유분을 조용히 삭제하거나 다른 것으로 치환하지 않는다.**
지금 코드가 무엇을 하고 있는지와, 고르면 무엇이 달라지는지를 나란히 적는다.

이미 결정된 것은 여기 없다. 그것들은 각 갈래 문서와 커밋에 있다.

---

## 1. 폐기 장비를 이미 보유한 옛 회차의 이전 처리

폐기 장비: `reprisal_shield` 반격 방패 · `relay_shield` 연계 방패

**지금 동작(아무것도 안 한 상태)**

| 자리 | 지금 |
|---|---|
| 자료에 정의 | 남아 있다 |
| 제작 후보 | 빠진다 (`PCatalog.equipment_retired`) |
| 상점 진열 | 빠진다 |
| 도감 총계 | 활성 목록에서 계산하므로 분모에 안 들어간다. 이미 연 기록은 "폐기한 제작법" 줄로 따로 보인다 |
| 이미 가진 개체 | **그대로 쓰인다.** 착용·해제·판매 전부 된다 |
| 저장 복구 | 자료에 있으므로 `_drop_unknown_equipment` 에 걸리지 않는다 |

**정해야 할 것** — 이미 가진 사람에게 무엇을 해 줄 것인가.

| 안 | 내용 | 잃는 것 |
|---|---|---|
| A(지금) | 그대로 둔다 | 없음. 옛 회차와 새 회차의 장비 구성이 달라진다 |
| B | 판매가를 올려 자발적 교체를 유도 | 없음. 경제 값이 하나 늘어난다 |
| C | 같은 칸의 다른 장비로 교환권 지급 | 새 화면·저장 항목이 필요하다 |
| D | 회차 시작 시 자동 회수·환급 | **사람이 고른 장비가 말없이 사라진다.** 권하지 않는다 |

관련: 이 둘은 `upgrade` 표가 비어 있어 강화해도 아무 값도 안 올랐다.
그 **차단은 별도로 확정됐다**(효과 없는 유료 강화 수정). 차단은 삭제가 아니다.

## 2. 빈틈 포착·지속력을 이미 보유한 옛 회차의 이전 처리

**지금 동작**

| 자리 | 지금 |
|---|---|
| 자료에 정의 | 남아 있다 (`passives` 10종 중 2종) |
| 신규 획득 후보 | **빠진다** (`offer: false`, 레벨 0일 때만 건너뛴다) |
| 이미 가진 것 | **그대로 작동한다.** 빈틈 포착 ×2.000 · 지속력 ×1.200 실측 확인 |
| 레벨업 후보 | 이미 가진 것은 계속 올릴 수 있다 |
| 저장 왕복 | 새 패시브와 섞여도 오류 없음 |

**정해야 할 것** — `docs/PASSIVE_SWAP.md` 3절에 5안이 있다. 요약하면:

| 안 | 내용 | 잃는 것 |
|---|---|---|
| A(지금) | 그대로 둔다 | 없음. 옛/새 회차 구성이 달라진다 |
| B | 보유는 유지하되 레벨업 후보에서도 뺀다 | 슬롯 하나가 현재 레벨에 묶인다 |
| C | 같은 레벨로 자동 치환 | **"임의로 치환하지 마라"에 정면으로 걸린다.** 권하지 않는다 |
| D | 슬롯을 비우고 다음 레벨업에 재선택 제시 | 새 제시 종류·저장·화면 변경이 필요하다 |
| E | 회차 시작 시점의 패시브 표를 저장에 고정 | 표 판본이 계속 늘어난다 |

권고: 그대로 두려면 **A**, 옛 패시브를 완전히 없앨 거면 **D**.

## 3. 흡혈에 주무기 개조의 추가 타격을 어디까지 포함할지

**지금 동작**: 흡혈은 `main_direct` **하나만** 적격이다. `main_extra` 는 제외.

### `main_extra` 에 무엇이 섞여 있나 — 세부 출처

`main_extra` 라는 이름 하나에 **성격이 다른 세 무리**가 들어 있다.
`scripts/rules/support_weapons.gd` 의 `cause_of()` 가 셋을 같은 이름으로 부른다.

| 무리 | 무엇 | 어디서 붙나 | 흡혈을 켜면 |
|---|---|---|---|
| ① 주무기 **개조**가 만든 추가 타격 | 검 교차 검격(crescent)·잔류 검흔(scar) · 창 분열 창날(split) · 망치 전방 충격파·여진 · 활 갈래 사격(spread) 등 | `src.extra` 또는 `direct:false` 로 표시된 주무기 타격 | 사용자가 그 무기 개조를 골라서 얻은 몫이 회복으로 이어진다 |
| ② 공용 증강이 만든 주무기 추가 타격 | **메아리**(echo) · **연사**(volley) | `st.attack_cause` 가 "echo"/"volley" 일 때 강제로 `main_extra` | 무기 개조와 무관한 공용 증강이 **조용히 흡혈 자격을 얻는다** |
| ③ 장비 **공성 망치머리**의 착탄점 추가 충격 | 자료 설명에 명시돼 있다 | 같은 이름을 물려받는다 | 장비 하나가 흡혈량을 한 번 더 올린다 |

**그래서 첫 구현에서 껐다.** 이 칸을 그냥 켜면 ②③까지 같이 열린다 —
"기존 출처 분류 오류 때문에 보조 폭발 등이 섞이지 않게 하라"는 지시가 가리킨 자리가 정확히 여기다.

### 고를 수 있는 것

| 안 | 범위 | 필요한 일 |
|---|---|---|
| A(지금) | `main_direct` 만 | 이미 됨. 코드 수정 없음 |
| B | ①②③ 전부 | `data/growth.json` 의 `growth.LIFESTEAL.denied` 에서 `main_extra` 를 빼 `eligible` 로 옮기면 끝. 코드 수정 없음 |
| C | ①만 (개조 추가 타격까지, 공용·장비는 제외) | **자격표에 경로 이름을 하나 더 만들어야 한다.** `cause_of()` 가 ②를 `main_extra` 로 뭉개고 있어 지금 구조로는 갈라낼 수 없다. `data/supports.json` 의 causes 에 새 이름을 넣고 ②③을 그리로 옮기는 작업이 따로 필요하다 |

**영향의 크기**(검 Lv3 1.5%, 피해 100 기준 실측): 적격이면 1.500, 비적격이면 0.
①은 무기·개조에 따라 자동 타격 1회당 추가 타격이 0~2회 붙는다 —
켜면 근접 흡혈량이 무기·개조 조합에 따라 대략 **1.0~2.0배** 사이로 벌어진다.
이 배수는 아직 실제로 재지 않았다. 결정하면 재서 보고하겠다.

## 4. 흡혈에 회복 준비(`heal_mult`)를 적용할지

**지금 동작**: 곱하지 않는다. 지시에 없어 임의로 곱하지 않았다.

| 안 | 내용 | 뜻 |
|---|---|---|
| A(지금) | 안 곱한다 | 흡혈은 회복 증폭과 별개의 계통이 된다 |
| B | 곱한다 | "회복량을 올린다"는 말 그대로가 된다. 흡혈 + 회복 준비를 함께 든 사람의 회복이 곱으로 커진다 |

B 를 고르면 상한 검사가 하나 더 필요하다 — 지금 흡혈은 최대 체력을 넘지 않는 것만 막고 있고,
전투당 회복 상한은 **일부러 두지 않았다**(그것도 확정 사항이다).

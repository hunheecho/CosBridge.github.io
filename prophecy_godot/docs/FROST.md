# 냉기 기본 특성과 서리 개조 3종 (2026-09-09)

사용자 확정 지시를 옮긴 결과다. 자료 모양·계측 이름·화면 신호는 `docs/FROST_CONTRACT.md`가 정본이고,
이 문서는 **규칙이 실제로 어떻게 도는가**와 **시험값의 근거**를 적는다.

> 여기 나오는 숫자는 전부 **시험값**이다(`data/supports.json` → `tuning.frost`).
> 사람이 승인한 밸런스가 아니며, 봇 결과로 재미·균형을 승인한 것도 아니다.

구현:
- `scripts/rules/combat_state.gd` — 중첩·빙결·파쇄 판정의 본체(`add_chill_stack` · `try_shatter` · `_tick_frost`)
- `scripts/rules/weapons.gd` — 서리 수정 발사(`fire_bolt`)와 차가운 바닥 생성
- `scripts/rules/support_weapons.gd` — 경로 어휘 조회(`known_cause`)와 계측 이름 목록
- `data/supports.json` — `eligibility`(자격표) · `tuning.frost`(시험값) · `weapons.frost`(개조 이름·설명)
- `tests/frost_tests.gd` — 아래 규칙을 전부 단언한다(스위트 이름 `frost_tests`)

## 1. 기본 특성 — 개조 없이도 얼고 깨진다

1. **냉기 공격이 적중하면 냉기 중첩이 쌓인다.** 5중첩에 도달하면 그 자리에서 얼어붙는다.
2. **빙결(hard, 일반·정예)** 중에는 이동도 공격도 멈춘다.
3. 빙결 중 **주무기 공격**이 적중하면 **파쇄**한다 — 그 적에게 추가 피해를 주고 주변으로 얼음 파편을 내보낸다.
4. 파쇄하면 빙결이 풀린다. **한 번의 빙결에서 파쇄는 한 번뿐이다.**
5. 파쇄하거나 빙결이 끝나면 중첩을 0으로 되돌리고 **재빙결 제한**을 건다(영구 행동 불능 방지).

**개조는 이 기능을 켜는 것이 아니다.** 서리 수정을 개조 없이 Lv1로 들어도 위 다섯 가지가 그대로 돈다.
서리 수정을 아예 들지 않고 공용 증강 '얼음 파편'만 있어도 언다(냉기 공급원이 하나면 충분하다).

### 얼린 그 타격은 깨뜨리지 않는다

냉기를 실은 **주무기** 타격이 5중첩을 채운 바로 그 `damage_enemy` 호출에서는 파쇄하지 않는다.
그러지 않으면 빙결이 한 프레임도 보이지 않고 '얼리고 → 내가 깬다'는 두 박자가 사라진다.
같은 프레임의 **다음** 타격은 깰 수 있다(중복 정산은 `freeze_broke`가 따로 막는다).

## 2. 냉기 중첩이 오르는 시점 — 공급원별

**중첩은 실제 적중·틱 이벤트로만 오른다.** 화면 프레임 수나 매 프레임 상태 검사로는 절대 오르지 않는다.
매 프레임 도는 `_tick_frost`는 남은 시간만 줄인다.

| 공급원 | 언제 중첩을 주는가 | 한 번에 |
|---|---|---|
| 서리 수정 탄환(기본) | 탄환이 적에게 **적중한 순간**(`damage_enemy` 안) | 1 |
| 넓은 빙결(부채꼴 3발) | **탄환마다 각각** 적중한 순간 | 발당 1 |
| 다중 투사체 일반 | 같은 투사체는 같은 적을 두 번 맞히지 못한다(`pr.hits`) — 서로 다른 탄환만 각각 준다 | 발당 1 |
| 차가운 바닥(빠른 빙결) | 장판 안에 있는 적에게 **`zoneStackTick`(0.5초)마다 한 번** | 틱당 1 |
| 공용 증강 '얼음 파편' | 주무기 **직접 타격**이 적중한 순간 | 1 |
| 지뢰 개조 '서리 함정' | 폭발이 적을 맞힌 순간(냉기를 실은 피해다) | 1 |
| 다른 보조가 실어 나른 냉기 | 그 피해가 냉기를 실었으면(`opt.chill`) 적중 순간 | 1 |

**중복 적중 방지 규칙 두 가지**
- **피해 이벤트 하나는 그 적에게 중첩을 최대 1만 준다.** 공용 증강과 서리 탄환이 같은 타격에 겹쳐도 1이다.
- **장판은 프레임이 아니라 틱마다 준다.** 주사율이 바뀌어도 초당 중첩 수가 같다.

여러 공급원은 **연결된다**(장판 + 탄환 = 초당 3). 막는 것은 '한 번의 적중이 여러 번 세지는 것'뿐이다.

**얼어 있는 동안에는 쌓지 않는다.** 얼어 있을 때 계속 쌓아 두면 해제 직후 곧바로 다시 얼기 때문이다.
재빙결 제한이 걸려 있는 동안에는 쌓이기는 하되(상한까지) 얼지 않으며, 제한이 풀린 뒤 **새 적중**이 있어야 언다
(제한이 풀리는 순간 저절로 얼지 않는다 — 그러면 프레임이 방아쇠가 된다).

## 3. 등급별 — 일반 · 정예 · 보스

| 등급 | 상태 | 지속(시험값) | 이동·공격 |
|---|---|---|---|
| 일반 | 빙결 `hard` | 1.0초 | **멈춘다** |
| 일반 정예 · 특수 정예 | 빙결 `hard` | 0.6초 | **멈춘다** |
| 보스 | **결빙** `soft` | 0.8초 | **멈추지 않는다** |

- **보스의 결빙은 아무것도 멈추지 않는다.** 패턴 단계·예고 타이머·연계를 취소하거나 초기화하지 않는다
  (`update_enemies`가 보스는 정지 분기에 넣지 않는다 — 결빙은 상태 표시와 파쇄 자격만 준다).
- 결빙 중에도 **파쇄 추가 피해와 파편은 그대로 발생한다.**

### 얼린 적의 예고와 실제 판정

빙결(hard)은 그 적의 **행동 갱신을 통째로 건너뛴다.** 그래서 상태(`state`)와 상태 시간(`state_t`),
확정된 방향(`dir`)이 그 자리에 멈추고, 해제되면 멈춘 지점에서 이어 간다.
**빙결 중에는 예고가 진행되지 않고, 예고된 공격도 나가지 않는다.**
해제 뒤에는 예고한 그 방향으로 판정이 난다 — 예고와 실제가 어긋날 수 없다(`frost_tests` 10절이 단언한다).

`enemy_speed_mult`도 빙결 중에는 0을 돌려준다. 행동 갱신 밖에서 움직이는 경로가 새로 생겨도 얼어 있는 동안은 못 움직인다.
겹침 해소(`resolve_overlaps`)만은 얼어 있는 적도 밀 수 있다 — 그것은 그 적의 '이동'이 아니라 몸이 겹치지 않게 하는 처리다.

## 4. 파쇄 — 무엇이 터뜨리고 무엇이 못 터뜨리는가

자격표는 `data/supports.json` → `eligibility.effects.frost_shatter` 한 곳이다. 코드는 `PSupport.eligible`만 본다.

| 경로 | 파쇄 | 왜 |
|---|---|---|
| `main_direct` 주무기 직접 타격 | **O** | 사용자 확정: 파쇄를 터뜨리는 것은 주무기 공격이다 |
| `main_extra` 주무기 개조가 만든 직접 추가 타격 | **O** | 교차 검격·잔류 검흔·분열 창날, 그리고 공용 메아리·일제 공격의 주무기 재타격. 모두 주무기가 낸 타격이다. **장비 '공성 망치머리'의 착탄점 추가 충격**도 여기다 |
| `eq_slash` · `eq_meteor_core` · `eq_meteor_wave` · `eq_riposte` · `eq_retrace` | **O** | **2026-09-10 사용자 확정** — 장비 기술 네 종(찰나 가르기·낙성 강하·받아치기·되짚는 궤적)의 직접 타격. 기술별 경로 이름을 그대로 `allow`에 적었다(묶음 이름을 새로 만들지 않았다) |
| `eq_icetomb` 결정 관 | X | 그 기술은 피해가 아니라 **냉기를 부여**하는 쪽이다(`frost_stack`은 막지 않는다). [9] 유예의 시계는 피해 경로 자체가 없다 |
| `support_direct` 보조무기 공격 | X | 보조가 먼저 깨면 '얼리고 내가 깬다'는 선택이 사라진다 |
| `echo_direct` 잔영 분신의 모방 | X | 분신은 보조다 |
| `zone_tick` 장판(불씨 등) | X | 지속 피해가 저절로 깨면 안 된다 |
| `dot` 출혈·화상·독 | X | 같은 이유 |
| `mine_blast` 지뢰 폭발 | X | 설치 → 폭발이라 직접 타격이 아니다 |
| `doll_blast` · `plague_burst` · `reflect` · `shock_bonus` | X | 보조가 만든 간접 피해다 |
| `frost_shatter` 파쇄 추가 피해 | X | 자기 호출 순환 금지 |
| `frost_shard` 얼음 파편 | X | 연쇄 파쇄 금지. **장비 기술이 깬 파쇄의 파편도 마찬가지다**(실측: 이웃은 파편 피해 6.0만 받고 여전히 빙결) |

**같은 빙결에서 파쇄는 한 번뿐이다.** 이것은 자격표가 아니라 `CombatState.try_shatter`가 맡는다 —
`freeze_broke` 표시를 **먼저** 세우고, 끝에서 `_end_freeze`로 빙결을 끝내며 재빙결 제한(`refreezeSec` 3.0초)을 건다.
그래서 장비 기술로 세 번 때려도 파쇄는 1회이고, 공성 망치머리의 본타 + 추가 충격(+ 여진까지 셋)이어도 1회다.

### 파편이 부르는 것 / 못 부르는 것 (재귀 경로 점검)

파편의 피해는 경로 이름 `frost_shard`로 들어간다. 아래 효과들의 `deny`에 그 이름을 **직접 적어 두었다.**

| 후속 효과 | 파편이 부르는가 | 근거 |
|---|---|---|
| 냉기 중첩(`frost_stack`) | **못 부른다** | 파쇄가 다음 빙결의 밑돌을 놓으면 얼음이 스스로를 먹여 살린다 |
| 파쇄(`frost_shatter`) | **못 부른다** | 옆에서 얼어 있는 적을 파편이 대신 깨뜨리지 않는다 |
| 감전 후속(`shock_bonus`) | **못 부른다** | 한 번의 파쇄가 여러 마리에게 감전을 동시에 터뜨리는 통로가 되지 않게 |
| 까마귀 표적(`crow_mark`) | **못 부른다** | 파편이 스친 적으로 표적이 갈아엎히지 않게 |
| 분신 모방(`echo_copy`) | **못 부른다** | 분신은 주무기 기본 공격만 따라 한다 |
| 독 전염(`plague_spread`) | **부른다** | `allow: ["*"]`. '처치는 무엇으로 죽였든 전염된다'는 기존 규칙을 파편만 예외로 두지 않는다 |
| 처치가 방아쇠인 효과(공용 얼음 파편의 처치 파편·불꽃 파열) | **부른다** | 위와 같은 이유 |

파쇄 추가 피해(`frost_shatter`)도 냉기를 쌓지 않고 다시 파쇄하지 않는다.

### 중복 정산

- `freeze_broke`를 **추가 피해를 주기 전에** 세운다. 같은 프레임에 여러 타격이 들어와도 파쇄는 한 번이다.
- 파쇄는 피해가 실제로 들어간 뒤에만 판정한다. **빗나간 공격에서는 화면 신호도 나오지 않는다.**

### 파편은 투사체가 아니다

파편은 **즉시 반경 판정**이다(가까운 순서, 같으면 id 순서로 최대 `shards`마리). 난수를 쓰지 않는다.
계약 3절이 "그린 파편 수 = 실제 판정에 쓰인 수"를 요구하기 때문이다 — 날아가다 빗나갈 수 있는
투사체로 만들면 화면이 그릴 수 없는 수가 된다.

## 5. 서리 개조 3종 — 옛것과의 대응

**개조 id는 하나도 바꾸지 않았다.** 옛 저장이 가리키는 개조가 조용히 사라지거나 다시 추첨되는 일이 없어야 하기 때문이다.
아이콘 파일도 그대로 쓴다(`mod_frost_fan` · `mod_frost_shatter` · `mod_frost_ground`).

| id | 옛 이름 · 옛 동작 | 새 이름 · 새 역할 | 움직이는 지표 |
|---|---|---|---|
| `fan` | **서리 부채** — 냉기 탄환 3발을 부채꼴로 | **넓은 빙결** — 여러 적에게 냉기를 공급한다(3발은 그대로) | `chill_targets` 중첩을 받은 **서로 다른 적의 수** |
| `ground` | **차가운 바닥** — 적중 지점에 2초 냉기 영역(둔화) | **빠른 빙결** — 그 바닥이 안에 있는 적에게 계속 냉기를 더한다(둔화는 그대로) | 같은 대상의 **첫 빙결까지 걸린 시간** |
| `shatter` | **깨지는 수정** — 탄환 적중마다 파편 3개로 분열 | **파쇄 강화** — 파쇄했을 때 파편 3 → 6개, 파편 피해·반경 1.5배 | `shard_hits` · `shard_dmg` |

- 보조 하나에 개조 하나라는 기존 제한은 그대로다(`slots.supportMods = 1`). 세 후보는 서로 다른 선택이다.
- **`shatter`만 동작이 실제로 바뀌었다.** 탄환 분열은 없앴다 — 적중마다 파편이 날아가면
  '얼리고 내가 깬다'는 순간이 파편에 묻혀 보이지 않고, 개조 이름과 실제 역할도 어긋났다.
- `fan`·`ground`는 **하던 일을 그대로 하면서** 새 체계의 두 축(넓이·속도)을 맡는다.
  옛 저장에서 그 개조를 갖고 있던 회차는 눈에 보이는 동작이 달라지지 않는다(이름과 설명만 바뀐다).
- **`shatter`를 갖고 있던 옛 저장**은 탄환 분열을 잃고 파쇄 강화를 얻는다. 개조를 지우거나 다시 뽑게 하지 않았다 —
  같은 id가 계속 유효하고, 새 체계에서 그 개조가 맡을 자리가 분명하기 때문이다.
- `data/icons.json`은 아이콘 생성 도구가 만드는 파일이라 손대지 않았다. 그 안의 표시 이름은 아직 옛 이름이다
  (그림 파일과 키는 그대로라 화면은 정상이다). 그 파일의 담당이 다음에 다시 만들 때 맞추면 된다.

## 6. 시험값과 근거

전부 `data/supports.json` → `tuning.frost`. 코드에는 숫자를 두지 않는다.

| 이름 | 값 | 근거 |
|---|---|---|
| `stackMax` | 5 | 사용자가 준 출발점 |
| `freezeSec.normal` | 1.0초 | 사용자가 준 출발점("일반 적 약 1초") |
| `freezeSec.elite` | 0.6초 | 이미 있는 제압 저항표 `resist.slow.elite`(0.6)를 그대로 곱했다. '정예는 둔화도 빙결도 같은 비율로 덜 받는다'로 설명이 하나가 된다 |
| `freezeSec.boss` | 0.8초 | 결빙은 정지가 없어 길이가 위협을 만들지 않는다. 대신 가장 느린 원거리 주무기 **활의 주기(0.8초)**와 같게 잡아, 검(0.55)·창(0.7)·쌍검(0.75)은 결빙 창 안에 대체로 한 번 맞히고 전투망치(1.4)는 조준해야 맞힌다 |
| `refreezeSec` | 3.0초 | 일반 적 기준 '빙결 1.0 + 제한 3.0 = 4.0초 주기'라 최악의 경우에도 행동 불능 비율이 25%를 넘지 않는다 |
| `stackTtl` | 3.0초 | 서리 수정 기본 주기(1.0초)로 다섯 발을 이어 맞히는 동안에는 절대 끊기지 않는다 |

## 8. 구현하면서 고친 것

- `PSupport.cause_of`의 `bool(hit.get("dot", false))`는 **진짜 지속 피해 opt를 넘기는 순간 오류를 냈다.**
  `opt.dot`에는 `"burn"` 같은 문자열이 들어오는데 Godot 4에는 String → bool 변환이 없다.
  그때까지 아무도 dot opt를 `hit`으로 넘기지 않아 드러나지 않았다. `hit.has("dot")`으로 바꿨다.
- `PSupport.known_cause`를 새로 만들었다. 규칙 코드가 피해 opt에 직접 적는 `cause` 중에는
  자격표 어휘가 아닌 것이 있다(지뢰가 `"mine"`을 쓰고 표에는 `"mine_blast"`만 있다).
  `cause_of`는 `opt.cause`가 있으면 그대로 돌려주므로, 어휘 밖이면 무기 id로 다시 물어 바로잡는다.
  이것이 없으면 지뢰 폭발이 표에 없는 이름이 되어 "모르는 효과는 막지 않는다" 규칙에 걸려 조용히 파쇄했다.
- `damage_enemy`의 처치 판정에 `not e.dead`를 걸었다. 파쇄 추가 피해가 적을 죽이면 안쪽에서
  `kill_enemy`가 이미 한 번 돌기 때문에, 그 가드가 없으면 같은 죽음이 두 번 정산된다.

# 편성 — 테마별 협공 · 분대 · 특수 정예 결투

2026-09-09 개편. **구조는 사용자 지시**이고, 숫자(비중·분대 크기·시간차·소환 상한·결투 자리)는 전부 **시험값**이다.
사람이 승인한 균형값이 아니다. 승인된 첫날 기준 전투(늑대 25 · 동시 12, `t1a_first`, D33)는 **건드리지 않았다.**

정본 데이터는 `data/themes.json`, 규칙 코드는 `scripts/rules/formation.gd` · `run.gd` · `sortie.gd` · `flow.gd` ·
`combat_state.gd`(소환·분대 투입·전환 부분), 검사는 `tests/squad_tests.gd`, 계측은 `tools/formation_probe.gd`다.

## 1. 테마마다 목적이 다른 협공 3개

각 테마의 `formations.normal` 세 항목이 대표 협공이다. 항목마다 다음을 갖는다.

| 필드 | 뜻 |
|---|---|
| `goal` | **행동 목적** 한 줄. 테마 안에서 서로 달라야 한다(검사로 못박음) |
| `kind` | 리듬. `swarm` 무리 처리형 · `coop` 협공형 · `strong` 강적형 |
| `comp` | 종류별 비중(총 등장 수 배분). 비중 1·2위 조합이 테마 안에서 겹치지 않는다 |
| `squad` | 분대 규칙(§2) |
| `common_elite` | 일반 정예 1마리(있을 때만, §4) |
| `xp_units` | 개편 **전** 경험치 예산. 구성이 바뀌어도 예산을 이 값으로 되돌린다(§5) |

| 테마 | ① | ② | ③ |
|---|---|---|---|
| 1막 사냥 숲 | 포위 탈출 · 늑대 + 멧돼지(swarm) | 막힌 길과 착지 예고 · 거미 + 두꺼비(coop) | 빈틈과 접근 · **일반 정예 늑대** + 박쥐(strong) |
| 1막 버려진 요새 | 전열 우회 · 방패병 + 궁수(coop) | 사격대 접근 중 측면 대응 · 궁수 + 도적(swarm) | 정면에 머물지 않고 우회 · **일반 정예 방패병** + 폭탄(strong) |
| 1막 포자 정원 | 탈출 공간 확보 · 포자 + 거미(coop) | 회피 경로의 착지 예고 · 두꺼비 + 포자(swarm) | 반격과 접근 처리 · **일반 정예 두꺼비** + 박쥐(strong) |
| 2막 붉은 의식터 | 화염 피하며 치료 끊기 · 도마뱀 + 주술사(coop) | 강적 집중과 치료사 우선 · 방패병 + 주술사(strong) | 회전 화염과 측면 · 도마뱀 + 도적(swarm) |
| 2막 무너지는 광산 | 폭발 회피와 기습 위치 · 잠복충 + 폭탄(coop) | 돌진 회피 직후 근접 · 멧돼지 + 박쥐(swarm) | 화염 밖 공간 고르며 출현 추적 · **일반 정예 잠복충** + 도마뱀(strong) |
| 2막 얼어붙은 협곡 | 봉쇄와 사격 사이 통과 · 서리술사 + 궁수(coop) | 전방 사격과 후방 착지 · 궁수 + 두꺼비(swarm) | 거미줄 제거하고 추격 · **일반 정예 궁수** + 거미(strong) |
| 3막 시간의 심연 | 안전 바닥 이동 · 잠복충 + 서리술사(coop) | 착지와 측면으로 바뀌는 방향 · 두꺼비 + 도적(swarm) | 출현 추적과 접근 · **일반 정예 잠복충** + 박쥐(strong) |
| 3막 피의 사냥터 | 회피 후 반격 · 도적 + 박쥐(coop) | 지상 추격과 착지 · 늑대 + 두꺼비(strong) | 측면과 직선 · 도적 + 멧돼지(strong) |
| 3막 뒤틀린 성채 | 전열과 회전 화염 사이 돌파 · 방패병 + 도마뱀(coop) | 강적 우회해 치료 차단 · **일반 정예 방패병** + 주술사(strong) | 사격·폭발·측면 사이 출구 · 궁수 + 폭탄 + 도적(swarm) |

### 표와 다른 곳(그리고 그 이유)

* **편성 id 를 바꾸지 않았다.** `data/elites.json` 의 배치표와 `tests/balance_tests.gd` 가 id 를 참조한다.
  그래서 `t1a_boar` 가 거미·두꺼비 편성이 되는 등 **id 와 내용이 어긋난 곳이 있다.** 이름·목적·구성은 표대로다.
* 사용자 표에서 **일반 정예**로 적힌 자리 중 세 곳(`t2a_elite_support` · `t3b_rogue_alpha` · `t3b_wolf_archer`)은
  **특수 정예를 그대로 두었다.** 이 세 편성은 2·3막에서 특수 정예 7종 전부가 실제 편성에 나온다는
  회귀 검사(`tests/elites_tests.gd`)를 지탱하는 자리다. 그래서 그 협공의 '강적'은 일반 정예가 아니라 특수 정예다.
  일반 정예로 바꾸려면 `data/elites.json`(다른 담당)의 배치를 함께 옮겨야 한다.
* 대표 협공의 두 주역 외에 **소수의 지원·측면**이 함께 들어 있는 편성이 있다. 분대에 '뒤에서 지원'과
  '측면·시간차' 자리를 만들기 위해서다(§2). 지원 비율은 편성의 절반을 넘지 않는다.

## 2. 등장 단위는 '역할이 갖춰진 분대'

`squad` 블록이 등장 **순서와 묶음**만 만든다. 종류별 총 수는 건드리지 않는다.

```json
"squad": {
  "size": 5,
  "slots": { "wolf": "front", "boar": "flank", "archer": "support" },
  "delay": { "front": 0.0, "support": 0.4, "flank": 1.0 },
  "stage_weight": { "wolf": [0.45, 0.30, 0.25], "boar": [0.05, 0.45, 0.50] }
}
```

* `front` 앞에서 접근 · `support` 뒤에서 지원 · `flank` 측면·시간차.
* **분대의 첫 자리는 front**(front 가 남아 있는 한). 한 분대의 support 비율 상한은
  `data/pacing.json` 의 `spawn.support_share_per_group`(0.5)을 그대로 쓴다.
* `flank` 은 **다른 진입 지점**에서 오고, `delay` 초만큼 늦게 도착한다 —
  "늑대가 맞붙을 무렵 멧돼지가 돌진 준비", "도마뱀이 화염을 준비하는 동안 도적이 측면 접근"이 이렇게 생긴다.
* **지원만으로 이루어진 분대를 만들지 않는다.** 구간 끝에 지원만 남으면 front 가 있는 분대들에 나눠 붙인다.
* `stage_weight` 가 있으면 종류마다 `[초반, 중반, 후반]` 비중으로 나눠 구간을 만든다.
  **없는 편성은 구간을 두지 않는다** — 모든 출격에 세 구간을 강제하지 않는다.
* 난수를 쓰지 않는다. 같은 시드·같은 카드면 분대 편성이 그대로 재현된다.

### 겹쳐 투입

`CombatState._push_squad`. 다음 분대는 **앞 분대의 전멸을 기다리지 않는다.** 막는 것은 두 가지뿐이다.

1. 동시 생존 상한(`formation.alive_cap`)을 넘는 예약
2. 이미 **동시 위험 공격 상한**(`PEnemiesNew.danger_max`, `data/pacing.json` `danger_limit`)까지 겹친 상태

종류별 상한에 걸린 구성원은 **버리지 않고** 다음 분대로 밀어 순서를 지킨다(`squad_carry`). 총 등장 수는 바뀌지 않는다.
전장이 비었는데 적이 남아 있으면 대기를 0으로 줄인다. 전투 말미에는 남은 분대들을 합쳐 낸다.
**적을 지우거나 자동 처치하지 않는다.**

## 3. 등장 종류 수

첫 기준(시험값): 짧은 일반 탐험 **3종 안팎** · 보통 출격 **4종 안팎** · 긴 출격·깊은 곳 **4~5종**.
**동시에 상대하는 종류는 주로 2~3종.** 등장 종류 수와 전체 개체 수는 다른 값이다
(총 개체 수는 `data/pacing.json` `day_total` 이 정한다 — 1일 25 → 9일 75).

실측은 `docs/sim/FORMATION_PROBE.md` §3.

## 4. 일반 정예(common_elite)

`{"type": "wolf", "n": 1}` 은 **그 종류의 일반 적 한 마리를 정예판으로 바꾼다**(총 등장 수 불변).
실제 id 규약은 `<종류>_elite`(예: `wolf_elite`)이고, 다음 두 조건이 **모두** 맞을 때만 바뀐다.

1. `data/enemies.json` 에 그 id 가 있다
2. `data/growth.json` 의 `growth.XP_VALUE` 에 그 id 의 마리당 경험치가 있다

하나라도 없으면 그 자리는 **그냥 그 종류의 일반 개체로 남는다**(조용히 건너뛴다).
**정예가 부족하다고 늑대 우두머리로 메우지 않는다.**

일반 정예는 **특수 정예와 구분된다**(`PRun.is_common_elite`). 특수 정예 = `data/elites.json` 의 7종.
일반 정예는 출격 카드의 '강적 출현' 예고와 **정예 추가 금화의 대상이 아니다**(금화 예산 불변).

> **지금 상태**: `bat`·`lizard`·`toad` 와 일반 정예 id 는 아직 카탈로그에 없다(다른 담당이 만드는 중).
> 편성 데이터에는 미리 들어 있고, 없는 동안에는 비중이 나머지 종류에 **비례 배분**되어 총 수·예산이 그대로 유지된다.
> 종류가 생기면 데이터를 고칠 필요 없이 그대로 나온다.

## 5. 총 등장 수·경험치·금화 예산

* **총 등장 수**는 `PPacing.day_total(날짜, 장소 비용)` + 편성의 정예 마리 수다. 편성을 바꿔도 달라지지 않는다.
* **경험치 예산**은 편성마다 `xp_units`(개편 전 값)에 고정된다. `PRun._pin_budget` 이 구성이 바뀐 만큼 `ref` 전체를
  되돌리므로, 구성이나 미구현 종류 유무와 **무관하게** 전투 경험치 예산이 같다.
* 자리를 대신 차지한 개체(일반 정예·결투 상대)는 `budget_from` 으로 **원래 종류의 단위값**을 따라간다.
  종류를 바꿔도 예산이 늘지 않는다.
* **금화**는 지역 전리품 규칙 그대로다. 결투가 붙은 출격은 기존 정예 추가 금화 규칙
  (`elite_reward`, 막당 15/25/40 × 0.7, **조우당 1회**)이 그대로 적용된다 — 새 보상 항목을 만들지 않았다.

검사: `tests/squad_tests.gd`(36편성 × 2장소 × 3날짜), 계측: `docs/sim/FORMATION_PROBE.md` §2.

## 6. 특수 정예 결투

**'1대1' = 일반 편성의 적과 증원이 끼어들지 않는 결투**다. 특수 정예 **자신의** 소환은 금지가 아니다.

### 언제 붙는가

`PRun.assign_duel` 이 **하루의 카드가 모두 정해진 뒤 한 장에만** 붙인다. **난수를 쓰지 않는다** —
시드·저장이 그대로 재현되고, 결과는 카드(`card.duelType`)에 저장된다.

* 막 안 날짜(1~3)마다 결투 자리가 하나. 선호 카드 순번은 `data/themes.json` 의 `duel.day_card_pref`.
* 그 자리가 **위험 카드면 같은 날의 다른 카드로 옮긴다**(위험 카드는 이미 편성 안에 특수 정예가 있다).
* 후보는 테마의 `special_elites` 에서 **막 안 날짜**로 고른다(`날짜 % 후보 수`).
  서로 다른 두 날에서는 반드시 다른 종류가 나온다.
* 그래서 **막마다 서로 다른 두 종류 이상**의 특수 정예를 만날 기회가 남는다(1막 포함).
  하루가 통째로 위험 카드가 되면 그 하루의 기회는 **결투가 아니라 위험 편성 안의 특수 정예**로 채워진다.
* 더 깊이 탐험은 추가 조우다(`duel.deep_extra`). 반복 탐험('일반 탐험')에는 붙이지 않는다 — 추가 보상 반복 지급 금지.

테마별 후보(사용자 배정):

| 테마 | 후보 |
|---|---|
| 사냥 숲 | 피의 송곳니 · 추격 사수 |
| 버려진 요새 | 철갑 추격자 · 군단 기수 |
| 포자 정원 | 역병 조율사 · 균열 채굴자 |
| 붉은 의식터 | 역병 조율사 · 사슬 집행자 |
| 무너지는 광산 | 균열 채굴자 · 철갑 추격자 |
| 얼어붙은 협곡 | 추격 사수 · 사슬 집행자 |
| 시간의 심연 | 균열 채굴자 · 역병 조율사 |
| 피의 사냥터 | 피의 송곳니 · 추격 사수 |
| 뒤틀린 성채 | 군단 기수 · 철갑 추격자 · 사슬 집행자 |

> **어긋난 곳**: `data/elites.json` 은 역병 조율사·균열 채굴자·사슬 집행자를 **2·3막 전용**(`acts`)으로 적어 두었는데,
> 사용자 배정에는 1막 포자 정원(역병 조율사/균열 채굴자)이 들어 있다. 사용자 배정을 그대로 따랐다.
> `data/elites.json` 은 다른 담당 파일이라 고치지 않았다 — **그쪽에서 `acts` 를 넓히거나 배정을 다시 정해야 한다.**

### 흐름과 전환 조건

```
일반 전투 → cleanup(잔여 위험 정리) → growth(성장 선택) → intro(등장 연출) → duel → 출격 승리
```

* **전환 조건**: 일반 몬스터 생존 0 · 등장 예고 0 · 미등장 예약 0 · 밀린 분대 구성원 0 · 일반 전투의 위험 효과 정리.
* `cleanup` 은 아직 **일반 전투 구간**이라 시간이 그대로 흐른다(남은 장판·투사체가 사라지길 기다린다.
  `cleanup_max_sec` 이 지나면 남은 **위험 효과만** 정리한다 — 적을 지우는 것이 아니다).
* `growth`·`intro` 는 **전환 구간**이다. 보스 등장 연출과 **같은 기준**으로 전투 시간과 모든 재사용 시간이
  함께 멈추고, 그 동안 적이 행동하지 않으므로 피해도 받지 않는다.
  **연출 길이로 회복이나 재사용 시간을 벌 수 없다.**
* **일반 전투 종료 뒤 자동 체력 회복은 없다.**
* 결투 중 **일반 편성의 추가 증원은 0**이다(`update_spawner` 가 결투 단계에서 즉시 돌아간다).

### 고유 소환

`duel.summon` 에 정예별로 `{type, count, interval, first_delay, max_alive, max_total, warn}`.
소환수는 **출처를 그 특수 정예에게 귀속**한다(`e.duel_summon`, `e.summon_owner`).
**군단 기수의 부하 소환은 유지된다.**

* 동시 상한(`max_alive`)과 **총 상한**(`max_total`)을 지킨다.
* 귀속 소환물은 **경험치를 주지 않는다**(`CombatState.xp_for`) — 무한 보상 파밍 금지.
  금화는 원래 지역 전리품이라 개체 수에 비례하지 않는다.

### 처치 순서(같은 프레임 경계)

`CombatState._end_duel`:

1. 결투 주체가 죽은 **그 프레임**에 승리가 확정된다(`status = "won"`).
2. 귀속된 잔여 소환물은 **추가 보상 없이** 같은 프레임에 정리된다(처치로 세지 않는다).
3. 그래서 **처치 직후 남은 소환물 때문에 승리 화면 전에 죽는 일이 없다** — 같은 프레임의 보류 패배는 승리가 이긴다
   (기존 `status == "won" → pending_loss = false` 규칙과 같다).

### 정산·저장·사망

* **특수 정예를 쓰러뜨려야 최종 승리다.** 결투가 끝나기 전에는 `PFlow.settle_victory` 가 거부한다
  (일반 전투 종료를 출격 승리로 먼저 처리하지 않는다).
* 결투는 **같은 조우(CombatState) 안**에 있다. 이 저장 구조에는 전투 중간 저장점이 없으므로
  일반 전투와 결투 사이에서 저장·복구해도 **일반 몬스터가 재생성되거나 보상이 중복 지급되지 않는다.**
  전투 단계는 `st.duel_stage` 로 읽을 수 있고, 정산 1회 보장은 기존 `st.settled` 가드 그대로다.
* 결투 상대는 카드(`card.duelType`)에 저장된다. 저장·복구해도 같은 강적이 나온다.
* 사망·부활은 기존 정책(`docs/DEATH_AND_ECONOMY.md`)을 그대로 탄다 — 결투 중 사망도 일반 출격 사망과 같다.
* **특수 정예전은 관문 보스전을 대체하지 않는다.** 관문은 그대로다.

### 출격 전 표시(자료만 내보낸다)

`PSortie.duel_notice(run, card)` → `{ present, type, name, role, read{}, hp, reward, text }`.
`read` 는 `data/elites.json` 의 역할 읽기 자료(손에 든 것·실루엣·예고)다.
**그리는 것은 다른 담당(`scripts/game/render.gd`)이다.** 긴 공략 설명을 전투 화면에 띄우지 않는다.

## 7. 다른 담당에게 필요한 훅

1. **`PCatalog` 접근자** — `themes.json` 의 새 뿌리 블록(`duel` · `planned_types` · `squad_rule`)을 읽는 접근자가 없어
   `PRun.themes_root()` 가 `PCatalog._load("themes")` 를 직접 부른다. `PCatalog.duel_cfg()` 같은 접근자가 있으면 좋다.
2. **성장 선택 문(gate)** — 화면이 결투 직전에 성장 선택을 띄우려면 `CombatState.hold_duel_gate()` 로 자리를 잡고,
   처리한 뒤 `open_duel_gate()` 를 부른다. **잡지 않으면 멈추지 않고 지나간다**(화면이 아직 연결하지 않았을 때
   전투가 영원히 멈추는 것을 막는 안전 기본값).
3. **결투 표시** — 이름·실루엣·전용 체력바. 자료는 `PSortie.duel_notice` 와 `e.duel_boss` 표시로 나간다.
   전환 연출(`st.duel_stage` = `intro`)의 길이는 `duel.intro_sec` 이다.
4. **신규 몬스터 3종**(`bat`·`lizard`·`toad`)과 **일반 정예 id**(`<종류>_elite` + `XP_VALUE`) — §4.
5. **`data/elites.json` 의 `acts`** — 1막 포자 정원 배정과 어긋난다(§6).

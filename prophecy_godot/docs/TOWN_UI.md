# 마을·빌드·전투 결과 화면 구성 (2026-09-09)

이 문서는 **화면이 무엇을 상시로 보여 주고 무엇을 상세로 내렸는지**의 정본이다.
규칙 수치는 여기서 정하지 않는다. 화면은 `PRun`·`PSortie`·`PBuild`·`PFlow`가 준 값을 그리기만 한다.

## 0. 원칙

- 메인은 설명이 아니라 **지금 할 수 있는 행동**을 먼저 보여 준다.
- **마우스를 올리기만 해서 긴 상세가 자동으로 펼쳐지지 않는다.** 상세는 항상 명시적인 버튼으로 연다.
  (용어 링크의 짧은 툴팁은 그대로 둔다. 길고 조건이 많은 설명은 버튼 뒤로 옮겼다.)
- **비용·위험·전리품 상실처럼 결정 전에 필요한 불이익은 접지 않는다.**
- 같은 행동 버튼을 두 곳에 흩어놓지 않는다.
- 상세는 소제목과 줄바꿈으로 나눈다. 한 문단으로 이어 붙이지 않는다.
- PC 클릭과 터치 탭이 같은 정보에 닿는다(아이콘 칸은 `PUi.icon_pick`이 아이콘 위에 버튼을 얹는다).

## 1. 거점(`scripts/game/screens/base.gd`) — 준비 단계

### 상시로 남긴 것

| 자리 | 내용 |
|---|---|
| 상단 줄 | 날짜·막 · 시간대(남은 N칸) · 다가오는 보스 · 체력 · 금화 · (작게) 판본·밸런스·시드 |
| 왼쪽 | 마을 그림(대장간·상점·장비·통계/기록·휴식 버튼) |
| 왼쪽 | 오늘의 출격 카드 — 장소 · 목표 한 줄 · **시간 N칸** · 특별 보상 한 줄 · 큰 출발 버튼 |
| 왼쪽 | **별도 영역 "일반 탐험 · N칸"** |
| 왼쪽 | 출격 준비물(가진 것이 있을 때만) · 보유 이용권 · 방문 상인 한 줄 |
| 오른쪽 | 현재 빌드(아이콘: 자동기술·개조·Space/Q/E·공용 증강·패시브·장비) |
| 오른쪽 | 보스 한 줄 + "보스 상세" 버튼 |
| 오른쪽 | 오늘 — 미처리 레벨업 · 하루 종료 · 저장 후 종료 · 기록 · "이번 회차 정보" 버튼 |

### 상세로 내린 것

- 출격 카드 "상세 보기": 장소 설명 · 나오는 적(역할·설명) · 웨이브 수 · 체력 배율 · 강적과 그 보상 ·
  위험 조건의 실제 효과 · 편성 이름과 설명 · **출발 시간대 변주와 다른 시간대 비교** ·
  "편성·사건·보상은 출발하는 순간의 시간대로 확정됩니다" · 지역 경험치 · 오늘 시도 횟수.
- 보스: 설명 장문 · 정보 줄 · 전장 · 체력 · 단계 전환 → "보스 상세".
- 회차 특징 한 줄 · 막 테마 한 줄 · 내일 미리보기 → "이번 회차 정보".
- "건물을 누르면 열립니다 / 시간 소모 없음" 같은 상시 안내 문장 → **삭제**.
- 방문 상인의 일정 비교 문장("…부터 하루 끝까지 · 장비 1개 할인 · 무료 휴식권 100금…") → 한 줄로 축약.

### 숨기지 않은 것(불이익)

- 각 카드의 **시간 N칸**, **위험 조건**, **강적 출현**.
- 일반 탐험의 "전리품·경험치만 — 임무 보상·사건·이용권은 없습니다".
- 하루 종료 확인 창의 "남은 N칸을 버리고".

### 상황 변화

- **완료한 출격**은 카드에서 빠지고 `오늘 완료  숲 · 능선` 한 줄로 접힌다.
- **시간이 0칸**이면 왼쪽 맨 위에 `오늘 활동을 마쳤습니다` 카드와 큰 `다음 날로 (N일차)` 버튼이 서고,
  오른쪽 "오늘" 카드의 `하루 종료` 버튼은 **사라진다**(같은 버튼을 두 곳에 두지 않는다).
- 상점·대장간·장비 버튼은 시간과 무관하므로 그대로 눌린다.
  휴식은 규칙(`PRun.can_rest`)이 시간 1칸 또는 휴식권을 요구하므로, **버튼을 숨기지 않고** 규칙이 막을 때만 비활성으로 남긴다.
  휴식권이 있으면 0칸에서도 눌린다.

### 일반 탐험

정본은 `data/pacing.json`의 `repeat_sortie`이고, 카드·시간·가능 판정은 전부 `PSortie.repeat_cards` / `PSortie.can_start`가 준다.
화면은 자기 영역(카드 하나)에 `일반 탐험 · 1칸` 제목과 장소별 버튼 `일반 탐험 · 숲 (1칸)`을 둔다.
나갈 수 없을 때는 버튼이 사라지지 않고 이유와 함께 비활성이 된다:
`관문 날에는 없습니다` / `출격을 한 번 마치면 열립니다` / `시간 부족 (1칸 필요)`.

## 2. 현재 빌드·아이콘 창

`PUi.build_icon_row` · `manual_icon_row` · `common_icon_row` · `equip_icon_row`가 각각 아이콘 줄을 만들고,
`on_pick(kind, id)`를 주면 아이콘 칸이 눌리는 버튼이 된다(`PUi.icon_pick`).

아이콘을 누르면 확인 창 층(`PScreen.open_confirm`)에 **짧은 정보 + 관련 행동**이 열린다.

| 종류 | 짧은 정보 | 행동 |
|---|---|---|
| 자동기술 | Lv · 공격 구조(연타 포함) · 붙은 개조 이름 | 상세 설명 · 대장간에서 강화·교체 |
| 개조 | 붙은 기술 · 효과 한 줄 | 상세 설명 · 대장간에서 개조 변경 |
| Space/Q/E | Lv · 최종 재사용 시간 · 효과 한 줄 | 상세 설명 · 대장간에서 변경 |
| 공용 증강·패시브 | 보유 단계 · 효과 한 줄 | 상세 설명 |
| 장비 | 부위 · 효과 한 줄 · 해제하면 바뀌는 수치 | 상세 설명 · 해제 · 판매 · 장비 화면 |

**"상세 설명"을 눌러야** 소제목으로 나뉜 긴 설명(기본값 / 붙은 개조 / 아직 붙지 않은 개조 후보 / 적용 대상 / 되팔 때 / 교체 규칙 …)이 열린다.

오른쪽 아래 `전체 빌드 ▶ (장비·성장·통계·기록)`은 기존 전체 패널을 여는 별개 토글이다(아이콘 창의 "상세 설명"과 이름이 겹치지 않게 두었다).

### 무기 표기

`PUi.weapon_damage_text` / `weapon_stats_text`가 정본이다.
`피해 6`처럼 연타 수가 빠진 표기를 쓰지 않는다.

- 연타(`hits`) — `6 × 3연타 (간격 0.09초)`
- 궤도 칼날(`count`) — `10 × 칼날 2개 (같은 적 0.4초마다)`
- 사슬(`hops`) — `9 · 최대 3번 튕김`
- 그 밖 — `12`

여기에 `· 주기 N초 · 사거리 N`을 붙인다. 값은 `PBuild.weapon_stats`가 준 파생 수치를 읽기만 한다.

## 3. 장비(`equip.gd`)·상점(`shop.gd`)

- 장비 목록은 **고르는 버튼만** 둔다. 줄마다 판매 버튼과 전후 수치를 반복하지 않는다.
- 장비 하나를 고르면 **장착(또는 해제) · 상세 설명 · 판매**가 한 창에 모인다.
  교체 시 원래 장비가 가방으로 간다는 것을 그 창에 **한 줄**로 적는다.
- 상점의 장비 카드는 `구매 (N금)` 버튼 하나다. 누르면 확인 창이 열리고 그 자리에서
  **`지금 장착` / `가방에 넣기`** 를 고른다. 취소하면 금화·가방·장착이 그대로다.
- 판매는 `PScreen.open_sell_confirm`을 거친다: `○○을 50금에 판매할까요?` · 받을 금액과 금화 전후 ·
  **장착 중이면 해제된다**는 경고와 해제 시 수치 변화 · "판 장비는 되사올 수 없습니다".

## 4. 휴식·확인 창 공통(`screen_base.gd`)

`PScreen.open_confirm(title, fill, actions, cancel_text)`가 모든 화면의 확인 창이다.

- 창마다 번호(`_modal_token`)를 매기고 확정 순간 번호를 올린다.
  **같은 창의 버튼을 다시 눌러도 아무 일도 일어나지 않는다**(중복 클릭 복제 방지).
- 취소·Esc는 아무것도 바꾸지 않는다.

휴식 확인 창은 다음을 적는다.

- 소모: 휴식권이 있으면 `휴식권 1장 (시간 소모 없음 · 사는 값 100금)`,
  없으면 `시간 1칸 (남은 3칸 → 2칸)`.
- 체력 `40 → 100` (가득이면 "이미 가득 — 시간만 넘깁니다")
- 넘어가는 시간대
- "취소하면 아무것도 바뀌지 않습니다."

**휴식권 표기**: 데이터(`data/missions.json`)의 이름은 `무료 휴식권`이지만, 값이 100금이라 '무료'는 값을 오해하게 만든다.
화면에서는 `PUi.rest_ticket_name()` = **휴식권**, `PUi.rest_ticket_note()` = **시간 소모 없음**으로 통일한다.
데이터의 이름 자체를 바꾸는 것은 규칙 담당의 몫이다(§7 참고).

## 5. 전투 HUD(`combat_hud.gd`)

- 전장에 남기는 것은 **Space / Q / E 조작 아이콘 3칸**과 **상단 체력**뿐이다.
- 대기 중에는 흑백 + 남은 초, 준비되면 컬러. 준비 전환 점등은 **1회**(반복 점멸 없음).
- 색은 `PCombatHud` 상수가 정본이다: `HP_FILL`(붉은 계열)·`SHIELD_FILL`(파란 계열).
  체력과 보호막을 같은 막대에 섞지 않는다. 체력 숫자는 22pt.
- 큰 빌드·장비 패널은 전장에 없다. 전체 빌드는 일시정지의 '내 빌드'(`PBuildDetail`)에서 본다.

## 6. 전투 승리(`reward.gd`)

기본 화면에 남긴 것

- `장소 · 전투 승리`
- 금화(+재료) 한 줄
- 지금 체력 `N / M`
- 실제로 받은 특별 보상이 있으면 한 줄씩(더 깊이 보상 / 임무 완료 / 봉인된 전리품 / 승리 회복 / 영구 기록)
- **큰 `계속 (Enter)` 버튼 하나** — 요약 바로 아래 한 곳에만 둔다
- 보조 `전투 통계 ▶` 버튼

`전투 통계`로 내린 것

- 보급 상자 포함 금액 · 지역 경험치 · 전투 중 경험치 · 처치 · 받은 피해 · 전투 시간 · 레벨업 횟수
- 피해 출처 상위 5 · 받은 피해 출처 · 판본·밸런스·시드

`예약·정산·반영` 같은 내부 처리 문장은 보상 설명으로 쓰지 않는다.
임무 보상은 실제로 받은 것으로 적는다(`임무 완료 — 보상 3택` / `— 금화 +30` / `— 다음 성장은 … 후보`).

## 7. 규칙 담당·`main.gd`에 필요한 것

이 작업에서 **규칙 파일(`scripts/rules/*`)과 `main.gd`는 고치지 않았다.** 남은 요청은 다음과 같다.

1. `data/missions.json`의 서비스 이름 `무료 휴식권` → `휴식권`(설명에 "쓸 때 시간 0칸").
   지금은 화면에서만 이름을 바꿔 쓰고 있어 데이터와 표시가 다르다.
2. 시간이 0칸이고 휴식권도 없을 때 `PRun.can_rest`는 false다(규칙상 옳다).
   화면은 버튼을 남기고 비활성으로 두지만, "0칸 대기"가 필요하다는 결정이 나오면 규칙 쪽에서 열어야 한다.
3. `main.gd` 훅은 새로 필요하지 않았다. 확인 창은 화면 안에서 만들고 확정 시 기존 함수
   (`main.rest` / `main.end_day` / `main.sell_equipment` / `main.buy_equipment(id, equip, from)`)를 그대로 부른다.
   다만 `main.buy_equipment`·`main.sell_equipment`는 실패 이유를 돌려주지 않고 `push_error`만 낸다.
   확인 창에서 실패를 사람 말로 알리려면 `bool`이나 사유 문자열을 돌려주는 형태가 있으면 좋다.

## 8. 검증

`tests/ui_flow_tests.gd`의 `_town_ui_tests`가 **실제 버튼을 눌러** 확인한다(문구 존재 여부만 세지 않는다).

- 출격·일반 탐험 버튼이 실제로 눌리고 전투가 시작되며 시간이 준다
- 남은 시간 1~5칸 어디서나 일반 탐험이 눌린다(시간이 남는데 못 나가는 상태가 없다)
- 일반 탐험이 완료 카드 안이 아니라 자기 영역에 있다
- 시간이 0칸이면 `다음 날로`가 크게 하나뿐이고, 상점 화면이 실제로 열리며, 휴식 버튼은 남는다(휴식권이 있으면 눌린다)
- 휴식·판매·구매 확인 창을 열고 **취소**하면 체력·시간·휴식권·금화·가방이 그대로다
- 판매 확정을 중복 클릭해도 한 번만 반영된다
- `지금 장착` / `가방에 넣기` 둘 다 동작한다
- 아이콘은 눌러야 열리고(마우스 hover로는 열리지 않는다), 긴 설명은 `상세 설명`을 한 번 더 눌러야 나온다
- 연타 무기 표기에 `× 3연타`와 `간격`이 들어간다

`tests/hud_tests.gd`는 승리 화면에 `계속` 버튼이 **하나**뿐이고 처치·피해·시간·상자 포함 금액이
`전투 통계`를 눌러야 나오는지, 체력이 붉은 계열이고 보호막이 파란 계열로 분리돼 있는지를 확인한다.
성장 3택 중 '내 빌드 보기'·'상세 보기'를 거쳐도 후보가 재추첨되지 않는 검사는 그대로 살아 있다.

### 자동 검사로는 볼 수 없는 것(사람이 직접 봐야 한다)

1. 마을 그림 위 건물 실루엣과 카드가 겹치지 않는지(창 비율 wide/standard/narrow 각각).
2. 출격 카드 2장이 나란히 설 때 글자가 줄바꿈으로 지저분해지지 않는지.
3. 확인 창(560px 고정 폭)이 좁은 창에서 화면 밖으로 나가지 않는지.
4. 아이콘 창의 행동 버튼이 4개까지 늘어날 때(장비) 한 줄에 들어가는지.
5. 전투 중 체력 막대의 붉은색이 3막 색감(붉은 배경)에서도 구분되는지.
6. 승리 화면이 실제로 "읽지 않고 계속 누를 수 있는" 분량인지.
7. 일반 탐험 버튼이 출격 버튼과 시각적으로 구분되는지(둘 다 큰 버튼이다).

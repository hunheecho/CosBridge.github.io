# 적 피드백 대응 — 방패병·주술사·전투 말미·특수 정예 (2026-09-09)

사람이 직접 플레이하고 준 피드백에 대한 대응 기록이다. **수치는 별도로 적지 않는 한 전부 시험값**이며
사람이 승인한 균형값이 아니다. 사용자 확정값과 시험값을 항목마다 갈라 적었다.

- 규칙 코드: `scripts/rules/enemies.gd` · `scripts/rules/enemies_new.gd`
- 손으로 정한 값: `data/pacing.json`(적 수치 겹쳐쓰기) · `data/elites.json`(정예 배치·역할 자료)
- 검사: `tests/elites_tests.gd` · `tests/enemy_pace_tests.gd`
- 계측: `tools/tail_probe.gd` → `docs/sim/TAIL_PROBE_*.md`

## 1. 방패병 정면 경감 85% → **70%** (사용자 확정)

`data/pacing.json` → `enemy_tuning.shieldbearer.frontMult = 0.30`.
유효 직접 피해 100이 정면에서 **30**이 된다. 자세한 판정·측정표는 `docs/SHIELDBEARER.md`.

유지한 규칙(측정해서 확인했다):

| 항목 | 결과 |
|---|---:|
| 측면(90도) · 후면(180도) | 100.0 (감소 없음) |
| 정면 각 경계 ±60도 | 59도 30.0 / 61도 100.0 |
| 바닥·추가(`extra`) 피해 | 100.0 (우회) |
| 지속 피해(`dot` 화상·출혈) | 100.0 (우회) |
| 기술 피해(`skill`) | 100.0 (우회) |
| 방패를 내린 시간(`bash`) | 100.0 |
| 방패를 내린 시간(`recover`) | 150.0 (빈틈 노출 ×1.5가 곱해진 값) |

**특수 정예의 방패 자세와 혼동하지 마라.** 정예 검사(`elite_blademaster`)의 `guardMult`는 **0.0(완전 차단)**이며
일반 방패병의 0.30과 아무 관계가 없다. 두 값을 나란히 놓은 표는 `docs/SHIELDBEARER.md` §7에 있다.

## 2. 주술사 — 강한 아군 우선 치료 + 공격 두 패턴

값은 전부 `data/pacing.json` → `enemy_tuning.shaman`.

### 2-1. 치료 대상 고르기

우선순위(사용자 지시)를 **등급 표**로 만들었다. 무작위 선택도, 잃은 비율만 보는 선택도 하지 않는다.

| 순위 | 대상 | 등급 |
|---|---|---:|
| 1 | 특수 정예 7종 | 3 |
| 2 | 일반 정예·우두머리(`elite` 표시) | 2 |
| 3 | 주력 적(역할 `melee_main`·`armored`·`support`) | 1 |
| 4 | 일반 잡몹(역할 `swarm`) | 0 |

- **같은 등급 안에서는 잃은 체력의 절대값이 큰 쪽**을 고른다.
  검사에서 늑대(잃음 20, 비율 0.42) vs 방패병(잃음 30, 비율 0.34) → **방패병**을 고른다.
- **다치지 않은 적은 대상이 아니다.** 체력이 가득 찬 특수 정예가 옆에 있어도 다친 늑대를 치료한다.
- 자기·다른 주술사·보스 제외(기존 규칙 유지). **구조물(깃발·돌무더기·제단)도 제외**했다 — 싸우는 아군이 아니다.
- 치료량 30% → **20%**(첫 시험값). 대상 최대 체력 기준. 늑대(최대 48)를 9.6 회복한다.
- 강한 타격(12 이상)·넉백(20 이상)으로 시전이 끊기는 기존 대응 유지(검사로 확인).

### 2-2. 공격 A — 세 갈래 저주탄

한 발 평타를 세 갈래 멀티샷으로 교체했다.

| 구간 | 상태 | 시간 | 내용 |
|---|---|---:|---|
| 예고 | `hex_aim` | 0.90초 | 조준선이 플레이어를 **따라간다** |
| 확정 | `hex_lock` | 0.15초 | **방향 고정** — 여기서부터 따라가지 않는다 |
| 실행 | — | — | `dir`, `dir ± 13도`로 3발(발당 피해 8, 기존 `hexDamage` 그대로) |

- **가운데 탄은 조준 확정 시점의 플레이어 방향 그대로다.** 가만히 선 플레이어를 양옆으로 빗겨 쏘지 않는다
  (검사: 확정 방향 180.0도 = 확정 시점 플레이어 방향 180.0도).
- 확정 뒤 플레이어가 260 움직여도 가운데 탄 방향이 그대로였다 → **옆으로 이동해 피할 수 있다.**
- 세 발이 다 맞게 설계하지 않았다. 발당 피해를 올리지 않았고 퍼짐(±13도)만 정했다.

### 2-3. 공격 B — 저주 문양

| 구간 | 상태 | 시간 | 내용 |
|---|---|---:|---|
| 예고 | `rune_aim` | 1.00초 | **시작하는 순간** 플레이어가 서 있던 자리에 문양을 고정 |
| 실행 | — | — | 반지름 70 · 피해 12 · 그 자리에서 폭발 |

- **예고가 끝날 때까지 플레이어를 따라다니는 판정이 없다.** 위치는 첫 프레임에 확정된다
  (검사: 예고 중 플레이어가 240 이동해도 문양 좌표가 바뀌지 않았다).
- 위치가 처음부터 확정이라 예고 도형이 **첫 프레임부터 `locked = true`**이고, 그 원이 곧 실제 폭발 범위다.

### 2-4. 치료와 공격은 행동 상태를 공유한다

`act_t`(공용 간격 1.0초)를 셋이 함께 쓴다. 한 행동을 끝내면 이만큼 지나야 다음을 시작한다.

- 검사: 치료·저주탄·문양의 대기 시간을 전부 0으로 만들어도 **하나만** 시작하고, 다음 행동까지 1.01초를 쉬었다.
- 정예급 연계(예고 → 확정 → 곧바로 다음 예고)는 넣지 않았다. 세 행동 모두 예고 → 확정 → 실행 → 빈틈 한 벌이다.

### 2-5. 화면에 필요한 것 (규칙 쪽 자료는 준비했다 — 그리는 것은 `render.gd` 담당)

규칙 쪽이 내보내는 **관측 가능한 자료**:

| 무엇 | 어디서 읽나 | 담긴 것 |
|---|---|---|
| 지금 누구를 치료 중인가 | `PEnemies.support_links(st, out)` | `{kind:"heal_link", e(시전자), target(대상), x,y, tx,ty, prog(0~1), ratio}` |
| 세 갈래 저주탄 확정 | `PEnemies.threats` (`hex_lock`) | 고정된 `beam` 3개. 가운데 것에 `center: true` |
| 세 갈래 저주탄 예고 | `PEnemies.threats` (`hex_aim`) | 따라오는 `beam` 1개, `locked: false` |
| 저주 문양 | `PEnemies.threats` (`rune_aim`) | 고정된 `circle`, `locked: true`, `r` = 실제 폭발 반지름 |

**`support_links`는 일부러 `threats`와 분리했다.** `threats`는 봇이 회피 계산에 쓰는 위험 목록이라
위험이 아닌 연결선을 섞으면 안 되기 때문이다.

그려야 하는 것(부탁):

1. **치료 연결선** — 시전자에서 대상까지 이어지는 선. `prog`로 차오르게 하면 언제 완료되는지 보인다.
   대상 쪽에는 회복 반응(고리 확대 등)이 필요하다. 지금은 회복이 **일어난 뒤**의 `+숫자` 글자와 보라색 `burst`만 있다.
2. **저주 문양** — `rune_aim`의 원. `locked`가 처음부터 참이므로 "따라오지 않는다"가 보이게 그려야 한다
   (지금은 폭발 순간의 `bossland` 효과만 있다).
3. **세 갈래 저주탄** — 확정 순간 세 줄이 함께 보여야 옆으로 피할 방향을 고를 수 있다.

## 3. 전투 말미가 지루하다 — **먼저 쟀다**

관찰: "멧돼지만 남으면 조금씩 등장해 전투가 지루하게 길어진다."
원인을 짐작하지 않고 `tools/tail_probe.gd`로 실제 편성(`data/themes.json → PRun.formation_waves → PFlow.encounter_opts`)을
그대로 돌려 쟀다. 봇 `balanced` · 시드 1·2·3 중앙값 · 20Hz 표본.

대조군 t3a는 **잠복충**(24.7~32.9초). 즉 멧돼지만의 문제가 아니라 **상한이 낮은 종류 전부**의 문제다.

### 3-2. 확인된 원인 (짐작이 아니라 측정)

**종류별 동시 생존 상한(`type_caps`)이 동시 생존 상한(`alive_cap`)보다 훨씬 낮다.**

- `t2c_boar_archer`: 동시 상한 15인데 멧돼지 2 + 궁수 3 = **최대 5마리**. 실제 최대 생존도 정확히 5였다.
- `t3a_archer_burrow`: 동시 상한 18인데 궁수 3 + 잠복충 2 = **최대 5마리**. 실제 최대 생존 5.
- 전투 시간의 **86~96%가 "자리는 비었는데 다음 적이 안 나오는" 시간**이고,
  그중 대부분(`cap_block`)이 **종류별 상한에 막혀** 아무도 못 나온 시간이다.
- 상한이 없는 종류(늑대)는 먼저 소진되고, 상한이 낮은 종류가 **대기열 끝에 몰린다**.
  `combat_state.update_spawner`가 상한에 걸린 종류를 건너뛰고 뒤엣것을 먼저 꺼내기 때문이다(순서 자체는 보존한다).
  대조군 `t1a_wolves`(늑대 20/25, 상한 없음)는 같은 조건에서 1~2마리 구간이 **3.3초**뿐이었다.
- 편성 자체는 이미 섞여 있다(`PFormation.mix_squads`). 대기열 뒤 1/4에도 종류가 섞여 있었다
  (`t1a_boar` = 늑대 5 · 멧돼지 2). **섞기의 문제가 아니라 꺼내기의 문제다.**
- 멀리서 대기하는 적 비율은 20~45%였다. 적지 않지만 **주된 원인은 아니다**(대조군도 20%로 비슷하다).

### 3-3. 이번에 한 것 — 적 생존 수와 동시 위험 공격 수를 **분리**했다

종류별 상한을 올리려면 "적이 많아지면 위험도 그만큼 많아진다"를 먼저 갈라야 한다.
그래서 규칙 쪽에 **동시 위험 공격 상한**을 만들었다(`PEnemiesNew.may_start`, 값은 `data/pacing.json` → `danger_limit`).

| 막 | 상한(시험값) | 실측 최고치(수정 전) |
|---|---:|---:|
| 1막 | 7 | 7 |
| 2막 | 8 | 3 |
| 3막 | 9 | 6 |

- **새 공격만 막는다.** 이미 시작한 예고는 끊지 않는다(검사: 예고에 들어간 12마리가 모두 실행까지 갔다).
- **적을 지우거나 자동 처치하지 않는다**(검사: 14마리 → 14마리, 처치 0).
- **늑대 계열은 세기만 하고 막지 않는다.** 0.3.1 규칙과 승인된 첫 전투(D33)를 보존해야 하기 때문이다
  (검사: 늑대 13마리에서 동시 위험 공격 10 — 상한 7을 넘겼다).
- 보스전에는 적용하지 않는다(그쪽은 `overlap_limit`·`wolf_may_attack`이 담당).
- 상한을 **오늘의 실측 최고치 이상**으로 잡았으므로 **지금 압박은 하나도 줄지 않았다.**
  같은 시드로 수정 전/후를 돌린 결과 **18회 전부 모든 항목이 완전히 동일**했다
  (`tail12_sec` · `room_wait_sec` · `cap_block_sec` · `avg_alive` · `max_danger` · `kills` · `status` 등 12개 항목).
  즉 이 천장은 아직 닿지 않는다 — 종류별 상한을 올리는 순간부터 일을 시작한다.

### 3-4. 이번에 **못 한 것** — 담당 밖 파일이 필요하다

말미 문제의 본체는 소환기와 편성표에 있고, 둘 다 이번 담당 밖이다. 규칙 쪽에서 손댈 수 있는 자리가 없다.
**수정 전후 말미 수치가 그대로인 이유가 이것이다** — 고칠 자리가 내 파일에 없다.
제안값은 `data/pacing.json` → `type_alive_cap_proposal`에 근거와 함께 적어 두었다(아직 아무도 읽지 않는다).
붙이는 방법은 §5에 있다.

**금지 사항은 지켰다**: 남은 적을 삭제하거나 자동 처치하지 않았고, 등장 예고와 안전한 출현 위치를 그대로 두었으며,
총 적 수·경험치·금화 예산은 건드리지 않았다.

## 4. 특수 정예 — 출현과 행동

### 4-1. 조우 빈도 (편성표가 아니라 **실제 회차의 카드**로 셌다)

`PSortie.cards_for`(실제 카드 생성기)를 시드 8개 × 1~9일로 돌리고 각 카드의 강적 예고(`PSortie.elite_notice`)를 셌다.
경로는 시드마다 다르게 잡았다 — **기본 경로만 보면 다른 테마의 정예를 영영 못 본다.**

| 정예 | 예고된 카드 수 |
|---|---:|
| 정예 궁수 | 6 |
| 정예 검사 | 23 |
| 피의 송곳니 | 5 |
| 역병 조율사 | 16 |
| 사슬 집행자 | 7 |
| 군단 기수 | **2** |
| 균열 채굴자 | 15 |

| 막 | 전체 카드 | 강적 예고 | 비율 |
|---|---:|---:|---:|
| 1막 | 48장 | 7장 | 15% |
| 2막 | 64장 | 37장 | 58% |
| 3막 | 32장 | 16장 | 50% |
| 합계 | 144장 | 60장 | **42%** |

- 7종이 **모두** 실제 카드에 나온다 — 편성표에 이름만 있는 종류는 없다(검사로 고정했다).
- 1막 15%: 존재는 알 수 있고 첫 만남이 사고가 되지는 않는다. 2·3막 50~58%: 큰 보상·깊은 곳에서 분명히 나온다.
- **의무는 아니다**: 전체의 42%라 강적 없는 일반 전투가 절반 이상이다.
- **처음 재 봤을 때 정예 궁수가 0이었다.** 기본 경로만 돌렸기 때문이며, 경로를 시드마다 바꾸자 6이 되었다.
  즉 **정예 궁수는 특정 경로에서만 만난다.** 배치를 바꾸지는 않았고 사실만 남긴다.
- 편차가 크다(군단 기수 2 · 피의 송곳니 5 vs 정예 검사 23). `elite_type_p2`가 대부분 `elite_blademaster`이기 때문이다
  (`data/elites.json` `assigned.by_formation`). 배치는 이번에 바꾸지 않았다 — 사용자 결정이 필요한 부분이다.

### 4-2. 3막 정예 늑대 처치 시간 — **체력은 바꾸지 않았다**

사용자 지시대로 체력을 손대지 않은 상태에서 관찰만 수치로 보존한다.

|---|---:|---:|---:|

| 피의 송곳니 | **3막** | 2301 | **23.8초** |

### 4-3. 역할 읽기 자료

외형(실루엣)은 `render.gd` 담당이므로, **무엇을 들고 있어야 역할이 읽히는가**를 자료로 남겼다.
`data/elites.json` → 각 정예의 `read` 블록(`PCatalog.elite_def(id).read`로 읽는다 — 새 접근자가 필요 없다).

| 정예 | 손에 든 것 | 예고에서 커져야 하는 곳 | 취해야 할 거리 |
|---|---|---|---|
| 정예 궁수 | 긴 활 + 화살통 | 시위를 당긴 팔(부채꼴 3발 전에는 화살 세 대) | 붙어야 한다 |
| 정예 검사 | 큰 검 + **방패** | 정면을 덮는 방패 | 측·후면으로 돈다 |
| 피의 송곳니 | 무기 없음(송곳니) | 접히는 뒷다리 + 착지 원 | 옆으로 돌 공간을 뺏는다 |
| 역병 조율사 | **포자 주머니 3개** | 주머니가 하나씩 사라진다 | 원 사이로 빠진다 |
| 사슬 집행자 | **사슬 갈고리** + 망치 | 곧게 펴지는 사슬 | 바위를 사이에 둔다 |
| 군단 기수 | **깃발 장대** + 짧은 검 | 깃발을 꽂는 동작 | 깃발을 먼저 부순다 |
| 균열 채굴자 | **곡괭이** | 흙 자국 + 고정된 출현 원 | 출현 원 밖으로 걷는다 |

행동에 대해: **예고를 짧게 만들어 속도를 올리지 않았다.** 이번에 정예의 예고 시간·체력을 하나도 바꾸지 않았고,
연계가 실제로 실행되는지는 `tests/elites_tests.gd`(상태 전이 순서 · 확정 뒤 추적 없음 · 빈틈 길이)가 계속 고정하고 있다.

## 5. 필요한데 못 만든 훅 (담당 밖 파일 — 고치지 않고 적는다)

### 5-1. **[가장 중요]** 종류별 동시 생존 상한을 동시 상한에 비례하게

말미 문제의 본체다. 값은 `data/pacing.json` → `type_alive_cap_proposal`에 이미 적어 두었다(비율 표 + 최소 2).

**① `scripts/rules/pacing.gd`** — 읽는 함수 추가

```gdscript
# ---------- 종류별 동시 생존 상한(동시 상한 비례) ----------
## 고정값(멧돼지 2 · 궁수 3)은 동시 상한이 12~18인데도 전장을 5마리로 묶어 전투 말미를 늘렸다(tools/tail_probe.gd).
static func type_cap_cfg() -> Dictionary: return D().get("type_alive_cap_proposal", {})

## 그 종류의 동시 생존 상한. 표에 없으면 fallback(템플릿 값) 그대로
static func type_alive_cap(type: String, alive_cap: int, fallback: int) -> int:
	if not counts_on():
		return fallback
	var C := type_cap_cfg()
	var share: Dictionary = C.get("share_by_type", {})
	if not share.has(type):
		return fallback
	return maxi(int(C.get("min_cap", 2)), int(round(float(alive_cap) * float(share[type]))))
```

**② `scripts/rules/run.gd`** — `theme_density_override`의 `type_alive_cap`을 그 함수로 통과시킨다

```gdscript
	var caps: Dictionary = (tpl.get("type_caps", {}) as Dictionary).duplicate()
	for k in caps:
		caps[k] = PPacing.type_alive_cap(String(k), cap, int(caps[k]))
	return { "alive_cap": cap, ..., "type_alive_cap": caps, ... }
```

기대 효과(제안값 기준): 2막 동시 상한 15 → 멧돼지 5 · 궁수 6 · 주술사 2. 전장에 11마리까지 설 수 있어
대기열이 밀리지 않는다. 위험은 §3-3의 `danger_limit`(2막 8)이 따로 막으므로 압박이 함께 부풀지 않는다.
**총 적 수·경험치·금화 예산은 바뀌지 않는다.** 적용 뒤에는 같은 시드로
`PROPHECY_TAIL_TAG=after2 godot --headless --path prophecy_godot -s tools/tail_probe.gd`를 돌려 §3-1 표와 견주면 된다.

### 5-5. `scripts/rules/observe.gd` — 주술사의 새 예고가 관측 계층에 없다

`PObserve`는 실력 프로필 봇(`PSkillBot`)과 공격 기록기(`PHitRecorder`)가 읽는 **별도의 관측 경로**다.

그대로 두면 **실력 봇이 세 갈래 저주탄의 확정선과 저주 문양을 보지 못해** 피할 수 없고, 기록기의 공격 통계도 빈다.
`observe.gd:273`의 `elif type == "shaman" and stt == "hex_aim":` 블록 뒤에 두 가지를 더하면 된다.

```gdscript
		elif type == "shaman" and stt == "hex_lock": # 확정된 세 갈래(가운데가 플레이어 방향)
			var n_h: int = int(PEnemiesNew.dv(e, "hexCount", 1.0))
			var st_h: float = PEnemiesNew.dv(e, "hexSpreadDeg", 0.0) * PI / 180.0

		elif type == "shaman" and stt == "rune_aim" and e.has("rune_at"): # 고정된 바닥 문양
			var at_r: Array = e.rune_at

			_th(out, e, "", "circle", "lock", float(e.state_t) / maxf(0.001, need_r), { "x": float(at_r[0]), "y": float(at_r[1]), "r": PEnemiesNew.dv(e, "runeR", 0.0), "shown_left": maxf(0.0, need_r - float(e.state_t)), "label": "rune" })
```

같은 이유로 `scripts/game/render.gd:2153`의 `type == "shaman" and stt == "hex_aim"` 예고 분기에도
`hex_lock`(확정된 세 줄)과 `rune_aim`(고정된 원)을 더해야 한다. §2-5 참고.

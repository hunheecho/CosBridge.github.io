# 냉기·빙결·파쇄 자료 계약 (v2, 2026-09-09)

여러 담당이 동시에 작업하므로 **자료 모양을 먼저 못 박는다.**
규칙 담당은 이 필드를 만들고, 화면 담당은 이 필드만 읽는다. 이름을 바꾸려면 이 문서를 먼저 고친다.

## v1 → v2에서 바뀐 것(규칙 담당이 구현하며 고친 것. 각각 이유를 적었다)

| 무엇 | v1 | v2 | 왜 |
|---|---|---|---|
| `freeze_on` 신호의 종류 필드 | `kind` | **`freeze_kind`** | `st.fx` 사전은 신호 종류를 이미 `kind`로 쓴다. 한 사전에 같은 이름을 둘로 둘 수 없어 적 dict 필드 이름과 같게 맞췄다 |
| 계측 이름 | — | **`chill_targets` 추가** | 개조 '넓은 빙결'이 움직이는 지표가 '중첩 누계'가 아니라 '서로 다른 적의 수'라서, 그 값을 따로 세지 않으면 세 개조를 지표로 가를 수 없다 |
| 파쇄 자격 | 큰 원칙만 | **경로 이름 `frost_shatter`·`frost_shard` 추가**, 파편의 후속 자격을 각 효과의 `deny`에 명시 | "모호하게 두지 않는다"(4절)를 실제 표로 옮겼다 |
| 파쇄 시점 | 명시 없음 | **얼린 그 타격은 깨뜨리지 않는다** | 냉기를 실은 주무기 한 방이 얼리자마자 같은 호출에서 깨면 빙결이 한 프레임도 보이지 않는다 |

구현: `scripts/rules/combat_state.gd`(판정 본체) · `scripts/rules/weapons.gd`(서리 발사·차가운 바닥) ·
`data/supports.json`(`eligibility` 자격표 · `tuning.frost` 시험값 · `weapons.frost` 개조 이름·설명) ·
검사 `tests/frost_tests.gd`. 설명은 `docs/FROST.md`.

## 1. 적 dict 필드

| 필드 | 형 | 뜻 |
|---|---|---|
| `chill` | float(초) | **기존 둔화 지속.** 뜻을 바꾸지 않는다 — 이동 속도 감소용이다 |
| `chill_n` | int | **냉기 중첩 0~`stackMax`.** 실제 적중 이벤트로만 오른다. 매 프레임 상태 검사로 올리지 않는다 |
| `chill_n_t` | float(초) | 중첩 유지 시간. 0이 되면 **전부 한 번에** 사라진다(v2 확정: `stackDecay: "all"`. 1씩 줄이면 화면 표시가 계속 흔들리고 '언제 얼지'를 읽을 수 없다) |
| `freeze` | float(초) | 남은 빙결/결빙 시간. `> 0`이면 그 상태다 |
| `freeze_kind` | String | `"hard"` = 일반·정예(이동·공격 정지) · `"soft"` = 보스 **결빙**(정지 없음) |
| `freeze_broke` | bool | 이번 빙결에서 파쇄가 이미 났는가. **한 번의 빙결에 파쇄는 한 번뿐** |
| `refreeze_t` | float(초) | 재빙결 제한 남은 시간. `> 0`이면 중첩이 차도 얼지 않는다(영구 행동 불능 방지) |

- 새 적을 만들 때 전부 초기화한다(`chill_n` 0 · `chill_n_t` 0.0 · `freeze` 0.0 · `freeze_kind` "" · `freeze_broke` false · `refreeze_t` 0.0).
- 저장·복구에 이 값들이 실려 **복제되지 않아야 한다**(전투 상태는 저장하지 않는다는 기존 규칙 확인).

## 2. 계측 이름 (`PSupport.meter(st, "frost", …)`)

| 이름 | 뜻 |
|---|---|
| `slows` | **새로 둔화가 걸린 적의 수**(기존 뜻 유지) |
| `chill_stacks` | 실제로 부여한 냉기 중첩의 누계 |
| `chill_targets` | 냉기 중첩을 한 번이라도 받은 **서로 다른 적의 수**(v2에서 추가) |
| `freezes` | 빙결(hard) 발생 횟수 |
| `chills_boss` | 결빙(soft) 발생 횟수 |
| `freeze_sec` | 빙결·결빙 **적·초**(상태인 적 하나가 1초를 보내면 1.0) |
| `shatters` | 파쇄 횟수 |
| `shard_hits` | 파편이 실제로 맞힌 수 |
| `shard_dmg` | 파편이 준 피해 |

`slows`와 `freeze_sec`는 **단위가 다르다**(횟수 vs 적·초). 서로 더하지 않는다 — 2026-09-09 BP-2와 같은 실수를 반복하지 않는다.
`freezes`·`shatters`(횟수)와 `freeze_sec`(적·초)도 마찬가지다.

`chill_targets`는 **적 id로 한 번만** 센다(같은 적이 다시 0에서 쌓아 올려도 더 세지 않는다).
그래야 '넓이'를 재는 값이 되고, 개조 **넓은 빙결**의 지표로 쓸 수 있다. 그 목록은
`CombatState._frost_seen`(계측 전용)이 들고 있으며 적 dict에는 필드를 더하지 않았다 — 화면이 읽을 값이 아니기 때문이다.

## 3. 화면에 보낼 신호 (`st.fx`)

| kind | 필드 | 언제 |
|---|---|---|
| `freeze_on` | `x, y, r, freeze_kind("hard"/"soft"), ttl` | 빙결·결빙이 걸린 순간 |

> **정정(2026-09-09).** 처음에는 이 신호의 칸 이름을 `kind`라고 적었는데, `st.fx`의 `kind`는
> **연출 종류**(`"freeze_on"` 자체)로 이미 쓰이는 자리라 한 사전에 둘 다 담을 수 없다.
> 그래서 1절의 적 dict와 **같은 이름 `freeze_kind`**를 쓴다. 화면은 값이 없으면 `"hard"`로 본다.
> **규칙 담당과 화면 담당이 서로 모르는 채 같은 결론에 이르렀고**, 실제 코드도 양쪽 다 `freeze_kind`다.
| `shatter` | `x, y, r, shards(int), ttl` | 파쇄가 **실제 피해 판정과 같은 프레임에** 났을 때 |

- **이름 변경(v2, 규칙 담당 2026-09-09):** `freeze_on`의 종류 필드는 `kind`가 아니라 **`freeze_kind`**다.
  `st.fx`의 사전은 신호 종류를 이미 `kind`로 쓰고 있어(`{"kind": "freeze_on", …}`) 같은 이름을 둘로 쓸 수 없었다.
  적 dict의 필드 이름(`freeze_kind`)과 같게 맞춰 화면이 두 곳에서 같은 이름을 읽게 했다.
- **장식 파편을 그리지 않는다.** 그린 파편 수는 실제 판정에 쓰인 수와 같아야 한다.
  파편은 투사체가 아니라 **즉시 반경 판정**이므로 `shards`는 그 프레임에 **실제로 맞힌 적의 수**다
  (주변에 아무도 없으면 0이며, 그때도 파쇄 자체는 났으므로 신호는 나온다 — `r`로 고리만 그리면 된다).
- 빗나간 공격에서는 `shatter`가 나오지 않는다.
- 화면이 쓰는 난수는 **전투 난수(`st.rng`)를 소비하지 않는다.** 화면 전용 난수를 따로 쓴다.
- 규칙이 더 내는 것: 소리 이벤트 `freeze`(빙결·결빙 시작)와 기존 `shatter`(파쇄), 떠오르는 글자
  "빙결!" / "결빙!" / "파쇄!". 옛 개조 '깨지는 수정'의 표시 전용 신호 `shatter_burst`는 **더는 나오지 않는다**
  (그 개조가 탄환을 쪼개지 않게 되었다 — 4절 참고). 화면 쪽에 그 그리기 코드가 남아 있어도 해가 없지만, 죽은 가지다.

## 4. 파쇄 자격 (자격표 `data/supports.json` eligibility)

- 파쇄를 **터뜨리는 것은 주무기 공격**이다. `PSupport.cause_of`가 돌려주는 원인 중
  `main_direct`와, 주무기 개조가 만든 **직접 추가 타격**(`main_extra`)이 자격을 갖는다.
- **2026-09-10 사용자 확정으로 장비 기술 네 종의 직접 타격이 더해졌다** —
  `eq_slash`(찰나 가르기) · `eq_meteor_core`·`eq_meteor_wave`(낙성 강하) · `eq_riposte`(받아치기) ·
  `eq_retrace`(되짚는 궤적). 그 다섯 이름을 `frost_shatter.allow`에 **그대로** 적었다
  (장비 기술을 `main_direct`로 위장하지도, `equip_skill_direct` 같은 묶음 이름을 만들지도 않았다).
  **`eq_icetomb`(결정 관)은 `deny`에 그대로**이고 [9] 유예의 시계는 피해 경로 이름 자체가 없다.
- 지속 피해(`dot`) · 장판(`zone_tick`) · 보조 공격(`support_direct`) · 지뢰(`mine_blast`)는 **깨뜨리지 못한다.**
  잔영 분신의 모방(`echo_direct`)도 보조가 낸 타격이므로 못 깨뜨린다.
- **2026-09-10: Q/E 일반 수동 기술도 깨뜨리지 못한다**(사용자 확정). 여섯 경로
  `skill_strike` · `skill_gust` · `skill_bladestorm` · `skill_gravity` · `skill_ward` · `skill_other`를
  `frost_shatter.deny`에 **명시**했다. **이것은 새 제한이 아니라 기존 합의 범위로 되돌린 것이다** —
  그전에는 `PSkills.hit`이 경로 이름을 적지 않아 수동 기술의 피해가 전부 `main_extra`로 떨어졌고,
  그래서 "파쇄를 터뜨리는 것은 주무기 공격"이라는 이 절의 확정을 **우회하고 있었다.**
  실측(고치기 전 → 후): 얼어붙은 늑대에게 낙뢰·돌풍·칼날 폭풍·중력핵을 하나씩 실제로 발동했을 때
  파쇄 **4회 → 0회**, 수호 결계 '맥동'까지 더하면 **5회 → 0회**. 같은 자리에서 주무기 한 대는 여전히 1회다.
  검사는 `tests/skill_cause_tests.gd`.
- 파쇄 추가 피해와 파편은 **다시 냉기를 쌓지 않고 다른 빙결을 파쇄하지 않는다**(재귀 차단).
  그 두 경로의 이름은 `frost_shatter` · `frost_shard`이며 자격표 `causes`에 추가했다.
- 파편이 감전 등 다른 후속을 부르는지는 자격표에 **명시**한다(모호하게 두지 않는다).
  못 부르는 것: `shock_bonus` · `crow_mark` · `echo_copy` · `frost_shatter` · `frost_stack`(각각의 `deny`에 `frost_shard`를 적어 두었다).
  부르는 것: `plague_spread`(처치는 무엇으로 죽였든 전염된다는 기존 규칙을 파편만 예외로 두지 않는다).
- 같은 프레임의 다중 적중으로 같은 적의 파쇄가 **중복 정산되지 않는다**(`freeze_broke`).
- **얼린 그 타격은 깨뜨리지 않는다**(v2 규칙 추가). 냉기를 실은 주무기 한 방이 5중첩을 채운 바로 그
  `damage_enemy` 호출에서는 파쇄하지 않는다 — 그러지 않으면 빙결이 한 프레임도 보이지 않고
  '얼리고 → 내가 깬다'의 두 박자가 사라진다. 같은 프레임의 **다음** 타격은 깰 수 있다.
- 개조 `shatter`(옛 '깨지는 수정' → 새 **파쇄 강화**)는 이제 탄환을 쪼개지 않는다.
  파쇄가 났을 때의 파편 수·파편 피해·반경만 키운다.

## 5. 쌍검 집중 중첩 표시용 필드

주무기 담당이 이미 만든 값을 화면이 읽는다. 이름이 지역 변수뿐이면 **무기 dict에 최소한으로 노출**한다:

| 필드 | 형 | 뜻 |
|---|---|---|
| `w.focus_id` | int | 지금 집중 중인 적 id(없으면 -1) |
| `w.focus_n` | int | 현재 중첩 0~`maxStack` |
| `w.focus_t` | float(초) | 남은 유지 시간(`window`) |

규칙은 바꾸지 않는다 — **이미 계산하고 있는 값을 밖에서 볼 수 있게만** 한다.

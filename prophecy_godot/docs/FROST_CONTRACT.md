# 냉기·빙결·파쇄 자료 계약 (v1, 2026-09-09 확정 지시)

여러 담당이 동시에 작업하므로 **자료 모양을 먼저 못 박는다.**
규칙 담당은 이 필드를 만들고, 화면 담당은 이 필드만 읽는다. 이름을 바꾸려면 이 문서를 먼저 고친다.

## 1. 적 dict 필드

| 필드 | 형 | 뜻 |
|---|---|---|
| `chill` | float(초) | **기존 둔화 지속.** 뜻을 바꾸지 않는다 — 이동 속도 감소용이다 |
| `chill_n` | int | **냉기 중첩 0~`stackMax`.** 실제 적중 이벤트로만 오른다. 매 프레임 상태 검사로 올리지 않는다 |
| `chill_n_t` | float(초) | 중첩 유지 시간. 0이 되면 중첩이 사라진다(전부 소멸인지 1씩인지는 규칙 담당이 정하고 근거를 적는다) |
| `freeze` | float(초) | 남은 빙결/결빙 시간. `> 0`이면 그 상태다 |
| `freeze_kind` | String | `"hard"` = 일반·정예(이동·공격 정지) · `"soft"` = 보스 **결빙**(정지 없음) |
| `freeze_broke` | bool | 이번 빙결에서 파쇄가 이미 났는가. **한 번의 빙결에 파쇄는 한 번뿐** |
| `refreeze_t` | float(초) | 재빙결 제한 남은 시간. `> 0`이면 중첩이 차도 얼지 않는다(영구 행동 불능 방지) |

- 새 적을 만들 때 전부 초기화한다(`chill_n` 0 · `chill_n_t` 0.0 · `freeze` 0.0 · `freeze_kind` "" · `freeze_broke` false · `refreeze_t` 0.0).
- 저장·복구에 이 값들이 실려 **복제되지 않아야 한다**(전투 상태는 저장하지 않는다는 기존 규칙 확인).

## 2. 계측 이름 (`PSupport.meter(st, "frost", …)`)

| 이름 | 뜻 |
|---|---|
| `slows` | **새로 둔화가 걸린 적의 수**(기존 뜻 유지) |
| `chill_stacks` | 실제로 부여한 냉기 중첩의 누계 |
| `freezes` | 빙결(hard) 발생 횟수 |
| `chills_boss` | 결빙(soft) 발생 횟수 |
| `freeze_sec` | 빙결·결빙 **적·초**(상태인 적 하나가 1초를 보내면 1.0) |
| `shatters` | 파쇄 횟수 |
| `shard_hits` | 파편이 실제로 맞힌 수 |
| `shard_dmg` | 파편이 준 피해 |

`slows`와 `freeze_sec`는 **단위가 다르다**(횟수 vs 적·초). 서로 더하지 않는다 — 2026-09-09 BP-2와 같은 실수를 반복하지 않는다.

## 3. 화면에 보낼 신호 (`st.fx`)

| kind | 필드 | 언제 |
|---|---|---|
| `freeze_on` | `x, y, r, freeze_kind("hard"/"soft"), ttl` | 빙결·결빙이 걸린 순간 |

> **정정(2026-09-09, 화면 담당 지적).** 처음에는 이 신호의 칸 이름을 `kind`라고 적었는데,
> `st.fx`의 `kind`는 **연출 종류**(`"freeze_on"` 자체)로 이미 쓰이는 자리라 한 dict에 둘 다 담을 수 없다.
> 그래서 1절의 적 dict와 **같은 이름 `freeze_kind`**를 쓴다. 화면은 값이 없으면 `"hard"`로 본다.
| `shatter` | `x, y, r, shards(int), ttl` | 파쇄가 **실제 피해 판정과 같은 프레임에** 났을 때 |

- **장식 파편을 그리지 않는다.** 그린 파편 수는 실제 판정에 쓰인 수와 같아야 한다.
- 빗나간 공격에서는 `shatter`가 나오지 않는다.
- 화면이 쓰는 난수는 **전투 난수(`st.rng`)를 소비하지 않는다.** 화면 전용 난수를 따로 쓴다.

## 4. 파쇄 자격 (자격표 `data/supports.json` eligibility)

- 파쇄를 **터뜨리는 것은 주무기 공격**이다. `PSupport.cause_of`가 돌려주는 원인 중
  `main_direct`와, 주무기 개조가 만든 **직접 추가 타격**만 자격이 있다.
- 지속 피해(`dot`) · 장판(`zone_tick`) · 보조 공격(`support_direct`) · 지뢰(`mine_blast`)는 **깨뜨리지 못한다.**
- 파쇄 추가 피해와 파편은 **다시 냉기를 쌓지 않고 다른 빙결을 파쇄하지 않는다**(재귀 차단).
- 파편이 감전 등 다른 후속을 부르는지는 자격표에 **명시**한다(모호하게 두지 않는다).
- 같은 프레임의 다중 적중으로 같은 적의 파쇄가 **중복 정산되지 않는다**(`freeze_broke`).

## 5. 쌍검 집중 중첩 표시용 필드

주무기 담당이 이미 만든 값을 화면이 읽는다. 이름이 지역 변수뿐이면 **무기 dict에 최소한으로 노출**한다:

| 필드 | 형 | 뜻 |
|---|---|---|
| `w.focus_id` | int | 지금 집중 중인 적 id(없으면 -1) |
| `w.focus_n` | int | 현재 중첩 0~`maxStack` |
| `w.focus_t` | float(초) | 남은 유지 시간(`window`) |

규칙은 바꾸지 않는다 — **이미 계산하고 있는 값을 밖에서 볼 수 있게만** 한다.

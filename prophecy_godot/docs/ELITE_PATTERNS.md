# 특수 정예 7종 — 신규 공격 패턴 14개 (§11-B, 2026-09-10)

**모든 수치는 첫 시험값이다.** 사람이 재미·밸런스를 확인한 값이 아니다.
정본은 `data/pacing.json` → `enemy_tuning.elite_*`, 규칙은 `scripts/rules/enemies_new.gd`,
표는 `PEnemiesNew.NEW_PATTERNS`, 검사는 `tests/elites_tests.gd`(§11-B 절), 계측은 `tools/probe_patterns.gd`.

## 목표

개수가 목표가 아니다. **"멀리서 같은 방향으로 걸으며 자동 공격"하는 놀이를 실제로 흔드는 것**이다.
그래서 패턴마다 둘 중 하나의 역할을 준다.

- **접근 압박(7개)** — 걸어서 벌린 거리를 정예가 **스스로 좁힌다.**
- **도주 경로 차단(7개)** — 지금 걷고 있는 **앞쪽**을 막거나 앞질러 선다.

## 지킨 선

| 지시 | 어떻게 지켰나 |
|---|---|
| 확정 뒤 끝까지 따라와 반드시 맞히는 방식 금지 | 모든 패턴이 lock(또는 실행) 시점에 각·자리를 굳히고 그 뒤 갱신하지 않는다. 검사 ③이 확정 시점 값과 이후 값을 문자열로 비교해 단언한다 |
| 플레이어 입력을 미리 읽지 말 것 | `PEnemiesNew.obs_vel()` — 개체가 **직접 관측한 위치 변화**를 0.30초짜리 지연으로 흐려 쓴다. `p.face`(그 프레임의 입력 방향)는 어디서도 읽지 않는다 |
| 방향 전환·안쪽 진입·회피로 피할 수 있어야 | 관측이 0.30초 늦으므로 방향을 꺾으면 앞을 겨눈 예고가 어긋난다. 검사 ②가 세 가지 대응(꺾음·멀어짐·회피)을 각각 굴려 **적어도 하나는 빗나가는지** 단언한다 |
| 연계 종료 후 반격 기회 유지 | 모든 패턴이 `recover`(빈틈)로 끝난다. 검사 ④ |
| 무적·강제 생존·체력 구간 피해 상한 금지 | 적 규칙에 그런 낱말이 없는지 검사가 원본을 훑어 단언한다 |
| 기존 회피는 유지하고 패턴 수에 세지 않는다 | `docs/ELITE_DODGE.md` 그대로. 이 문서에 회피는 없다 |
| 기존 공격의 속도·조준 개선을 신규로 세지 않는다 | 사슬 발사 속도·도마뱀 준비시간은 **§12**(다른 절)이며 여기 세지 않는다 |

### 원안과 다르게 만든 것

원안 그대로 만들었고, **역할·조건만 두 곳에서 넓혔다**(구현상 모순이 아니라 계측 결과다).

| 항목 | 원안 | 지금 | 이유 |
|---|---|---|---|
| 추격 사격 시작 조건 | "달려 접근하다" | `dist > chaseStop(200)` | 원안대로 '사거리 밖(340)'만으로 잡으면 실제 전투에서 **한 번도 서지 않았다**(`probe_patterns` 계측). 궁수가 스스로 190~340을 유지하기 때문이다 |
| 달리는 물어뜯기 사거리 | "짧은 물기" | 사거리 82 + 반지름 16 = 98(기본 물기 68보다 넓다) · 부채꼴 60도(기본 90도보다 좁다) | 예고 중 덤벼드는 속도를 걷기(220)보다 **느리게**(101) 잡아 '옆으로 걸으면 맞고 뒤로 물러나면 빠져나간다'를 만들려면 사거리가 달려오는 판정 거리보다 넓어야 했다 |

또 **양면 협공의 본체 대체 연계**는 원안이 요구한 대로 넣었고(부하가 없을 때), 예고 상태(`pincer_aim`)는
부하가 있든 없든 **같다** — 예고가 끝날 때 갈린다. 화면에 뜨는 낱말만 다르다("반대편으로" / "혼자서 두 번").

## 관측 이동(`obs_vel`) — 앞을 겨누는 근거

```
매 프레임:  v ← v + ((지금 위치 − 지난 프레임 위치)/dt − v) × (dt / 0.30)
앞 지점:    P + v × tof   (tof = 확정부터 착탄까지, 상한 <id>LeadMax)
```

- 시간상수 0.30초짜리 **지연**이라, 방향을 꺾으면 최대 0.30초 동안 옛 방향을 가리킨다 → 그래서 피할 수 있다.
- `tof`는 **확정 시점부터 실제 착탄까지**로 맞춘다. 이보다 크게 잡으면 계속 걷는 상대에게 오히려 빗나가고
  꺾은 상대에게 맞는 이상한 모양이 된다(사슬 끌어쓸기 첫 시험값 0.7초의 결함. 0.35초로 고쳤다).
- `LeadMax`가 있어 **무한정 앞서 겨누지 않는다.**

읽는 법

- **① 맞음**이 접근 압박 7/7 = "같은 방향으로 걷기만 하면 전부 빗나간다"가 **아니다**.
- **② 셋 중 하나는 빗나감**이 14/14 = 어떤 패턴도 대응 불가가 아니다.
- **③ 굳음 / 확정=실행** = 확정 뒤 추적이 없다. `확정=실행`인 셋(runbite·pincer·surface)은
  **확정과 실행이 같은 순간**이라 추적할 구간 자체가 없는 것들이다(각이 아니라 **거리**로 피한다).
- **차단 역할이 ①에서 빗나감**인 것은 정상이다. 그쪽은 걷는 앞을 막는 것이지 지금 자리를 때리는 것이 아니다.

### 계측(`tools/probe_patterns.gd`) — 실제 전투에서 왜 덜 쓰이나

정예가 `approach`(패턴을 고를 수 있는 상태)로 돌아와 있는 시간은 **45초 중 2~4초뿐**이다.
나머지는 자기 연계와 빈틈이다. 그 좁은 창에서 거리 조건이 서야 패턴이 쓰인다.
그래서 첫 시험값의 사슬 끌어쓸기 300 · 양면 협공 320은 창에서 거의 서지 않아 380 · 420으로 넓혔다.
**예고·확정 시간과 피해는 하나도 바꾸지 않았다.**

## 남은 관찰거리

- `runbite`가 ①에서 빗나가는 것은 "달려붙는 속도(240)가 걷기(220)보다 겨우 빠르다"는 첫 시험값 때문이다.
  올리면 ①은 맞지만 **멀어지기로 빠져나갈 길**이 사라진다. 지금은 후자를 택했다.
- `drag`가 회피로만 빠져나가는 판이 있다(꺾음·멀어짐이 둘 다 맞은 판). 쓸기 각(60도)과 추 반지름(26)의 첫 시험값 문제이며,
  사람 손으로 재미를 확인하기 전에는 더 줄이지 않았다.
- 접근 압박 패턴 다섯이 **멀어지기에는 맞는다**(chase·step·anchor·rush). 등속으로 멀어지는 것은 관측이 그대로 맞히기 때문이며,
  설계 의도(걷기만으로 벌리는 놀이를 흔든다)와 같은 방향이다. **꺾으면 빠져나간다.**

# Godot 첫 전투 규칙 (현재 규칙 · 시험값 · 변경 이력 · 검증 상태)

> godot-0.4.0(2026-09-07)부터 이 문서의 규칙은 **기준 전투**(0.3.1 D33, `CombatState.first_fight`)와 회차 전투의 늑대·회피·밀도 공통 규칙을 설명한다. 나머지 콘텐츠(자동기술·Q/E·적 12종·보스·목표·회차·경제)는 HTML `GAME_SPEC.md` §19가 규칙 정본이고, Godot에서 다른 점만 `docs/PORT_BASELINE.md` §6과 `ASSUMPTIONS.md` §전체 게임 이식에 적는다(같은 규칙을 두 곳에 쓰지 않는다). 회차 전투의 편성 변환은 §밀도의 규칙을 `FORMATION_TABLE.md`대로 전 지역에 적용한 것이다.

이 문서가 Godot 버전 규칙의 기준이다. 숫자는 `data/first_fight.json`, 규칙 코드는 `scripts/rules/combat_state.gd`. 화면(`scripts/game/`)은 규칙을 읽기만 한다. HTML v0.8.0(ee10fc7)과 다른 점은 각 절에 적는다. 설계 변경의 이유·사용자 판단은 저장소 루트 `docs/DESIGN_DECISIONS.md`(D34 회피, D35 늑대·밀도, D36 피해 통계).

**비교 기준 조합(D33)**: godot-0.3.1의 기본값 조합(편성 x5, 회피 hold·1.5초, 동시 돌진 2, 늑대 체력 30, 물기·돌진 12)을 사용자가 직접 플레이하고 긍정 평가했다(2026-09-07). 이후 어떤 절의 값을 바꾸더라도 이 조합을 같은 OS에서 함께 재측정해 비교 기준으로 남긴다. 조합 전체의 체감 평가이며 개별 값·최종 밸런스 승인이 아니다.

## 공통
- 고정 단계 1/120초. 입력은 게임 행동 `{mx, my, dodge_press, dodge_held, special}`. 사람(키보드)과 봇이 같은 `CombatState.step`을 쓴다.
- 한 단계의 순서: 플레이어(이동·회피·Q·검격) → 적 → 감속장·효과 → 승패 판정. 승패는 1회만 확정되고 그 뒤 전투 시간은 멈춘다.
- 난수는 시드 하나(mulberry32). 같은 시드·같은 입력 열 → 같은 결과. 회피 설정은 난수를 쓰지 않으므로 설정이 달라도 같은 시드의 적 배치는 같다(테스트 D13). 단, 이 결정성은 같은 OS 안에서만 확인됐다: 같은 코드·같은 시드라도 Linux와 Windows에서 긴 전투(25·50마리)의 시간·처치가 달라질 수 있다(PORT_NOTES §11, 부동소수점 수학 함수 차이로 추정·미확정).
- 받은 피해 집계(godot-0.3.1): 플레이어에게 들어간 **유효 피해 = min(피해량, 타격 직전 남은 체력)**. 총합(`stats.damage_taken`)과 출처별(`metrics.taken[src]`)에 같은 유효 피해를 기록하므로 출처별 합 = 총 유효 피해 = 실제 체력 감소가 항상 성립한다. 명목 피해(과잉 포함)는 `stats.damage_taken_nominal`에만 따로 남긴다. 회피 무적·피격 보호·사망 뒤에 거부된 공격은 어느 집계에도 남지 않는다(테스트 E18·E20~E23). 적에게 준 피해도 같은 원칙(`metrics.dmg`, 과잉 제외). 생존 판정·피격 보호 0.6초·회피 무적 규칙은 바뀌지 않았다.

## 회피 (2026-09-07 시험 설계, 최종 밸런스 아님)
변경 이유: 사용자가 회피 거리 조절을 제안했고, 기존 0.9초 쿨다운이 너무 짧을 가능성이 있어 기본 1.5초로 시험한다. 목표는 회피를 자주 반복하기보다 적의 예고를 보고 이동 거리를 고르는 재미.

### 입력
| 규칙 | 내용 |
|---|---|
| 출발 | Space를 누르는 순간(`dodge_press`) 같은 단계에서 즉시 출발. 짧게/길게 판별을 기다리지 않는다 |
| 방향 | 출발 순간 고정. 이동 입력이 있으면 그 방향(대각선 정규화), 없으면 마지막으로 바라보던 방향(`face`, 시작값 오른쪽). 회피 중 이동 입력은 무시(HTML과 같음) |
| 짧게 | 누른 뒤 떼면(`dodge_held`=false) **최소 거리 70**을 채운 시점에 종료. 누른 단계에서 이미 뗀 아주 짧은 탭도 70 |
| 길게 | 계속 누르면 **최대 거리 150**에서 종료(누르고 있어도) |
| 재발동 | 계속 누르고 있어도 대기 시간이 지나 저절로 다시 회피하지 않는다. 새 회피는 뗐다가 새로 눌러야 한다(`dodge_press`는 1회성) |
| 대기 중 누름 | 재사용 대기 중의 누름은 버려진다. 나중에 저절로 발동하지 않는다 |

### 수치 (기본값)
| 항목 | 값 | 비고 |
|---|---|---|
| 방식 | `hold` 누르는 시간에 따른 거리 조절 | 비교용 `fixed`(항상 150, 옛 HTML 방식) |
| 최소 거리 | 70 | 장애물 없는 상황의 보장 거리 |
| 최대 거리 | 150 | |
| 속도 | 150 / 0.26 ≈ 577/s, 회피 중 일정 | HTML과 같은 속도 |
| 무적 | **이동과 따로 센다.** 회피 **시작 순간**부터 주무기별 무적 시간(`player.invuln_t`) | 2026-09-10 변경. 예전에는 `dodge_active`(이동 중)에만이라 짧은 탭이면 0.12초에 끊겼다. 지금은 이동이 먼저 끝나도 남은 무적이 그대로다 |
| 재사용 대기 | **주무기별, 출발 순간부터**(아래 표) | 짧게 써도 같다. 표에 있는 주무기는 비교 설정(0.9/1.2/1.5/1.8)이 덮지 않는다 |
| 장애물 | 바위·나무·전장 경계에 막히면 그 자리에서 즉시 종료(무적도 끝). 통과·겹침 없음. 최소 거리를 채우려 붙어 있지 않는다 | 막힌 채 누르면 거리 0으로 끝나며 대기 시간은 소모된다(미결: 사용자 판단) |
| 단계 반올림 | 마지막 이동량을 남은 거리로 제한. 150 = 31단계 + 0.4(**이동** 0.2583초 ≤ 0.26) | 초과 이동 없음. 무적은 별도 계산이라 여기에 걸리지 않는다 |

#### 주무기별 재사용 대기·무적 (2026-09-10 시험값, 최종 아님)
자료: `data/config.json` `PLAYER.dodge.byWeapon` · 코드: `CombatState.resolve_dodge()`.
이동거리(70~150)와 이동시간(0.26초)은 다섯 무기가 **모두 같다**. 무기마다 다른 것은 아래 둘뿐이다.

| 주무기 | 재사용 대기 | 무적 | 실측(1/120초 단계) |
|---|---|---|---|
| 쌍검 | 0.9초 | 0.36초 | cd 0.900 · 무적 0.358 · 이동 0.258 |
| 검 | 1.1초 | 0.32초 | cd 1.100 · 무적 0.317 · 이동 0.258 |
| 관통창 | 1.3초 | 0.28초 | cd 1.300 · 무적 0.275 · 이동 0.258 |
| 전투망치 | 1.6초 | 0.32초 | cd 1.600 · 무적 0.317 · 이동 0.258 |
| 추적궁 | 2.2초 | 0.26초 | cd 2.200 · 무적 0.258 · 이동 0.258 |

- 실측의 무적이 설정값보다 최대 한 단계(0.0083초) 짧은 것은 단계 반올림이다(`0.36 - 43/120 = 0.0017` 남고 44단계에서 0으로 떨어진다).
- 무적 < 재사용 대기가 다섯 무기 모두에서 성립한다 → **상시 무적이 되지 않는다**. 가장 빠듯한 쌍검도 0.36 / 0.9 = 40%.
- 재사용 대기 배율(`build.dodge_cd_mult`)은 성장·장비가 건드리지 않는다(항상 1.0). 대기 중 연타로 무적이 겹치지도 않는다(`invuln_t`는 더하지 않고 `maxf`로 덮는다).
- 시험: `tests/main_weapon_tests.gd` §10, `tests/run_tests.gd` D2·D4·D6.

### HTML(ee10fc7)과 다른 점
- HTML: 항상 150, 무적 0.26초, 재사용 0.9초가 **회피 종료 시점부터**(출발 기준 약 1.17초). Godot: 위 표. `fixed`+0.9 비교 설정도 재사용은 출발 순간부터라 과거와 완전히 같지는 않다(0.27초 빠름) — 두 방식을 같은 재사용 규칙으로 비교하기 위해 통일했다.
- 대조 측정(`tools/compare_scenario.gd`, fixed·0.9)에서 `dodge_cd_after`만 HTML과 다르다(0.6333 vs 0.8933). 거리·무적 단계·나머지 13개 측정은 같다.

### 프레임 → 단계 (`scripts/game/step_driver.gd`, 화면과 테스트가 같은 코드)
- 누름은 `_unhandled_input`에서 기록되고 다음에 실행되는 첫 단계에서 정확히 1번 소비된다. 프레임 사이의 짧은 탭도 잃지 않는다. 한 프레임에 여러 단계가 돌아도 중복 소비하지 않는다.
- `dodge_held`는 프레임 시작 시점의 키 상태(`Input.is_action_pressed`)를 그 프레임의 모든 단계에 준다.
- 일시정지·재시작·포커스 상실은 `driver.reset()`: 대기 중인 누름을 버린다. 일시정지 중 입력은 받지 않는다. 재개 뒤 회피는 새 누름이 필요하다(누른 채 재개해도 발동 없음).
- 너무 긴 프레임(>0.1초)은 12단계까지만 진행하고 나머지를 버린다(멈춤 방지, HTML과 같음).

### 비교 설정
F3 검증 패널 오른쪽: 회피 방식(고정 거리 / 누르는 시간에 따른 거리 조절) × 재사용 대기(0.9 / 1.2 / 1.5 / 1.8). **2026-09-10부터 재사용 대기 선택은 주무기별 표에 없는 주무기에만 적용된다** — 표에 있는 다섯 주무기는 표의 값이 정본이다(그래서 기준 전투는 어떤 선택에서도 검 1.1초로 돈다). 패널·HUD의 "재사용 N초" 문구는 아직 비교 설정의 값을 그대로 적으므로 표가 이기는 경우와 어긋난다(알려진 표시 결함, `scripts/game/game.gd` `dodge_text`). 전투 중에는 바뀌지 않고 **다음 재시작**(Enter 또는 패널의 "이 설정으로 같은 시드 다시 시작")에 적용. 같은 시드 = 같은 적 배치. 적용된 설정은 HUD 하단·검증 패널·결과 화면(회피 거리 목록 포함)에 표시. 기본값은 자동으로 바뀌지 않는다.

### 봇
봇(`scripts/rules/bot.gd`)은 사람과 같은 규칙·같은 입력 형식을 쓴다. 정책: 확정된 돌진 통로 안이면 `dodge_press`, 회피가 끝날 때까지 `dodge_held`(항상 최대 거리를 시도). 즉시 종료·대기 우회 같은 봇 전용 처리는 없다. 봇은 거리를 고르지 않으므로 봇 결과로 재미·밸런스를 판단하지 않는다.

## 늑대 (godot-0.3.0 시험 설계, 2026-09-07 — 최종 밸런스 아님)
사용자 결정: 몬스터가 너무 적어 위협이 없다. 단순 접촉 피해는 넣지 않는다. 늑대는 가까우면 짧은 물기, 멀면 돌진. 물기는 자주, 돌진은 훨씬 드물게. 적이 많아도 예고와 반격 기회가 읽혀야 한다.
숫자는 `data/first_fight.json` `enemies.wolf`, 근거는 `docs/ASSUMPTIONS.md`.

### 공격 선택(접근 상태에서 매 단계)
| 조건 | 행동 |
|---|---|
| 플레이어 중심까지 ≤ 물기 사거리 44, 물기 재사용 가능 | 물기 시도 |
| 44 초과, 첫 돌진 지연 경과, 돌진 재사용 가능, 거리 70~170, 시야 확보, 동시 돌진 자리 확보 | 돌진 시도 |
| 그 외(돌진 대기 중·자리 없음·너무 가까움·너무 멂) | 접근해서 물기 시도. 사거리 안인데 물기 대기 중이면 제자리 |
| 공격 중·공격 뒤 빈틈 | 다른 공격으로 바꾸지 않음(플레이어가 움직여도 절차를 마친다) |

물기·돌진 재사용 대기는 독립. 돌진 대기가 끝났다고 사거리 안(≤44)의 플레이어에게 억지로 돌진하지 않는다(70 미만이면 돌진 조건 불충족).

### 시간 단위·감속장·일시정지
- 상태 시간(준비·고정·유효·빈틈·돌진)과 **재사용 대기(물기 1.2·돌진 8)**는 모두 `dt × 적 시간 배율`로 진행. 감속장 안(배율 0.4)에서는 대기가 0.4배로 느리게 돌아온다 → 감속장에서 더 빨리 돌아오는 역전 없음(테스트 E9: 안 1초 = 0.4초 진행).
- 첫 돌진 지연(dash_ready_at)은 절대 시뮬레이션 시각(`t`)과 비교(배율 없음).
- 일시정지는 단계를 진행하지 않으므로 전부 정지.

### 동시 돌진 제한
- 전투 전체에서 준비(crouch)·고정(lock)·실행(dash) 상태의 늑대 합계 ≤ 2(기본). F3에서 2/3 비교.
- 자리는 매 단계 상태를 세어 계산(`dash_states_count`)하므로 사망·전투 종료 시 정확히 반환되고 중복 확보가 없다. 빈틈(recover)은 포함하지 않음.
- 여러 늑대가 같은 단계에 돌진을 원하면 **마지막 돌진 종료 시각이 오래된 순, 동률은 id 순**으로 빈 자리만큼 허가. 추첨 없음 → 같은 시드·입력이면 같은 순서(테스트 E11 attack_log 재현).
- 자리를 얻지 못한 늑대는 돌진 예고를 띄우지 않고 접근·물기.

### 접촉·겹침
- 피해는 물기·돌진 판정만. 스침·오래 붙어 있음·겹침만으로 피해 없음(테스트 E15).
- 겹침 해소: 적끼리 절반씩(단계당 ≤6px), 적-플레이어는 적 70%·플레이어 30%. 플레이어 밀림은 여러 적을 합산해도 **120/s 상한**(단계당 1px), 밀린 뒤 장애물·경계 밖으로 보정. 같은 좌표면 id 기반 고정 방향. 회피 중(무적)에는 적의 몸을 통과한다. 돌진 중인 늑대는 겹침 해소에서 제외.
- 피격 보호 0.6초는 공용 1개(적별 아님): 물기 3개가 같은 순간 겹쳐도 12만 잃는다(테스트 E16).

### 화면 표시
물기: 머리 앞 짧은 부채꼴(반지름 44 = 판정 거리, 100°). 추적 = 옅은 주황, 고정 = 진한 주황 + 테두리 + '!', 유효 = 흰색 0.1초, 빈틈 = 늑대 연한 파랑. 돌진 통로는 동시 최대 2개만 존재하므로 화면을 덮지 않는다.

## 랜덤 지형 (2026-09-08 시험 설계, **기본 꺼짐** — 최종 밸런스 아님)
사용자 요구 7("랜덤 맵/지형 가능성. 밀도 편차 과다·고립·막힌 목표·불공정 배치 방지"). 전장을 새로 만들지 않는다.
**검증된 전장 뼈대(`data/themes.json`·`data/config.json`의 arenas)는 그대로 두고** 그 위에 장애물 후보 자리를 추첨해 더한다(`scripts/rules/terrain.gd`, `PTerrain`).

- **켜는 법.** 기본은 꺼져 있어 지금까지의 모든 측정·기준값이 그대로다. `PROPHECY_TERRAIN=1` 또는 조우 옵션 `terrain_random: true`로 켠다.
- **적용하지 않는 곳.** 승인된 기준 전투(`first_fight`), **보스 전장(지금 배치 유지)**, 옵션으로 장애물을 직접 준 전투.
- **난수.** 지형 전용 `PRng`를 따로 만든다(시드 = 전투 시드 ⊕ 전장 이름). **`st.rng`(전투 난수)를 쓰지 않는다** — 소비 순서가 바뀌면 기준 전투가 깨진다.
- **좌우 대칭.** 후보 자리는 가로 중앙을 기준으로 **쌍으로** 놓는다(중앙선 위 자리는 하나). 한쪽만 막히는 불공정 배치를 구조로 막는다.
- **재현.** 같은 시드는 같은 배치를 만든다. 결과는 `st.terrain`에 남고, 그 값을 조우 옵션 `terrain`으로 주면 시드와 무관하게 그대로 되살아난다.
- **실패 처리.** 조건을 어기면 최대 12회 다시 뽑고, 그래도 안 되면 **뼈대 그대로** 쓴다(무한 루프 없음).

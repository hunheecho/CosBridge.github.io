# 웹(브라우저) 빌드 — 안드로이드 시험용

**같은 Godot 프로젝트를 웹으로 내보낸 것이다.** 모바일 전용 전투 코드는 없고, 옛 HTML 시제품과도 무관하다.
이 문서는 준비 절차와 확인 결과만 적는다. **배포(공개 호스팅)는 여기서 하지 않는다** — §7.

측정한 환경: Godot 4.7.2-stable, Windows 10, 커밋 `9472291` 기준.

---

## 1. 되는가 — 결론

| 항목 | 결과 |
| --- | --- |
| 웹 내보내기 템플릿 | 있다 (`%APPDATA%/Godot/export_templates/4.7.2.stable/web_*.zip`) |
| 렌더러 | `gl_compatibility` → WebGL2로 그대로 동작 (`OpenGL ES 3.0 (WebGL 2.0)`) |
| 스레드 | 프로젝트에 `Thread`·`Mutex`·`WorkerThreadPool` 사용 **없음** → 스레드 없는 빌드로 내보낸다 |
| SharedArrayBuffer / COOP·COEP | **필요 없다** (`GODOT_THREADS_ENABLED = false`) — §3 |
| 파일 접근 | `res://`(읽기)·`user://`(JSON) 뿐. 절대 경로·`OS.execute` 없음 |
| 터치 | 이미 있는 오버레이가 브라우저에서 **환경 변수 없이** 켜진다 — §4 |
| 첫 화면 | 로컬 정적 서버로 띄워 제목 화면까지 확인함 |

내보내기는 **첫 시도에 성공**했다. 다만 그대로 두면 브라우저에서 못 쓸 결함이 세 가지 있었고, 모두 고쳤다(§2·§3).

## 2. 글꼴 — 이것부터 넣어야 한다 (가장 중요)

**증상.** 넣지 않으면 브라우저에서 **한글이 전부 네모(□)로 나온다.** 제목·메뉴·전투 HUD·예고 글자까지 전부.

**원인.** 프로젝트에 글꼴 파일이 하나도 없고 화면 전부가 엔진 기본 글꼴(`ThemeDB.fallback_font`)을 쓴다.
PC에서는 엔진이 **운영체제 글꼴**로 대신 그려 주기 때문에 문제가 드러나지 않는다. 브라우저에는 그 운영체제 글꼴이 없다.

**넣는 법.** OFL 같은 재배포 가능한 한글 글꼴을 `assets/fonts/ui.ttf` 로 둔다. 그 한 곳이면 된다.

```
# 예: 이 PC에 이미 있는 Noto Sans KR(OFL 1.1). 배포하려면 라이선스 파일도 같이 둔다.
cp "C:/Windows/Fonts/NotoSansKR-Regular.ttf" prophecy_godot/assets/fonts/ui.ttf
```

`Game._apply_ui_font()`가 시작할 때 **파일이 있을 때만** 깔고, 없으면 아무것도 하지 않는다(PC 동작은 그대로).

> 두 군데를 모두 바꿔야 한다. `ThemeDB.fallback_font`만 바꾸면 **화면이 하나도 안 바뀐다** —
> Label·Button·RichTextLabel은 기본 테마의 `default_font`를 먼저 읽기 때문이다(4.7에서 확인).
> 그래서 `ThemeDB.get_default_theme().default_font`와 `ThemeDB.fallback_font`를 함께 넣는다.

**글꼴에 없는 기호는 미리 바꿔 두었다.** 프로젝트가 쓰는 비-한글 기호 30종을 Noto Sans KR에 대조한 결과
`▸`·`▾`·`☠` 세 개만 없었다. 각각 `▶`·`▼`·`독`으로 바꿨다(11곳의 펼치기/접기 버튼 + 포자 지역 표시).
나머지 27종(`·` `—` `→` `×` `≥` `①` `★` `●` …)은 모두 들어 있다.

**저장소에는 글꼴 파일을 넣지 않았다.** 6.2 MB 짜리 제3자 파일이고, 어떤 글꼴을 쓸지·라이선스 파일을
어떻게 같이 둘지는 사람이 정할 일이다. `.gitignore`에 `prophecy_godot/assets/fonts/` 를 넣어 두었다.

## 3. 내보내기

```
python tools/export_web.py                 # 권장: 내보내기 + 빌드 표식(version.json) + 크기 표
```

속을 알고 싶으면 이것과 같다(**이 단계만** APPDATA를 격리하지 않는다 — 내보내기 템플릿이 진짜 AppData에 있어야 한다):

```
godot --headless --path prophecy_godot --export-release "Web" prophecy_godot_build/web/index.html
```

프리셋은 `export_presets.cfg`의 `[preset.1] name="Web"`에 새로 넣었다. 중요한 값:

- `variant/thread_support=false` — **스레드 없는 빌드.** COOP/COEP 헤더가 필요 없어진다.
- `html/experimental_virtual_keyboard=true` — 모바일에서 글자 입력 칸을 누를 때 자판이 뜬다.
- `exclude_filter="tests/*,tools/*,docs/*"` — 윈도우 프리셋과 같은 기준.
- `progressive_web_app/enabled=false` — 서비스 워커를 쓰지 않는다(캐시가 옛 빌드를 붙잡는 것을 피하려고. §6).

### 산출물 (글꼴 포함)

| 파일 | 그대로 | gzip |
| --- | ---: | ---: |
| `index.wasm` | 39,514,754 | 10,084,297 |
| `index.pck` | 5,447,012 | 5,113,610 |
| `index.js` | 279,815 | 68,400 |
| `index.html` | 5,471 | 2,263 |
| `index.audio.worklet.js` | 7,298 | 2,217 |
| `index.audio.position.worklet.js` | 2,973 | 1,193 |
| `index.png` (splash) | 21,443 | 19,270 |
| `index.icon.png` / `index.apple-touch-icon.png` | 4,796 / 11,023 | — |
| `version.json` (빌드 표식) | 425 | 256 |
| **합계** | **45,295,010 (43.2 MB)** | **15,307,335 (14.6 MB)** |

글꼴을 빼면 `index.pck`가 1,601,368(gzip 1,274,863)이라 합계가 약 41.4 MB(gzip 11.5 MB)다.
즉 **글꼴 값이 gzip 기준 약 3.8 MB**다. 줄이고 싶으면 글꼴 부분집합(subset)을 만들어 넣는 것이 가장 크게 준다.

### 서버에 필요한 것

| 항목 | 값 | 왜 |
| --- | --- | --- |
| `Content-Type: application/wasm` (`.wasm`) | **필수** | 없으면 `WebAssembly.instantiateStreaming`이 실패하고 느린 대체 경로로 떨어진다 |
| `Content-Encoding: gzip` 또는 `br` | 사실상 필수 | 43 MB → 14.6 MB. 폰 회선에서 차이가 크다 |
| COOP `same-origin` / COEP `require-corp` | **필요 없다** | 스레드 없는 빌드라 `SharedArrayBuffer`를 안 쓴다. 나중에 `thread_support=true`로 바꾸면 그때 필요하다 |
| HTTPS | 사실상 필요 | 폰에서 열 때. `file://`로는 아예 뜨지 않는다(fetch 차단) |
| `Cache-Control` | §6 참고 | `version.json`만 캐시하지 않는다 |

### 이 PC에서 확인하기 (외부 공개 안 함)

```
python tools/serve_web.py            # 127.0.0.1:8765 에만 연다
python tools/serve_web.py --host 0.0.0.0   # 같은 공유기의 폰으로 볼 때만. 끝나면 끈다
```

`.wasm` MIME을 올바로 주고 `Cache-Control: no-store`를 붙인다(시험 중 옛 빌드가 섞이지 않게).

## 4. 터치 조작 — 브라우저에서 그대로 켜진다

`PLayout.is_touch()`는 `DisplayServer.is_touchscreen_available()` **또는** `PROPHECY_TOUCH=1`이다.
브라우저에는 환경 변수가 없으므로 앞의 것만 쓰이는데, 내보낸 엔진 JS를 열어 보면 구현이 이렇다:

```
touchscreen_is_available(){return "ontouchstart" in window}
```

안드로이드 크롬에서는 참이다(실제로 확인: `ontouchstart=true`, `maxTouchPoints=5`).
**따라서 폰에서는 아무 설정 없이 터치 오버레이가 켜진다.** `PROPHECY_TOUCH=1`은 PC 시험용으로만 남는다.

### 화면 크기별 확인 (`tools/layout_shots.gd`, `PROPHECY_TOUCH=1`)

| 창 | canvas | 구분 | 넘침 검사 | HUD 검사 |
| --- | --- | --- | --- | --- |
| 2400×1080 (가로) | 1422×640 | wide | 통과 | 통과 |
| 1600×720 (가로) | 1422×640 | wide | 통과 | 통과 |
| 1080×1421 (세로) | 960×1263 | narrow | 통과 | 통과 |
| 648×1421 (세로, 실제 폰 비율 0.46) | 960×2105 | narrow | 통과 | 통과 |

**가려지는 것은 없다.** 네 크기 모두 `fails=0`이고, 전장은 가운데에 레터박스로 놓이며
가상 스틱·회피/Q/E·'빌드' 버튼은 전부 **전장 바깥 여백**에 그려진다. 예고 원(늑대 표시)도 전장 안에 보인다.

**다만 세로는 권하지 않는다.** 실제 폰 비율(0.46)에서 전장이 화면 높이의 **약 30%**밖에 되지 않고
위아래로 큰 빈 띠가 남는다. 조작 버튼도 전장에서 멀어진다. 가로에서는 전장이 화면을 가득 채우고
조작이 양쪽 여백에 놓여 훨씬 낫다. → 시험은 **가로로** 하고, 세로는 "깨지지 않는다" 정도로만 본다.

작은 흠: 세로에서 상단 목표 줄이 두 줄로 접힌다(`… 0.6` / `초`). 기능 문제는 아니다.

## 5. 저장 지속성

`user://`는 브라우저에서 **IndexedDB**에 들어간다. 실제로 확인한 값:

```
데이터베이스 이름: /userfs      (Emscripten IDBFS 마운트 이름)
객체 저장소:       FILE_DATA
DB_VERSION:        21
```

- **파일 하나하나가 아니라 `user://` 전체가 이 저장소에 담긴다.** 우리 파일은
  `prophecy_save_v1.json`(진행 중 회차), `prophecy_records_v1.json`(처치 기록),
  `audio_prefs.json`(음량), `shake_prefs.json`, 영구 성장 프로필이다.
- 쓰기는 파일을 닫을 때 엔진이 동기화를 부르고, IDBFS가 그 뒤 자동으로 IndexedDB에 밀어 넣는다.
  → **새로고침·탭 종료 뒤에도 남는다.**
- **출처(origin)마다 따로다.** `https://예시.com/게임/`과 `https://예시.com/다른곳/`은 같은 저장을 쓰지만,
  포트나 호스트가 다르면 **다른 저장**이다. 시험 주소를 바꾸면 진행이 사라진 것처럼 보인다 — 잃은 것이 아니라 다른 칸을 본 것이다.
- 지워지는 경우: 브라우저의 '사이트 데이터 삭제', 안드로이드 크롬의 저장공간 정리, 시크릿 창 종료.

**기존 저장 형식과 호환된다.** 형식은 `{"schema":"prophecy_save/1", "saved_at":…, "run":…}` 한 파일이고
플랫폼 의존 값이 없다. PC에서 만든 저장을 그대로 넣으면 웹에서 읽고, 반대도 된다.
(`PSave` 머리말대로 옛 **HTML 시제품** 저장과는 원래 호환하지 않는다 — 그건 웹 이식과 무관한 별개 결정이다.)

**저장 시점을 알아 둘 것.** 회차 저장은 **화면이 바뀔 때**(`go_base()` → `save_run()`) 일어나고 **전투 중에는 저장하지 않는다.**
폰에서 전투 도중 앱을 바꾸다 탭이 버려지면 그 전투는 처음부터다. 직전 거점 상태는 남는다.

### 아직 없는 것 — 저장 내보내기/가져오기

저장 파일을 글자로 주고받는 길이 **없다.** 시험자가 브라우저 데이터를 지우면 복구할 방법이 없다.
넣는다면 이렇게 하면 된다(작업 안 함):

- 넣을 곳: `PSettingsPanel`(설정 화면). `main.open_settings()`로 어디서나 열린다.
- 내보내기: `PSave.load()` → `JSON.stringify` → `DisplayServer.clipboard_set()`.
  (브라우저에서 파일 내려받기는 사용자 제스처가 필요해 성가시다. 클립보드가 간단하다.)
- 가져오기: `DisplayServer.clipboard_get()` → `JSON.parse_string` → `schema` 확인 → `PSave.save()` → 제목 화면 새로 그림.
- 검사: 같은 회차를 내보내고 지우고 가져왔을 때 `PSave.normalize()` 결과 문자열이 같은지.
  (`PSave._normalize`가 정수 필드를 되돌려 주므로 문자열 비교가 성립한다 — `save.gd` 머리말.)

## 6. 갱신 흐름 — 전투 중에 새로고침이 일어나지 않게

### 빌드 표식

`tools/export_web.py`가 산출물 옆에 `version.json`을 쓴다.

```json
{ "build": "9472291", "game_version": "godot-0.7.0", "exported_at": "…Z", "files": { … } }
```

### 캐시 규칙 (서버 설정)

Godot 웹 내보내기는 파일 이름에 해시를 붙이지 않는다(`index.wasm`은 늘 같은 이름). 그래서:

| 파일 | `Cache-Control` |
| --- | --- |
| `version.json` | `no-store` — 이것만은 늘 새로 받는다 |
| `index.html` | `no-cache` — 매번 서버에 확인(변경 없으면 304) |
| `index.wasm`, `index.pck`, `index.js` | `no-cache` |

`no-cache`는 '캐시하지 말라'가 아니라 '쓰기 전에 확인하라'다. 바뀌지 않았으면 304로 끝나 재다운로드가 없다.
**`max-age`를 길게 주면 안 된다** — 이름이 그대로라 옛 빌드가 계속 뜬다.
더 확실히 하려면 배포 폴더 자체에 버전을 넣는다: `/v/9472291/index.html`. 그러면 옛 주소는 옛 빌드 그대로 살아 있다.

서비스 워커(PWA)는 **끄는 쪽**을 골랐다(`progressive_web_app/enabled=false`). 켜면 캐시를 스스로 붙잡아
"왜 옛 판이 뜨지" 문제를 하나 더 만든다. 오프라인 실행이 필요해지면 그때 다시 본다.

### 전투 중 강제 새로고침 금지 — 설계

원칙: **새 판을 발견하는 것과 적용하는 것을 나눈다.** 발견은 아무 때나, 적용은 전투가 아닌 화면 전환에서만.

1. **발견.** 페이지가 `version.json`을 주기적으로(예: 5분, 그리고 창이 다시 보일 때) 가져와
   지금 켜 둔 `build`와 다르면 '새 판 있음' 상태만 켠다. **이 시점에 아무것도 하지 않는다.**
2. **안전 지점 알리기.** 게임이 "지금 새로고침해도 되는가"를 밖으로 알려 준다.
   전투 중(`view.running and not view.paused`)이면 거짓, 제목·거점·상점·보상 같은 화면이면 참이다.
   `main.show(...)`가 화면을 바꾸는 유일한 길이므로 거기 한 줄이면 된다:
   `JavaScriptBridge.eval("window.__safeToReload = %s" % ("true" if 안전 else "false"))`.
3. **적용.** 새 판이 있고 `__safeToReload`가 참일 때만 "새 판이 있습니다 — 지금 적용" 알림을 띄우고,
   **사람이 누를 때** `location.reload()`. 자동으로 새로고침하지 않는다.
4. **저장은 살아남는다.** 새로고침해도 §5의 IndexedDB는 그대로라 진행이 유지된다.
   다만 §5 끝의 이유로 **전투 중 진행은 저장되지 않으므로**, 3의 조건이 그 자체로 필요하다.

이 중 1·2·3은 아직 **구현하지 않았다**(빌드 표식만 만들어 두었다). 넣을 자리는 `main.gd`의 `show()` 한 곳과
`html/head_include`(내보내기 프리셋)에 넣는 짧은 스크립트다.

## 7. 안드로이드 실기 점검표

폰에서 **설치 없이 브라우저로만** 확인한다. 순서대로.

**준비.** PC에서 `python tools/serve_web.py --host 0.0.0.0` → 화면에 뜨는 `http://<PC주소>:8765/`를 폰 크롬에 친다.
(같은 공유기 안에서만 열린다. 끝나면 Ctrl+C로 끈다.) 외부 공개 배포는 하지 않는다.

| # | 볼 것 | 통과 기준 |
| --- | --- | --- |
| 1 | **첫 로딩** | 진행 막대가 끝까지 가고 제목 화면이 뜬다. 43 MB(gzip 14.6 MB)라 첫 로딩은 회선에 따라 십수 초 걸릴 수 있다 |
| 2 | **글자** | 제목·메뉴가 **한글로** 보인다. 네모(□)가 하나라도 보이면 §2 글꼴이 빠진 것이다 |
| 3 | **가로로 돌리기** | 폰을 가로로. 전장이 가운데, 조작 버튼이 양쪽 여백에 놓인다. **가로로 하는 것을 권장** |
| 4 | **터치 조작** | 왼쪽 아래를 끌면 이동(누른 자리가 중심), 오른쪽 아래 '회피'를 **누르고 있으면** 거리가 늘고, Q·E가 눌린다. 왼손 이동 + 오른손 회피 **동시**가 되는지 |
| 5 | **오른쪽 위 '빌드'** | 누르면 전투가 안전하게 멈추고 '내 빌드'가 열린다 |
| 6 | **세로로 돌리기** | 깨지지 않고 전부 보인다(전장은 작아진다). 돌린 뒤 조작 버튼이 손가락 닿는 곳에 다시 놓이는지 |
| 7 | **소리** | 화면을 한 번 누른 뒤 타격음이 난다. 브라우저는 사람이 누르기 전에는 소리를 내지 않는다(자동재생 정책) |
| 8 | **저장 유지 — 새로고침** | 거점까지 진행 → 새로고침 → 제목의 '계속하기'에 그 일차·레벨·금화가 그대로 |
| 9 | **저장 유지 — 탭 종료** | 탭을 닫고 다시 열어도 8과 같다 |
| 10 | **앱 전환** | 다른 앱에 갔다 돌아왔을 때 시간이 건너뛰지 않는다(한 프레임 0.1초·12단계로 잘라 둠). 전투 중이었다면 **그 전투 진행은 저장되지 않는다**는 점을 알고 볼 것 |
| 11 | **성능** | 늑대 25마리 전투에서 눈에 띄게 끊기지 않는지. 끊기면 전투 중 F3 대신 §8의 방법으로 기록 |
| 12 | **주소를 바꿔 열기** | 포트나 호스트가 다르면 저장이 **다르게** 보인다(§5). 진행이 사라졌다고 오해하지 말 것 |

## 8. 안 한 것 · 남은 것

- **배포하지 않았다.** 공개 호스팅에 올리지 않았고, 도메인·서비스 가입·자격 증명도 건드리지 않았다.
  기존 CosBridge 사이트도 그대로 두었다. 확인은 전부 `127.0.0.1`에서만 했다.
- **글꼴 파일을 저장소에 넣지 않았다** (§2). 넣어야 브라우저에서 한글이 나온다.
- **갱신 알림 구현 안 함** (§6의 1·2·3). 빌드 표식(`version.json`)만 만들어 두었다.
- **저장 내보내기/가져오기 없음** (§5 끝).
- **브라우저에서 실제 조작 확인은 못 했다.** 자동화 도구의 미리보기 창이 숨겨져 있으면
  `requestAnimationFrame`이 아예 돌지 않아 게임 루프가 멈춘다(첫 화면 그림까지는 확인). 그래서
  조작·저장 지속은 §7 점검표로 사람이 폰에서 봐야 한다. 화면 배치는 대신 `tools/layout_shots.gd`로 확인했다(§4).

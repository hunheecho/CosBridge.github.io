# 알려진 결함 추적

닫히지 않은 결함만 여기 남긴다. **성공한 재실행이 앞선 실패 기록을 지우지 않는다** — 발생한 실행은 그대로 두고, 아래 표에 한 줄씩 더한다.

## KD-1. 검사 통과 뒤 종료 시 접근 위반 (**열림 — 원인 미확정**)

> **상태 구분.** 2026-09-08 실행에서 23개 스위트가 모두 정상 종료했다(단언 1105/1105 · 정상 종료 23/23 · 종료 실패 0).
> 그것은 **그 실행에서 증상이 나오지 않았다**는 뜻이지 **원인을 찾아 고쳤다**는 뜻이 아니다.
> 재현이 불규칙하므로 이 항목은 계속 **열린 상태로 추적**한다. 아래 관측 기록에 줄을 계속 더한다.

**증상.** 검사는 전부 통과하고 `21/21 PASS`까지 출력한 **뒤**, 프로세스가 종료 코드 `3221225477`(0xC0000005, 접근 위반)로 죽는다.

**판정.** 검사 통과와 프로세스 정상 종료는 다른 사실이다. 공통 실행기는 이 실행을 **실패(fail)**로 남기고 `crash_after_pass` 표시를 붙인다. 통과 집계에 넣지 않는다.

순차 실행(`--jobs 1`)에서 또 났고 단독 재실행에서는 통과했다. 두 번 연속 실행에서 `theme_tests`는 매번, `world_tests`는 한 번만 났다 — **재현이 불규칙하다**는 기존 관측과 같다. **앞선 실패 기록은 지우지 않는다.**

**지금까지 아는 것.**
- 검사 출력과 요약 줄까지 정상이다. 검사 로직이 아니라 **프로세스 종료 처리**의 문제다.
- 처음에는 동시 실행에서만 보였지만, **순차 실행(`--jobs 1`)에서도 났다**(boss_pace_tests). 동시성은 빈도를 높이는 요인이지 원인이 아니다.
- 같은 스위트를 단독으로 다시 돌리면 통과한다(boss_pace_tests도 단독 재실행에서 통과). **재현이 불규칙하다.**
- 특정 스위트에 묶이지 않는다. 실제 장면을 띄우지 않는 `collision_tests`에서도 난다.
- 여러 스위트가 `ObjectDB instance was leaked at exit` 경고를 함께 낸다.

**아직 모르는 것.** 무엇이 원인인지. 지금까지 걸린 스위트가 `ui_flow_tests`·`content_tests`·`theme_tests`·`balance_tests`·`boss_pace_tests`·`input_tests`·`collision_tests`·`elites_tests`로 **특정 스위트에 묶이지 않는다.** 실제 장면을 띄우지 않는 스위트에서도 난다.
한 실행에 보통 **한 개**가 걸리고, 다음 실행에서는 다른 스위트가 걸린다 — 무작위에 가깝다. 표본이 늘어도 규칙이 보이지 않는다.

**당장의 대응.** 판정이 걸린 실행은 `--jobs 1`로 돌린다. 실행기는 이 경우를 **실패로 남기고** `crash_after_pass` 표시를 붙이며, 성공한 재실행이 앞선 실패 기록을 지우지 않는다.

**다음에 할 것.** 발생하면 그 실행 로그를 보존하고 위 표에 줄을 더한다. `--verbose`로 남은 객체 목록을 받아 두면 원인 후보를 좁힐 수 있다.

**증상.** 사람 플레이 보고: 7·8일차를 휴식으로 넘긴 뒤 **9일차 전투에서 플레이어가 움직이지 않아 죽었다.**

## KD-4. 검증 메뉴의 '봇 조작으로 보기'가 회차 전투까지 따라간다 (열림, 2026-09-08)

**증상 가설(재현은 아직 안 함).** 사람 입력이 전혀 먹지 않는 전투가 된다.

**경로.** 제목 화면 검증 메뉴의 체크박스 → `title.gd:131 main.start_fight(_bot_check.button_pressed)` → `main.gd:603 use_bot = bot`.
`use_bot`은 main의 지속 변수인데 `start_run`(main.gd:207)·`continue_run`(main.gd:258) 어디서도 되돌리지 않는다.
그 뒤 회차 전투는 `main.gd:594 _view_start(st, make_bot("balanced") if use_bot else null)`로 **봇이 조종**하고, `CombatView._process`는 `bot != null`이면 사람 입력(`router.poll`)을 읽지 않는다.

**왜 안 고쳤나.** 자동 진행 검증이 `use_bot = true; start_run(...)` 순서로 쓰고 있어(main.gd:1663 등) `start_run` 안에서 되돌리면 그 경로가 깨진다. 되돌릴 지점(제목 진입·회차 시작·이어하기 중 어디)은 사람 판단이 필요하다.

**증거는 자동으로 남는다.** 이 상태면 이동 진단이 `"봇": true`와 이유 `봇 조종(사람 입력 무시)`를 남긴다(부록).

## KD-5. 나무 가림(canopy) 반지름이 화면에서 1px로 그려진다 (열림, 2026-09-08 발견 — 담당 밖)

**증상.** 전장에 나무가 있어도 머리 위 가림 그림이 사실상 보이지 않는다.

**원인(코드 실측).**

| 위치 | 값 |
|---|---|
| `data/themes.json`·`data/config.json`의 나무 | `"canopy": 60 ~ 74`(반지름, 숫자) |
| `scripts/rules/combat_state.gd:143` | `"canopy": bool(ob.get("canopy", false))` → **숫자가 참/거짓으로 바뀐다** |
| `scripts/game/render.gd:436` | `var R: float = float(ob.get("canopy", 70.0))` → `float(true)` = **1.0** |

즉 모든 나무의 가림 반지름이 60~74가 아니라 1.0으로 그려진다.

**규칙에는 영향이 없다.** `canopy`를 읽는 곳은 `render.gd`의 `draw_canopies`뿐이고, 시야 판정(`los_blocked`)은 `ob.r`만 쓴다.
`combat_state.gd:142`의 주석 "canopy(머리 위 가림)는 시야 판정에 쓰인다"는 **사실과 다르다**(코드 전체 검색으로 확인).

**왜 안 고쳤나.** 랜덤 지형 작업의 담당은 배치 규칙이다. 이 값의 형(숫자 vs 참/거짓)을 바꾸면 `st.obstacles`의 내용이 달라져 화면·관측(`observe.gd`)·저장 비교에 영향이 갈 수 있어, 화면 담당이 판단할 몫으로 남긴다.
랜덤 지형이 만드는 나무도 같은 규칙을 따르므로(생성 쪽은 `r × 2.4`를 넣는다) **새 결함을 더하지는 않는다**.

**고치는 법(제안).** `combat_state.gd`의 두 곳(`_init`의 장애물 복사, `_set_obstacles`)에서 `bool(...)`을 `float(ob.get("canopy", 0.0))`로 바꾸고, `render.gd`가 0이면 기본값을 쓰게 한다. 주석도 함께 고친다.

## 부록. 이동 진단 계측(2026-09-08 추가)

`scripts/game/combat_view.gd`가 매 프레임 **입력 벡터 → 시뮬레이션에 넘긴 값 → 실제 이동량(px) → 거부 이유**를 기록한다. 규칙·난수·연출은 건드리지 않는다.

| 환경 변수 | 뜻 |
|---|---|
| `PROPHECY_MOVE_LOG=<초>` | 그 간격으로 `MOVE_LOG <JSON>`을 계속 출력한다(`0`이면 매 프레임). 없으면 아래 감시만 동작 |
| `PROPHECY_MOVE_STUCK=<초>` | 이동 의도가 있는데 못 움직인 시간이 이 값을 넘으면 보고한다(기본 3초, 이유가 '경기장 벽에 붙음'뿐이면 15초) |

출력 줄(환경 변수 없이도 자동으로 남는다):

- `MOVE_STUCK <JSON>` — 이동 입력이 있는데 실제 이동량이 0.5px 이하인 상태가 이어질 때(같은 전투에서 10초 간격)
- `MOVE_DEAD_INPUT <JSON>` — 전투가 도는데 이동 입력이 20초 넘게 계속 0일 때(장치→라우터 경로 단절·입력 잠금 의심)

JSON에 담기는 것: `입력`(mx·my·held) · `장치`(키보드 4방향 실제 눌림, 가상 스틱·유지, 터치 모드) · `단계`(steps·acc·대기 중인 누름) · `이동`(px) · `전투`(위치·반지름·이동배율·기본속도·경기장·arena·region·장애물 수·탈출예외 횟수·회피 중) · `최근사건`(일시정지 켬/끔·창 포커스 상실/복귀) · `이유`(막고 있는 것으로 보이는 항목들).

`PROPHECY_UI_SMOKE` 자동 진행의 `UI_SMOKE diagnostics`와 30초 심박 줄에도 같은 값이 들어간다(`combat.move`, `move=[이유]`).

# 알려진 결함 추적

닫히지 않은 결함만 여기 남긴다. **성공한 재실행이 앞선 실패 기록을 지우지 않는다** — 발생한 실행은 그대로 두고, 아래 표에 한 줄씩 더한다.

---

## KD-1. `ui_flow_tests` 종료 시 접근 위반 (열림)

**증상.** 검사는 전부 통과하고 `21/21 PASS`까지 출력한 **뒤**, 프로세스가 종료 코드 `3221225477`(0xC0000005, 접근 위반)로 죽는다.

**판정.** 검사 통과와 프로세스 정상 종료는 다른 사실이다. 공통 실행기는 이 실행을 **실패(fail)**로 남기고 `crash_after_pass` 표시를 붙인다. 통과 집계에 넣지 않는다.

**관측 기록**

| 실행 | 조건 | 검사 결과 | 프로세스 | 판정 |
|---|---|---|---|---|
| 2026-09-08 15:14 (`20260908_151439`) | `--group all --jobs 2` | 21/21 PASS | 종료 코드 3221225477 | 실패 |
| 2026-09-08 15:15 단독 3회 | `--suites ui_flow_tests` | 21/21 PASS | 종료 0 | 통과 |
| 2026-09-08 15:18 (`20260908_151847`) | `--group all --jobs 2` | 21/21 PASS | 종료 0 | 통과 |
| 2026-09-08 15:25 (`20260908_152529`) | `--group all --jobs 2` | 21/21 PASS | 종료 0 | 통과 |

**지금까지 아는 것.** 마지막 검사(무료 보급 사건) 출력과 요약 줄까지 정상이므로 검사 로직의 문제가 아니라 **종료 처리** 쪽으로 보인다. 이 스위트는 실제 장면을 띄우므로 노드 해제 순서나 엔진 정리 단계가 의심된다. 같은 실행에서 다른 스위트도 `ObjectDB instance was leaked at exit` 경고를 낸다.

**아직 모르는 것.** 재현 조건. 동시 실행(`--jobs 2`)에서만 1회 관측했지만 표본이 적어 동시성이 원인이라고 말할 수 없다.

**다음에 할 것.** 발생하면 그 실행 로그를 보존하고 위 표에 줄을 더한다. `--verbose`로 남은 객체 목록을 받아 두면 원인 후보를 좁힐 수 있다.

## 이 검수가 한 일과 하지 않은 일

- 기존 스위트가 **자격표를 자기 자신에게 물어보는 방식**(`PSupport.eligible("shock_bonus", "mine_blast")`)으로 단언하는 곳이 많다.
  그것은 자료 파일이 자기와 일치한다는 것만 증명한다. 그래서 되도록 **실제 피해 경로**(`fire_chain` · `explode_mine` ·
  `damage_player` · `st.step` · `PSortie.start` → `CombatState`)를 그대로 태워 결과 계수기로 확인했다.
- **통과 숫자는 재미·밸런스·가독성을 증명하지 않는다.** 아래 수치는 규칙이 의도대로 도는지에 대한 것이고,
  사람이 봐야 하는 항목은 §5에 따로 모았다.
- 화면(그림·연출)은 코드로만 확인했다. 실제 화면을 눈으로 보지 않았다.

## 2. 결함

심각도: **치명** = 확정된 규칙이 실제로 성립하지 않거나 사람이 곧바로 겪는다 / **중간** = 규칙은 서지만 의도와 다르게 동작한다 / **경미** = 표시·문구.

### D1. 지뢰 폭발이 감전 후속을 발동시킨다 — 자격표가 명시적으로 금지한 경로 (**중간**)

- **재현**: 번개 구체 + 룬 지뢰를 들고, 감전된 적 옆에서 지뢰를 터뜨린다.
  `tests/review_tests.gd` 1-8이 실제 `PWeapons.explode_mine`으로 재현한다.
- **기대**: 감전 후속 0회. `data/supports.json`의 `eligibility.shock_bonus.deny`에 **`mine_blast`가 들어 있다.**
  `docs/SUPPORT_WEAPONS.md` §3 표도 "지뢰/인형 폭발"을 발동 안 함으로 적었다.
- **실제**: 감전 후속이 **1회 터진다**(`shock_procs` +1).
- **근거**:
  - `scripts/rules/weapons.gd:717-718` — 감전 후속의 자격 판정이 `opt.cause`를 **넘기지 않는다**.
    ```gdscript
    if float(e.conduct) > 0.0 and String(sr.weapon_id) != "orb" and not bool(opt.get("no_conduct", false)) \
            and PSupport.eligible("shock_bonus", PSupport.cause_of(st, { "weapon": String(sr.get("weapon_id", "")) })):
    ```
    `{ "weapon": ... }`만 넘기므로 `cause_of`는 `st.attack_cause`를 읽는다. 지뢰 폭발은 `PWeapons.update` 안에서
    일어나 그 값이 `""`이고, 무기 `mine`은 주무기가 아니므로 **`support_direct`**로 해석된다 → 허용.
  - `scripts/rules/weapons.gd:617` — 지뢰는 `{"cause": "mine"}`을 **분명히 넘긴다**(`cause_of`가 `mine_blast`로 바꾼다).
    즉 자료도 호출부도 맞는데 **중간에서 버려진다.**
  - `scripts/rules/weapons.gd:31-35` `src()`가 `direct: true`를 기본으로 넣어, `on_hit`의 `direct` 관문도 통과한다.
  - 대조: `scripts/rules/supports_a.gd:70-82` `PSupportA._cause`는 `opt.cause`를 제대로 넘긴다.
    그래서 까마귀 표적·분신 복제는 지뢰 폭발로 발동하지 않는다(2-2에서 실측). **감전만 이 관문을 안 쓴다.**
- **왜 다른 경로는 안 터지나(중요)**: 역병 파열·인형 폭발·반사는 `src.direct = false`라서
  `weapons.gd:713`의 `direct` 관문에 걸려 막힌다. **자격표가 막은 것이 아니다.**
  `docs/SUPPORT_A.md` §4-4가 이미 같은 취지를 적어 두었는데, 그 문서는 "eligible을 부르지 않는다"고 했고
  지금은 부르기는 한다 — **경로 이름을 틀리게 넘긴다**는 것이 정확한 상태다.
- **사용자에게 보이는 증상**: 지뢰를 감전된 적 위에서 터뜨리면 추가 번개가 한 번 더 나간다.
  자료 표를 읽고 조합을 짠 사람에게는 예상 밖 피해이고, 감전 소모(`e.conduct = 0`)도 함께 일어나
  **의도한 주무기 연계가 지뢰에 잡아먹힌다.**

### D2. 인형이 본체에서 멀면 가로채기가 아예 작동하지 않는다 (**중간**)

- **재현**: `tests/review_tests.gd` `doll_case()` — 유인 명단에 오른 늑대를 **인형 바로 옆(10px)**에 세우고
  실제 근접 피격(`st.damage_player`)을 태운다. 인형만 플레이어에게서 60px / 200px로 옮겨 두 번 잰다.
- **기대**: 두 경우 모두 인형이 대신 맞는다. 인형의 값어치는 **적을 본체에게서 떼어 놓는 것**인데
  (`docs/SUPPORT_B.md` §4의 판단), 떼어 놓을수록 못 막으면 앞뒤가 맞지 않는다.
- **실제**:

  | 인형 위치 | 대신 받음 | 인형 체력 | 플레이어 |
  |---|---:|---:|---|
  | 플레이어에게서 60px | **1회** | 60 → 0 (부서짐) | 안 맞음 |
  | 플레이어에게서 200px | **0회** | 60 (그대로) | **그대로 맞음** |

- **근거**: `scripts/rules/supports_b.gd:555` — 가로채기는 `cause != "enemy_melee"`면 즉시 포기한다.
  그 `cause`를 정하는 `scripts/rules/supports_b.gd:353-370` `hit_cause()`가 **플레이어와 공격자의 거리**를 본다.
  ```gdscript
  if PGeom.dist(p.x, p.y, float(att.x), float(att.y)) <= float(att.get("r", 0.0)) + float(p.r) + reach:
      return "enemy_melee"
  return "enemy_projectile"
  ```
  기본 `reach` 95 + 반지름 28 = **123px**. 인형 기본 설치 거리는 `place` 120이므로,
  인형 옆에 선 적은 대개 이 경계 밖이다 → 근접 공격이 **투사체로 잘못 분류**되어 인형이 못 막는다.
- **사용자에게 보이는 증상**: 인형이 적을 잘 끌어당길수록(= 멀리 떼어 놓을수록) 인형은 멀쩡한데
  플레이어는 계속 맞는다. 실전 40초 측정에서도 **유인 21회에 대신 받은 것은 3회**뿐이었다.
- **참고**: `docs/FEEDBACK_TABLE.md` §7은 인형을 "**해결**"로 적었다. 유인·조준·피해 적용이 연결된 것은 맞고
  (`combat_state.gd:633-644` `target_of`), 인형이 실제로 맞고 체력이 줄고 부서지는 것도 확인했다.
  그러나 **"해결"은 인형이 가까울 때만 성립한다.**

### D3. 특수 정예 7종이 실제 회차에서 거의 등장하지 않는다 (**치명**)

- **재현**: `tools/review_probe.gd` ①. 시드 8개 × 10일을 **실제 카드 경로**로 끝까지 태운다
  (`PSortie.cards_for` → `PSortie.start` → `PFlow.encounter_opts` → `CombatState`). 실제로 시작한 전투 144회.
- **기대**: `data/themes.json`의 배치표는 특수 정예를 12자리에 넣어 두었고
  `tests/elites_tests.gd:818-862`가 그 배치를 고정한다. 카드도 "강적 출현"이라 예고한다.
- **실제**: 144전투에서 실제로 예약된 정예는 **`wolf_alpha` 51마리 · `elite_blademaster` 3마리**가 전부다.
  **`elite_archer` · `elite_chainbreaker` · `elite_fang` · `elite_miner` · `elite_plaguecaller` · `elite_standard`는 0회.**
  카드가 '강적 출현'이라 예고한 58전투 중 **실제로 정예가 있던 것은 39전투**(19회는 예고만 하고 없었다).
- **근거(경로가 세 단계로 끊긴다)**:
  1. `scripts/rules/sortie.gd:91-93` — 위험 조건(`risk`)은 **`obj != "clear"`, 즉 임무 카드에서만** 생긴다.
  2. `scripts/rules/sortie.gd:106` → `PRun.pick_formation(..., risk != null)` — 위험 편성은 `risk`가 있을 때만 뽑힌다.
     특수 정예 12자리 중 **9자리가 위험 편성**(`t1a_risk` … `t3c_risk`)이다.
  3. `scripts/rules/objectives.gd:279-283` — 그런데 임무 전투는 편성을 다시 만들면서
     **정예·보스·구조물을 전부 걸러 낸다**. 그 결과를 `scripts/rules/objectives.gd:421` `st.set_formation(f)`가
     원래 편성 위에 덮어쓴다(`CombatState._init`의 편성 생성보다 나중이다).
  → **위험 편성에 넣은 특수 정예는 넣은 그 순간 임무 코드가 지운다.** 1막 특수 정예 3자리는 전부 위험 편성이므로
  카드 경로만으로는 1막에서 특수 정예를 한 번도 만날 수 없다.
- **사용자에게 보이는 증상**: 사람이 관찰한 "**특수 정예는 출현이 적고 정체가 안 보인다**"의 실제 원인이 이것이다.
  배치표를 손봐도 이 경로가 막혀 있으면 바뀌지 않는다.
- **덧붙임**: `docs/ELITES.md`의 "조우 42%"는 `PSortie.elite_notice`(카드 예고)를 센 값이라
  **실제 조우가 아니다**. `sortie.gd:129-147`이 카드의 `objective`를 보지 않기 때문이다.
- **한계(확인 못 한 것)**: '더 깊이 탐험' 카드는 이 도구가 태우지 않았다. 그 경로는 `objective == "clear"`라
  정예가 살아남는다(코드로 확인, 실행 미확인). 즉 특수 정예를 볼 수 있는 통로가 아예 0은 아닐 수 있다.

## 4. 항목 8 — UI 버튼을 실제 입력 경로로

### 4-1. 먼저: 헤드리스의 한계를 실측으로 확인했다

- `DisplayServer = headless`, `window_get_size() = (0,0)`. **마우스 사건은 GUI에 전달되지 않는다** —
  버튼 한가운데 좌표로 `Viewport.push_input`을 넣어도 `pressed`가 **0회**였다(직접 확인).
- **키보드 사건은 전달된다** — Enter를 실제 `InputEventKey`로 넣으니 화면이 `base → combat`으로 바뀌었다.

그래서 세 층으로 나눠 확인했고, 단언 이름에 어느 층인지 적었다.

### 4-2. 결과 (`tests/review_input_tests.gd`, 16/18)

| 버튼 | 눌릴 수 있는 상태인가(보임·크기·가림·비활성) | 실제 동작 | 확인 방법 |

- **일반 탐험만 확인하지 못했다.** 내 자동 흐름이 출격의 **'귀환'까지 마치지 못해**(Enter 기본 경로가
  사건 화면에서 추가 전투로 갈라진다) 반복 카드가 열리지 않았다. 화면은 비활성 버튼에
  `"일반 탐험 · 출격을 한 번 마치면 열립니다"`라는 **정확한 이유**를 적고 있었다.
  즉 잠금 조건과 안내는 옳고, **눌리는지는 못 봤다.**
- **덮여서 못 누르는 버튼은 하나도 없었다**(전부 `덮임=없음`, `mouse_filter=0`, 크기 > 0).

### 4-3. 기존 UI 시험이 무엇을 확인하지 않는가(중요)

기존 스위트는 버튼을 **`pressed.emit()`으로 직접 쏜다**(`ui_flow_tests` 24회 · `meta_ui_tests` 8회 ·
`input_tests` 6회 · `hud_tests` 5회 · `prep_shop_tests` 0회). 실제 `InputEvent`를 UI에 넣는 곳은 **없다.**
그래서 다음은 어떤 시험도 잡지 못한다: 다른 Control에 가려짐 · `mouse_filter` 오설정 · 크기 0 ·
**`disabled`인데 눌린 것처럼 통과**(`pressed.emit()`은 `disabled`를 무시한다) · Enter 경로.
`docs/TOWN_UI.md:182`의 "**실제 버튼을 눌러** 확인한다"는 "버튼 노드를 찾아 그 신호를 쏜다"는 뜻이다.

특히 `계속` 버튼은 **어떤 시험도 눌러 보지 않는다** — `tests/hud_tests.gd:481-500`은 존재·글자 크기·개수만 본다.

## 8. 검수 절차에서 발견한 것 (결함은 아니지만 적어 둔다)

**갓 만든 작업 공간에서는 어떤 스위트도 바로 돌지 않는다.** `.godot/global_script_class_cache.cfg`가 없으면
`PSubset`·`PCatalog` 같은 `class_name`이 등록되지 않아 모든 도구가 `Parse Error`로 죽는다(위 표 #1·#2).
`godot --headless --path prophecy_godot --import`를 한 번 돌려야 한다.
`tools/run_suites.py`는 이 경우를 `script_error`로 잡아 주지만, **원인이 "가져오기 안 됨"이라는 것은 알려 주지 않는다.**

## 10. 사람이 직접 봐야 하는 것 (통과 숫자가 답하지 않는다)

1. 지뢰 폭발이 감전을 터뜨리는 것(D1)을 **막을지 허용할지**. 자료 표는 막으라고 적혀 있으나, 재미로는 허용이 나을 수도 있다.
2. 인형 가로채기의 판정을 **인형 위치 기준으로 바꿀지**(D2). 바꾸면 인형이 강해진다 — `docs/SUPPORT_B.md` §4의
   "훅이 붙으면 두 배로 세진다"는 우려가 그대로 적용된다.
3. 쌍검 1.5배를 **개조 포함으로 맞출지**(D4). 검의 `잔류 검흔`을 낮추지 말라는 조건이 있으므로 쌍검 개조 쪽을 손봐야 한다.
4. 특수 정예를 임무 전투에 **되붙일지**, 아니면 일반 편성으로 옮길지(D3). 임무 전투의 목표 판정과 충돌할 수 있다.
5. 전투 말미의 "다음 적을 기다리는 시간"이 여전히 전투의 절반 이상인 것(§3)이 실제로 지루한지.
6. 특수 정예·새 보조(까마귀·분신·인형 몸체·잔바람·반격탄)가 **화면에 안 그려지는 것** — `render.gd`에 해당 분기가 없다.

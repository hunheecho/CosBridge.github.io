# 특수 정예 7종 (2026-09-08, 시험값)

사람 플레이 평가("일반 전투가 전반적으로 너무 쉽다 / 5일차에는 가만히 있어도 적이 접근하다 죽었다 /
한 대 맞았을 때 피해량은 나쁘지 않은데 몬스터 공격이 실제로 적중하는 일이 적다")에 대한 대응 중,
**체력만 높인 적이 아니라 고유 연계를 가진 정예**를 만든 결과다.

- 정의(행동 수치): `data/enemies.json` → `enemies.elite_*`
- 규칙(행동): `scripts/rules/enemies_new.gd` → `update_elite_*`
- 배치표(어디에 무엇이 나오는가): `data/elites.json` → 실제 편성은 `data/themes.json`, 규칙은 `PRun.elite_types_for` (§10)
- 검사: `tests/elites_tests.gd`(규칙 + 배치 회귀)
- 측정: `tests/elites_bot_measure.gd`(1막 단독) / `tests/elite_placement_measure.gd`(2·3막 실제 편성, §12)
- 방패병 확정 변경은 `docs/SHIELDBEARER.md`

> 이름은 가칭이고 시간·체력·피해는 전부 **시험값**이다. 사용자가 확정한 값은 방패병 85%뿐이다.
> 체력 표(`data/pacing.json enemy_hp.elite_by_act`)에는 7종 1·2·3막 값이 들어 있다.
> **배치 작업(2026-09-08)에서도 체력 수치는 바꾸지 않았다** — 바꾼 것은 어디에 어떤 정예를 넣는가와 경험치 30 통일뿐이다.

## 0. 공통 규칙

| 규칙 | 구현 |
|---|---|
| 예고 → 방향(위치) 확정 → 실행 → 빈틈 | 모든 연계가 `*_aim` → `*_lock` → 실행 → `recover`/`stagger` |
| 확정 뒤에는 추적하지 않는다 | 확정 상태에서 `e.dir` / `e.leap_at` / `e.emerge_at` / `e.slam_at`을 고정하고 그 뒤 갱신하지 않는다. 검사 항목으로 고정 |
| 무조건 명중·회피 불가·강제 피해 할당 없음 | 모든 피해가 `st.damage_player()`를 지난다(회피 무적·피격 보호가 그대로 작동). 사슬의 끌기도 **피해가 실제로 들어갔을 때만** 발생한다 |
| 위험 공격 동시 제한 | 기존 `CombatState.may_attack` 경로를 그대로 쓴다. **보완**으로 "정예 동시 연계 1"을 더했다(`PEnemiesNew.elite_may_start`) |
| 예고 도형 공유 | `PEnemiesNew.elite_threats()`가 봇(`PBot.threats`)과 화면이 같은 기하를 읽게 한다 |
| 빈틈 보너스 | `recover`/`stagger` 중에는 기존 규칙대로 피해 ×1.5 |

### 정예 동시 연계 1 (보완한 부분)

일반 전투는 `overlap_limit`이 0이라 `may_attack`이 **항상 참**이다(동시 제한이 사실상 꺼져 있다 — 늑대 돌진만
`grant_dash_slots`로 따로 제한된다). 여기에 정예 연계까지 겹치면 탈출이 불가능해질 수 있으므로,
정예끼리만 "같은 순간에 연계 중인 정예는 하나"라는 조건을 추가했다.

- 일반 적의 압박은 **전혀 줄이지 않는다**(모두가 한 마리씩 차례를 기다리는 상태가 되지 않는다).
- `elite_busy()`는 정예 7종만 본다. 보스·일반 적은 세지 않는다.
- 편성 단계의 상한(`data/elites.json placement.max_elites_alive`)과는 별개의 두 번째 안전장치다.

## 1. A. 정예 궁수 (`elite_archer`) — 추격 사수

| 단계 | 상태 | 시간(초) | 내용 |
|---|---|---:|---|
| 조준 | `aim` | 0.58 | 플레이어 추적 |
| 방향 고정 | `shot_lock` | 0.12 | **여기서 방향 확정** → 발사(피해 12) |
| 재조준 ×2 | `aim` → `shot_lock` | 0.38 + 0.12 | 발사 간격 **0.50초** |
| 부채꼴 예고 | `fan_aim` | 0.60 | 추적 |
| 부채꼴 확정 | `fan_lock` | 0.15 | 중앙 화살 = 예고 방향, ±22도로 3발(각 10) |
| 빈틈 | `recover` | **1.40** | 옆으로 움직이며 재장전 |

- 첫 발까지 **0.70초**(0.58 + 0.12), 이후 0.50초 간격 3발, 부채꼴 예고 0.75초. 한 연계 = 화살 6발 / 발사 판정 4회.
- 거리 유지 190~340. 장애물에 **1초 이상** 시야가 막히면 `reposition`(1.2초 측면 이동)으로 사격 위치를 바꾼다.

| 순차 폭발 | (같은 상태) | **0.45 간격** | 반지름 70 · 피해 16, 폭발 자리에 구름 |

- 포자는 플레이어 주위 120 거리에 55도 간격으로 흩어 놓되, **놓고 난 뒤에도 16방향 중 6방향 이상이

- 재사용 시계(`cast_t`)는 상태와 무관하게 흐른다. 붙어서 분출만 반복해 주 연계를 못 보는 일이 없도록 한 것이다.

## 5. E. 사슬 집행자 (`elite_chainbreaker`)

| 단계 | 상태 | 시간(초) | 내용 |
|---|---|---:|---|
| 사슬 예고 | `chain_aim` | 0.60 | 직선(길이 330 · 폭 26). **바위에 막히면 예고 길이도 짧아진다** |
| 확정 | `chain_lock` | 0.15 | 방향 고정 |
| 발사 | `chain_fly` | 속도 620 | 피해 10 |
| 끌기 | `pull` | 0.35 | 70까지 끌어당김. **벽·바위는 그대로 막는다** |
| 강타 예고 | `slam_aim` | **0.55** | 강타 위치는 **예고 시작 때 이미 고정** |
| 강타 확정 | `slam_lock` | 0.15 | 반지름 92 · 피해 26 |
| 빈틈 | `recover` | 1.20 | |
| 빗나감 | `retract` | **1.40** | 회수 빈틈 |
| 근접 대응 | `sweep_aim` | 0.45 | 72 이내 · 160도 횡베기 · 피해 18 · 빈틈 0.9 |

- **회피 기회 보장**: 끌기가 끝난 뒤 강타까지 **0.70초**(0.55 + 0.15) 동안 원의 위치가 **움직이지 않는다.**
  플레이어 이동 220 × 0.70 = 154 > 강타 반지름 92 + 플레이어 반지름이므로 회피를 쓰지 않고 걸어서도 벗어난다.
  검사에서 "걸어 나가면 강타를 맞지 않는다"를 수치로 확인한다.
- 여기만 "예고 중 추적"의 예외다. 끌기로 자리를 강제한 직후에 다시 추적하면 회피할 방법이 사라지기 때문이며,
  코드 주석에도 그 이유를 남겼다.
- 사슬이 회피·피격 보호로 막히면 끌기가 일어나지 않고 그대로 회수 빈틈으로 간다.

## 6. F. 군단 기수 (`elite_standard`)

| 단계 | 상태 | 시간(초) | 내용 |
|---|---|---:|---|
| 깃발 설치 예고 | `plant_aim` | 0.80 | |
| 설치 | — | — | **파괴 가능한 구조물** `elite_banner`(체력 90 · 수명 20초) |
| 지휘(깃발이 살아 있는 동안) | — | — | 범위 220 안 아군: 이동 ×1.25 · 직접 피해 ×0.85 |
| 돌격 명령 | — | 6초마다 2마리 | 2.2초 동안 이동 ×1.5, **총 6회 예산** |
| 재배치 | `plant_aim` | — | 깃발이 부서지면 다시 세운다. **깃발 예산 2개** |
| 근접 | `slash_aim` | 0.50 | 60 · 110도 · 피해 16 · 빈틈 1.2 |

- **적을 새로 소환하지 않는다.** 이미 싸우고 있는 적의 이동만 바꾼다.
  깃발(구조물)은 경험치·금화를 주지 않으므로(`xp_for`가 구조물에 0) 반복 파괴가 수급 경로가 되지 않는다.
- 지휘받은 적도 위험 공격 동시 제한(`may_attack`)을 그대로 따른다. 명령은 이동만 바꾼다.
- **깃발과 기수 중 무엇을 먼저 칠지 선택 가능**: 깃발을 부수면 집결·방어 지원·명령이 즉시 끊긴다(0.25초 안에 자동 해제).
  기수를 먼저 잡으면 명령은 멈추지만 남은 깃발의 방어 지원은 수명이 끝날 때까지 유지된다.
- 표시: 깃발 범위 고리와 지휘받는 적 표시를 0.6초마다 내보낸다(전용 그림은 `render.gd` 담당 — 아래 §9).

| balanced | 14.7 | 1회 | 2회 | 2/6 | **없음(설계상 소환하지 않는다)** |
| aggressive | 10.9 | 1회 | 2회 | 2/6 | **없음** |

### 대조군 (강화된 1막 일반 적, 같은 조건)

| 적 | 봇 | 체력 | 처치 시간(초) | 실행한 공격 수 | 받은 피해 |
|---|---|---:|---:|---:|---:|
| 늑대 | balanced | 48 | 2.1 | **1** | 0 |
| 방패병 | balanced | 88 | 6.1 | 3 | 0 |

### 읽는 법

- **"살아서 실행한 공격 수"가 핵심 지표다.** 강화된 일반 늑대는 죽기 전에 1회밖에 못 때리지만,
  정예는 4~20회를 실행한다. 체력이 아니라 "행동을 끝까지 보여 주는가"로 만든 차이다.
- **"고유 연계 2회"** 목표: 사슬 집행자/aggressive 1회를 빼면 모든 조합에서 2회 이상 나온다.
  사슬 집행자는 그 대신 7회의 공격(사슬 2 + 횡베기 5)을 실행하므로 대응 기회 자체는 충분하다.
  더 확실히 하려면 체력을 220 → 260으로 올리는 것이 후보다(미적용).
- "받은 피해 0"인 줄이 있는 것은 봇이 확정 예고를 잘 피하기 때문이며, **회피가 통한다는 증거**이지
  위협이 없다는 뜻이 아니다. 정예 검사/aggressive의 78은 방패 자세로 붙었을 때의 압박을 보여 준다.
- 처치 시간 8~19초는 사용자가 제시한 정예 범위(8~15초)의 위·아래를 조금 넘나든다. 1막 기준이며
  2·3막은 §10의 체력 표를 넣은 뒤 다시 재야 한다.

## 10. 실제 출격 편성 배치 (2026-09-08 완료)

정예는 이제 **게임에서 실제로 만난다.** 붙는 자리는 `data/themes.json`의 편성 템플릿이고,
읽는 코드는 `PRun.elite_types_for` → `PRun.template_waves`다.

```gdscript
# scripts/rules/run.gd
static func elite_types_for(tpl, place_key, deep) -> Array   # 템플릿이 정한 정예 종류 목록(길이 = tpl.elites)
```

| 템플릿 필드 | 뜻 |
|---|---|
| `elite_type` | 기본 정예 1종 |
| `elite_type_p2` | **비용 2칸(큰 보상) 장소**와 **더 깊이 탐험**에서 쓰는 더 강한 정예. 없으면 `elite_type` |
| `elite_types` | 정예 2마리 이상일 때의 조합. 조합은 이미 최대 위험이라 장소로 더 올리지 않는다 |

값이 없으면 기존 늑대 우두머리라 회귀가 없다. **어느 경우에도 `elites`(마리 수)는 바꾸지 않았다.**

### 배치 규칙

1. **1막은 위험 편성에만.** 첫 만남이 사고가 되지 않게 한다(1막 일반 편성 9개는 정예 0).
2. **평범한 출격에는 드물게.** 일반 편성 27개 중 정예를 쓰는 것은 3개(11%)다.
3. **심층·큰 보상 장소는 강한 정예 1 + 호위.** 비용 2칸 장소와 더 깊이 탐험에서는 종류가 `elite_type_p2`로
   바뀌고, 마리 수는 막별 상한(`data/elites.json placement.max_elites_per_fight` = 1/1/2)을 넘지 않는다.
   더 깊이 탐험은 **호위만** 묶음마다 +1 한다(예전에는 정예도 +1 되어 2마리가 됐다).
4. **3막 고위험은 정예 2마리 조합.** 서로 다른 두 종류를 쓰고 `avoid_with`를 어기지 않는다.
5. `acts` · `avoid_with` · `requires_allies`(군단 기수 호위 4 이상)를 전부 지킨다.
6. **총 등장 수·경험치 예산 불변.** 정예 종류만 바뀌므로 배치 전(늑대 우두머리)과 수·예산이 같다.

### 어디에 무엇이 들어갔는가

  먼저 확인한 뒤 전체를 다시 돌렸다.
- 군단 기수는 **처치가 빠르다**(2막 14.3초 / 3막 11.4초). 지휘가 본체이므로 깃발이 먼저 부서지면
  존재감이 사라진다 — 체력이 아니라 깃발 수명·명령 예산의 문제이며 사람 판단 항목으로 남긴다.
- 사슬 집행자는 가장 오래 버티고(3막 45.9~58.6초) 연계를 가장 많이 보여 준다(14~16회).
  3막 성채가 다른 곳보다 길게 느껴질 수 있다 — 조정 후보로 적어 둔다.

## 역할 읽기 — 무엇을 들었는지로 역할이 보여야 한다 (2026-09-09)

사용자 지시: 특수 정예는 일반 경로에서도 **존재를 알 수 있어야** 한다.
**체력을 올려 강적처럼 보이게 하지 않는다.** 대신 실루엣에서 역할이 읽히게 한다.

외형을 그리는 것은 `scripts/game/render.gd` 담당이므로, 규칙 쪽은 **자료만** 준비했다.
`data/elites.json`의 각 정예 항목 안 `read` 블록이며 `PCatalog.elite_def(id).read`로 읽는다
(새 접근자를 만들 필요가 없도록 일부러 `elites` 안에 두었다).

| 항목 | 뜻 |
|---|---|
| `held` | 손에 든 것 — 실루엣에서 가장 먼저 읽혀야 하는 것 |
| `silhouette` | 몸 형태의 특징 |
| `tell` | 예고 때 커지거나 빛나야 하는 부위(무엇이 올지 알려 주는 곳) |
| `role_text` | 한 줄 역할(출격 카드·도감 문구와 같은 말) |
| `distance` | 플레이어가 취해야 하는 거리 |

| 정예 | 손에 든 것 | 예고에서 커져야 하는 곳 | 취해야 할 거리 |
|---|---|---|---|
| 정예 궁수 | 긴 활 + 화살통 | 시위를 당긴 팔(부채꼴 3발 전에는 화살 세 대) | 붙어야 한다 |
| 정예 검사 | 큰 검 + **방패** | 정면을 덮는 방패 | 측·후면으로 돈다 |
| 피의 송곳니 | 무기 없음(송곳니) | 접히는 뒷다리 + 착지 원 | 옆으로 돌 공간을 뺏는다 |
| 역병 조율사 | **포자 주머니 3개** | 주머니가 하나씩 사라진다 | 원 사이로 빠진다 |
| 사슬 집행자 | **사슬 갈고리** + 망치 | 곧게 펴지는 사슬 | 바위를 사이에 둔다 |
| 군단 기수 | **깃발 장대** + 짧은 검 | 깃발을 꽂는 동작 | 깃발을 먼저 부순다 |
| 균열 채굴자 | **곡괭이** | 흙 자국 + 고정된 출현 원 | 출현 원 밖으로 걷는다 |

`tests/elites_tests.gd`가 7종 모두 다섯 항목이 비어 있지 않은지 고정한다.

## 조우 빈도 — 편성표가 아니라 **실제 회차의 카드**로 셌다 (2026-09-09)

"편성표에 이름이 있다"는 것만으로 완료로 치지 않는다.
`PSortie.cards_for`(실제 카드 생성기)를 **시드 8개 × 1~9일**로 돌리고
각 카드의 강적 예고(`PSortie.elite_notice`)를 셌다. 경로는 시드마다 다르게 잡았다.

| 정예 | 예고된 카드 수 |
|---|---:|
| 정예 궁수 | 6 |
| 정예 검사 | 23 |
| 피의 송곳니 | 5 |
| 역병 조율사 | 16 |
| 사슬 집행자 | 7 |
| 군단 기수 | 2 |
| 균열 채굴자 | 15 |

| 막 | 전체 카드 | 강적 예고 | 비율 |
|---|---:|---:|---:|
| 1막 | 48장 | 7장 | 15% |
| 2막 | 64장 | 37장 | 58% |
| 3막 | 32장 | 16장 | 50% |
| 합계 | 144장 | 60장 | **42%** |

- 7종이 **모두** 실제 카드에 나온다 — 이름만 표에 있는 종류는 없다(검사로 고정).
- 1막 15%로 존재는 알 수 있고 첫 만남이 사고가 되지 않는다. 2·3막은 절반 안팎으로 분명히 나온다.
- 전체 42%라 **모든 일반 전투에 의무로 들어가지는 않는다.**
- **처음 재 봤을 때 정예 궁수가 0이었다.** 기본 경로만 돌렸기 때문이며, 경로를 시드마다 바꾸자 6이 되었다 —
  즉 정예 궁수는 특정 경로에서만 만난다. 배치는 바꾸지 않았고 사실만 남긴다.
- 편차가 크다(군단 기수 2 · 피의 송곳니 5 vs 정예 검사 23). `elite_type_p2`가 대부분 정예 검사이기 때문이다.
  **배치는 이번에 바꾸지 않았다** — 사용자 결정이 필요한 부분이다.

## 3막 정예 늑대 처치 시간 — **체력은 이번에 바꾸지 않았다** (2026-09-09)

사용자 관찰("3막 정예 늑대가 오래 걸린다")을 지금 상태 그대로 재서 보존한다.
사용자 지시대로 **체력을 손대지 않았다**(새 증강 비교 뒤에 사용자가 결정한다).

# 주무기·보조무기 분리 구조

2026-09-08. 사용자가 확정한 것은 **슬롯 구조·무기 명단·핵심 역할** 세 가지다.
아래의 피해·범위·발동 간격 등 **수치는 전부 시험값**이며 사람이 승인한 밸런스가 아니다.

## 1. 슬롯과 성장 (확정)

| 자리 | 개수 | 레벨 상한 | 개조 상한 | 개조 자격 |
|---|---:|---:|---:|---|
| 주무기 | 1 | Lv5 | 2 | Lv2에 첫 번째, Lv4에 두 번째 |
| 공통 보조 | 2 | Lv3 | 1 | 그 보조의 Lv2 |

- 개조 자격이 열려도 **자동 지급하지 않는다**. 성장 선택을 따로 써야 한다.
- 보조마다 개조 후보 3개 중 **하나**를 고른다.
- 주무기와 보조는 **개별적으로** 오른다. 한 선택으로 다른 무기까지 오르지 않는다.
- 장비(무기·갑옷·방패) 슬롯은 이 구조와 **별개**다.
- Q/E 주력 딜링 트리는 이번 범위에 넣지 않았다.

정본은 `data/supports.json`의 `slots`이고, 코드는 `PGrowth.level_cap` / `mod_cap` / `mod_quota_of` / `can_take_weapon`만 본다.
`data/weapons.json`은 `tools/port_export_data.js`가 만드는 생성 파일이라 손대지 않는다 — 손으로 정한 값은 전부 `data/supports.json`에 있고 `PCatalog.weapons()`가 겹쳐 읽는다.

### 기회비용

새 보조 획득 · 보조 레벨업 · 보조 개조 · 주무기 성장이 **같은 3택 풀**에서 경쟁한다.
선택 유형(`kind`)은 예전 이름을 그대로 쓰고(`weapon_new` / `weapon_level` / `weapon_mod`) 후보에 `role`(main·support)을 붙였다.
저장·재생·통계의 선택 기록 형식을 바꾸지 않으려는 것이다.

### 보조 레벨업이 올리는 것

모든 보조를 피해 증가 하나로 처리하지 않는다. `data/supports.json`의 `levelScale`이 보조마다 무엇이 오르는지 정한다.

|---|---|
| 회전 칼날 | 피해 ×1→1.8 · 반지름 ×1→1.16 |
| 번개 구체 | 피해 ×1→1.8 · 연쇄 횟수 +1 |
| 서리 수정 | 피해 ×1→1.8 · 냉기 지속 +1.0초 |
| 불씨 정령 | 피해 ×1→1.8 · 장판 지속 +1.0초 |
| 룬 지뢰 | 피해 ×1→1.8 · 설치 상한 +2 |
| 추격 까마귀 | 피해 ×1→1.8 · 표적 유지 +1.0초 |
| 수호 방울 | 방울 수 +1 · 충전 시간 ×0.7 |

## 2. 무기 명단 (확정)

**주무기 5종**: 검 · 관통창 · 쌍검 · 전투망치 · 추적궁
**보조 12종**: ① 회전 칼날 ② 번개 구체 ③ 서리 수정 ④ 불씨 정령 ⑤ 룬 지뢰 ⑥ 추격 까마귀 ⑦ 수호 방울 ⑧ 잔영 분신 ⑨ 바람 정령 ⑩ 역병 나비 ⑪ 가시 갑각 ⑫ 도깨비 인형

이번 명단에서 뺀 것: 사슬 · 수정 포탑 · 파쇄 정령 · 수확 낫 · 전투 깃발.
(`tests/slots_tests.gd`가 이 다섯이 들어오지 않았는지 검사한다.)

## 3. 효과별 발동 자격표 (한 곳)

`data/supports.json`의 `eligibility`가 정본이고 코드는 `PSupport.eligible(효과, 경로)`만 본다.
경로 이름은 피해 계측(`st.attack_cause`)과 같은 어휘를 쓴다.

| 효과 | 발동함 | 발동 안 함 | 이유 |
|---|---|---|---|
| 감전 후속 피해 | 주무기 직접·주무기 개조 추가·보조 직접·**분신 모방** | 장판 틱·독·출혈·반사·**감전 후속 자신**·지뢰/인형 폭발·역병 파열 | 분신은 자격이 있고(지시 4절 2번), 감전이 감전을 부르는 순환을 끊는다 |
| 분신 모방 | 주무기 **기본** 공격만 | 주무기 개조 추가 타격·다른 보조·**분신 자신** | 개조와 보조를 통째로 복제하지 않는다. 분신이 분신을 만들지 않는다 |
| 가시 반격 | 적의 **근접** 타격 | 적 투사체·적 장판·**반사 자신** | 반사가 반사를 부르는 순환 금지 |
| 까마귀 표적 지정 | 주무기 직접·주무기 개조 추가 | 보조 직접·장판·독·반사 | '주무기로 직접 맞힌 대상'이 지정 조건 |
| 독 전염 | 죽음이 방아쇠라 출처를 가리지 않음 | — (대신 **세대 상한 2**, 지속 시간을 최대치로 되돌리지 않음) | 전염이 무한 증식하지 않게 |

**시간이 아니라 경로로 막는다.** 정상 연타를 막는 광범위한 공통 쿨다운은 쓰지 않는다.
표에 없는 효과는 막지 않는다 — 모르는 효과를 조용히 꺼 버리면 원인을 못 찾기 때문이다.

## 4. 제압 저항

`data/supports.json`의 `resist`. 전부 시험값.

| | 일반 | 정예 | 보스 |
|---|---:|---:|---:|
| 밀어내기 | 1.0 | 0.35 | **0** |
| 경직 | 1.0 | 0.4 | **0** |
| 둔화 | 1.0 | 0.6 | 0.35 |
| 유인 | 1.0 | 0.5 | **0** |

- 둔화를 몇 개 겹쳐도 이동 속도는 `slowFloor` 0.35 아래로 내려가지 않는다.
- 보스는 밀어내기·경직·유인이 **0**이라 강제 위치 이동이나 영구 제압이 원리적으로 불가능하다.
- 검사: `tests/support_tests.gd` 8절(둔화 20번 중첩·보스 밀어내기 0·보스 유인 불가).

## 5. 저장 호환

- 새 회차의 `growth.structure`는 `"v2"`다. **이 표시가 없는 저장은 `"v1"`(옛 구조)로 읽는다.**
- 옛 회차는 옛 상한(자동기술 3개·전부 Lv5·개조 2개)으로 **끝까지 그대로 마칠 수 있다.**
- 옛 저장의 주무기 계열이 여러 개여도 **지우거나 하나를 골라 주지 않는다.** 더 늘지 않을 뿐이다.
- 상한보다 높은 레벨이 저장에 남아 있으면 **계산에서만** 잘라 쓴다(저장값을 깎지 않는다).
- 카탈로그에서 사라진 자동기술이 저장에 있으면 후보로 올리지 않고 그대로 둔다.
- 시작 선택은 주무기만이다. 옛 구조에서 시작 자동기술로 해금해 둔 회전 칼날·번개 구체는 시작 목록에서 빠지지만
  **프로필 해금 자료는 지우지 않고**, 회차 중 보조 후보로 계속 나온다.

검사: `tests/slots_tests.gd` 7~9절.

- 화면 표시: 추격 까마귀 몸체·잔영 분신·도깨비 인형 몸체·잔바람 장판이 아직 그려지지 않는다.
- 새 구조에서의 성장·몬스터 체력 비교.

## 8. 실험실(검증 패널)의 고정 빌드는 옛 구조다

`data/balance.json`의 `lab.BUILDS`는 보스 속도 비교용 **고정 빌드**다(예: `blades Lv1 + launch + dual`).
이 사전에는 `structure` 표시가 없어 **v1(옛 구조)로 읽힌다.** 그래서 새 구조의 상한을 어기는 것이 아니라
"옛 구조 저장과 같은 취급"이며, 실제 플레이로 얻은 빌드가 아니다.

실제로 플레이해서 얻은 빌드는 새 구조를 지킨다 — 10일 완주 자동 진행의 마지막 빌드는
`검 Lv4 + 개조 2 / 불씨 정령 Lv3 + 개조 1 / 회전 칼날 Lv3 + 개조 1`이었다.

고정 빌드를 새 구조로 바꾸면 기존 보스 속도 비교가 깨지므로 **그대로 둔다.** 대신 여기 적어 둔다 —
실험실 화면의 빌드를 새 구조의 예시로 읽지 않는다.

`tests/slots_tests.gd` 12절이 **실제 회차를 끝까지 굴려서** 상점 교체·대장간 개조 변경·임무 보상 같은
다른 경로가 상한을 넘기지 않는지 확인한다.

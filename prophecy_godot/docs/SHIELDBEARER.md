# 방패병 정면 방어 — 확정 변경과 판정 점검 (2026-09-08)

사람 플레이 평가("일반 전투가 전반적으로 너무 쉽다 / 몬스터 공격이 실제로 적중하는 일이 적다")에 대한 대응 중,
**방패병 쪽 확정 변경**과 그 판정을 실제로 측정해 적는다. 무조건 명중·회피 불가 공격·강제 피해 할당량은 쓰지 않았다.

- 정의: `data/enemies.json` → `enemies.shieldbearer`
- 규칙: `scripts/rules/enemies_new.gd` → `update_shieldbearer` · `guard_closed` · `shield_mult` · `note_block`
- 검사: `tests/elites_tests.gd` (작업 1 구역) · `tests/balance_tests.gd`(확정값 고정 1줄)

### 실제 피해 예시 (검사에서 측정한 값, `tests/elites_tests.gd`)

유효 직접 피해 100을 방패병 몸 기준 각 방향에서 넣었을 때 실제로 깎인 체력:

| 공격이 온 방향 | 실제 피해 | 비고 |
|---|---:|---|
| 정면 0도 | **15.0** | 85% 감소 |
| 정면 경계 안 59도 | 15.0 | 경계가 흔들리지 않는다 |
| 정면 경계 밖 61도 | 100.0 | ±60도(총 120도)가 정확한 경계 |
| 측면 90도 | 100.0 | 감소 없음 |
| 후면 180도 | 100.0 | 감소 없음 |

상태별(정면 100 기준):

| 상태 | 실제 피해 | 방패 |
|---|---:|---|
| `approach`(접근·이동) | 15.0 | 닫힘 |
| `bash_aim`(방패치기 준비) | 15.0 | **닫힘**(이번에 바뀐 부분) |
| `bash`(실제 방패치기) | 100.0 | 열림 |
| `recover`(공격 후 빈틈) | 150.0 | 열림 + 빈틈 노출 배율 ×1.5 |

> 빈틈의 150은 "방패가 열려 100" 위에 기존 빈틈 규칙(`build.exposed_mult` = 1.5)이 곱해진 값이다.
> 이 규칙은 원래 있던 것이고 이번에 만들지 않았다.

## 2. 우회 관계 (현재 동작을 측정해서 적는다 — 바꾸지 않았다)

방패는 **직접 공격만** 막는다. 판정 조건은 `PEnemiesNew._blockable(opt)` 한 곳에 모여 있다:

```
막힌다  : opt.src.direct == true 이고 extra 아님, skill 아님, opt.dot 없음
안 막힌다: 바닥·추가 효과(extra) · 기술 피해(skill) · 지속 피해(dot: 화상·출혈)
```

측정값(정면에서 100을 넣었을 때):

| 피해 종류 | 실제 피해 | 방패 |
|---|---:|---|
| 자동기술 직접 타격(근접·투사체) | 15.0 | 막는다 |
| 바닥·추가 효과(잔불 등 `extra`) | 100.0 | 우회 |
| 지속 피해(화상·출혈 `dot`) | 100.0 | 우회 |
| 기술(Q/E 계열 `skill`) | 100.0 | 우회 |

즉 **바닥 장판과 지속 피해로는 방패병을 정면에서도 그냥 녹일 수 있다.** 기존 관계 그대로 유지했다.

## 3. 출처 방향(어디서 온 공격인가) 규칙

`shield_mult`는 `opt.from`(공격이 시작된 점)에서 방패병으로 향하는 각을 본다.
공격 종류별로 무엇이 `from`이 되는지는 아래와 같다. **`scripts/rules/weapons.gd`가 정본이고 이번에 바꾸지 않았다.**

| 공격 | `from` | 뜻 | 확인 |
|---|---|---|---|
| 근접 부채꼴 `hit_arc` | 시전 시작점 `(fx0, fy0)` | 휘두른 자리(대개 플레이어 위치) | 검사에서 측정 |
| 직선 `hit_beam` | 시전 시작점 | 같은 규칙 | 코드 확인 |
| 원형 범위 `hit_circle` | 원의 중심 `(cx, cy)` | 폭발 중심(플레이어 위치가 아니다) | 코드 확인 |
| 투사체 적중 `on_projectile_hit` | `(pr.x, pr.y)` = **충돌 직전 위치** | 화살이 날아온 쪽 | 검사에서 측정 |
| 공전 칼날 | 칼날 위치 `(bp.x, bp.y)` | 몸이 아니라 칼날이 온 쪽 | 코드 확인 |
| 사슬(연쇄 번개) | 직전 연쇄 지점 | 튀어 온 쪽 | 코드 확인 |
| **from이 없는 경우** | **플레이어 현재 위치**로 대체 | 아래 결함 참고 | 검사에서 측정 |

### 귀환(부메랑) 공격

부메랑도 결국 `on_projectile_hit`을 지나므로 **돌아오는 순간의 투사체 위치**가 출처가 된다.
따라서 방패병 뒤로 던져 돌아오는 검기는 후면 판정이 되어 감소 없이 들어간다. 의도한 동작이며 검사 항목(투사체 = 충돌 직전 위치)으로 고정했다.

### 알려진 결함 (이번에 고치지 않았다 — 담당 밖 파일)

`from`을 넘기지 않는 두 경로가 있고, 그 경우 **플레이어의 현재 위치**가 출처가 된다.
플레이어와 실제 타격 지점이 다른 상황에서 방패 판정이 사실과 어긋난다.

| 위치 | 내용 | 왜 문제인가 |
|---|---|---|
| `scripts/rules/weapons.gd:334` | 연쇄 번개의 **첫 대상 되돌아오기**(`{"knock":0.0,"loop":true}`) | 튀어 온 방향이 아니라 플레이어 방향으로 판정된다 |
| `scripts/rules/weapons.gd:487` | 공전 칼날 **잔향(echo)** 재타격 | 칼날이 아니라 플레이어 방향으로 판정된다 |

두 곳 모두 `weapons.gd`(내 담당 밖)라 손대지 않았다. 고친다면 각각 `"from": from`(직전 연쇄 지점),
`"from": {"x": bp.x, "y": bp.y}`(칼날 위치)를 넣으면 된다.

## 4. 판정이 흔들리지 않는가

| 점검 | 결과 |
|---|---|
| 정면 각도 경계(±60도) | 59도 = 감소, 61도 = 정상. 경계에서 값이 튀지 않는다 |
| 준비 → 실행 전환 | `bash_aim`(닫힘) → `bash`(열림)에서 한 단계 만에 명확히 바뀐다. 중간 상태 없음 |
| 감속장 안 방향 전환 | `face`는 `adv = dt × time_factor`로 돌기 때문에 감속장(×0.4) 안에서는 회전도 같이 느려진다. 감속 중 정면이 갑자기 따라붙는 일은 없다 |
| 방향 전환 속도 | 1초에 126도(2.2 rad/s). 플레이어 이동 220으로 반지름 60을 돌면 초당 약 210도라 항상 옆을 잡을 수 있다 |
| 피해 감소 중복 | **없다.** `shield_mult`가 여러 방어 효과를 곱하지 않고 `min`으로 가장 강한 하나만 쓴다. 깃발 지원(0.85)과 방패 정면(0.15)이 겹쳐도 결과는 15.0(0.1275가 아니다) |
| 다른 경로의 중복 | 일반 적의 피해 감소 경로는 `damage_enemy` 안 `PEnemies.shield_mult` 한 곳뿐이다(보스는 `PBoss3.shield_mult`로 갈라진다). 두 번 곱해지는 경로는 없다 |

## 5. 막기 연출

**실제 방어 판정이 일어난 순간에만** 신호를 낸다. 규칙 쪽(`PEnemiesNew.note_block`)이 피해 적용 직후
같은 `opt`로 `shield_mult`를 한 번 더 물어보고(부작용 없는 조회) 1보다 작을 때만 아래를 내보낸다.

| 신호 | 내용 |
|---|---|
| 방패 타격 효과 | `fx {kind:"burst", color:"#e8e8f0"}` — 방패 앞면(몸 반지름 + 6)에서 흰 고리 |
| 불꽃 | `fx {kind:"spark"}` — 공격이 온 반대 방향으로 튀는 불꽃 |
| 짧은 '방어' 표시 | `text "방어"` (0.8초) |
| 금속음 | `ev("shatter")` — 짧은 고음 사각파(오디오에 이미 있는 소리) |
| 연타 방지 | 같은 개체는 0.15초에 한 번만 연출(판정 자체는 매번 그대로) |

**방어 중과 열린 상태의 외형 구분**은 이미 `scripts/game/render.gd`가 하고 있다:
`blocked_t > 0`이면 방패가 흰색으로 번쩍이고 "막음"이 뜨며, 방패가 열리면 방패가 −1.2 rad 젖혀진다.
`blocked_t`는 `damage_enemy`가 감소가 일어날 때 0.2초로 켠다.

### 담당 밖 파일에 필요한 변경 (고치지 않고 보고)

`scripts/game/render.gd:1464` (`draw_shieldbearer`)

```gdscript
var open: bool = stt == "bash_aim" or stt == "bash" or stt == "recover"
```

규칙이 바뀌어 **`bash_aim`(준비 중)에는 방패가 닫혀 있는데 화면은 열린 것처럼 그린다.** 아래로 바꿔야 외형과 판정이 맞는다.

```gdscript
var open: bool = stt == "bash" or stt == "recover"
```

같은 파일의 예고 표시(`render.gd:1933`, `type == "shieldbearer" and stt == "bash_aim"`)는 그대로 두어야 한다
(방패치기 예고 부채꼴은 계속 보여야 하고, 규칙의 상태 이름도 바꾸지 않았다).

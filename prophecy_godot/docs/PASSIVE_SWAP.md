# 패시브 교체 — 빈틈 포착·지속력 → 회피 숙련·흡혈 (2026-09-10 첫 시험값)

사용자 지시 1절. **여기 수치는 전부 첫 시험값이고 승인된 밸런스가 아니다.**
구조(패시브 보유 한도 4종 · 각 최대 Lv3)는 그대로 둔다.

## 1. 무엇을 바꿨나

| | 예전 | 지금 |
|---|---|---|
| 신규 획득 후보 | 건강·강인함·무기 숙련·가속·기동력·집중·**빈틈 포착·지속력** | 건강·강인함·무기 숙련·가속·기동력·집중·**회피 숙련·흡혈** |
| 빈틈 포착·지속력의 효과 계산 | 있음 | **그대로 있음**(지우지 않았다) |
| 이미 보유한 회차 | — | 값·효과·레벨업 후보 모두 그대로 |

구현 자리:
- `data/growth.json` `passives.exploit.offer = false` · `passives.persistence.offer = false`
- `scripts/rules/growth.gd` 후보 생성에서 **레벨 0일 때만** 그 항목을 건너뛴다
- `scripts/rules/build.gd`의 `exposed_mult`·`duration_mult` 계산은 **그대로 남겨 두었다**

## 2. 신규 후보 제외와 기존 저장 처리는 다른 문제다

- **신규 후보 제외**(이번에 구현했다): 레벨 0인 빈틈 포착·지속력을 성장 3택에 내지 않는다.
  새 회차에서는 이 둘을 새로 얻을 길이 없다.
- **기존 저장 처리**(아래 안만 제시한다 — 결정 전에는 아무것도 하지 않는다):
  이미 Lv1~3을 가진 저장을 어떻게 할 것인가.

지금 상태(결정 전 보존)에서 기존 저장은:
1. 값이 그대로 남는다(`growth.passives.exploit` 등을 지우거나 다른 id로 바꾸지 않는다).
2. 효과가 그대로 계산된다(빈틈 배율·지속 배율이 예전과 같다).
3. 레벨업 후보로 **계속 나온다** — 보유분이 오르지 못하는 죽은 슬롯이 되지 않게.
4. 저장 왕복·빌드 계산·화면 표시 어디에서도 오류를 내지 않는다.

검사: `tests/qe_tests.gd` `sec_passive_swap()`.

## 3. 이전 처리안 (제시만 — 사용자가 고르기 전에는 실행하지 않는다)

### 안 A. 그대로 둔다 (지금 상태, 기본값)
- 옛 저장은 옛 패시브를 계속 쓰고 레벨업도 계속할 수 있다.
- 장점: 아무것도 잃지 않는다. 구현 비용 0(이미 그렇다).
- 단점: 옛 회차와 새 회차의 패시브 구성이 다르다. 빈틈 포착·지속력을 아는 코드가 계속 남는다.

### 안 B. 보유는 유지하되 **레벨업 후보에서도 뺀다**
- 지금 값·효과는 그대로. 다만 더 올릴 수 없다.
- 장점: 새 회차와 옛 회차의 성장 경로가 같아진다.
- 단점: 슬롯 하나가 지금 레벨에 묶인다(체감상 손해). 슬롯 반환 규칙이 따로 필요할 수 있다.

### 안 C. 같은 슬롯 수·같은 레벨로 **자동 치환**
- 빈틈 포착 Lv n → 회피 숙련 Lv n, 지속력 Lv n → 흡혈 Lv n.
- 장점: 슬롯 수·투자량이 보존되고 새 표에 맞춰진다.
- 단점: **사용자가 고르지 않은 패시브가 생긴다.** 빌드 성격이 조용히 바뀐다
  (빈틈 포착은 화력, 회피 숙련은 생존이다). 지시의 "임의로 치환하지 마라"에 정면으로 걸린다.

### 안 D. 슬롯을 비우고 **다음 레벨업 때 다시 고르게 한다**
- 빈틈 포착·지속력을 제거하고, 제거한 수만큼 '패시브 재선택' 제시를 예약한다.
- 장점: 사용자가 직접 고른다. 투자량도 보존된다.
- 단점: 새 제시 종류(재선택)를 만들어야 한다 — 성장 흐름·저장 형식·화면이 함께 바뀐다.
  제시를 받기 전까지 슬롯이 비어 그 구간 동안 실제로 약해진다.

### 안 E. 회차별 표를 저장에 적어 둔다(회차 고정)
- 회차를 시작한 시점의 패시브 목록을 저장에 적고, 그 회차는 끝까지 그 표를 쓴다.
- 장점: 진행 중인 회차의 규칙이 도중에 바뀌지 않는다.
- 단점: 표 판본이 저장에 늘어난다. 이후 교체마다 판본이 하나씩 더 생긴다.

**권고: 안 A(지금 상태)를 기본으로 두고, 사용자가 옛 패시브를 완전히 없애기로 하면 안 D.**
안 C는 지시가 금지한 임의 치환이라 권하지 않는다.

## 4. 새 패시브 두 종

### 회피 숙련 (`dodge_mastery`)
Lv1 −5% · Lv2 −10% · Lv3 −15%. **무기별 기본 재사용 시간에 비례.**

| 주무기 | Lv0 | Lv1 | Lv2 | Lv3 |
|---|---|---|---|---|
| 쌍검 | 0.900 | 0.855 | 0.810 | 0.765 |
| 검 | 1.100 | 1.045 | 0.990 | 0.935 |
| 관통창 | 1.300 | 1.235 | 1.170 | 1.105 |
| 전투망치 | 1.600 | 1.520 | 1.440 | 1.360 |
| 추적궁 | 2.200 | 2.090 | 1.980 | 1.870 |

- 곱하는 자리는 `CombatState.update_player`의 `p.dodge_cd = p.dodge_cd_time × build.dodge_cd_mult` **한 곳뿐**이다.
  거리(`D.distance`)·이동 시간(`D.duration`)·무적(`p.dodge_invuln_time`)은 이 값을 읽지 않는다.
- 무기별 회피 차이는 그대로다(같은 레벨에서 쌍검 < 검 < 창 < 망치 < 활).
- 잔영 허물 같은 회피 변형 장비의 효과 수치(지속·반지름·횟수)는 건드리지 않는다.

검사: `tests/main_weapon_tests.gd` `sec12_dodge_mastery()` — 실제로 두 번 회피해서 잰다.

### 흡혈 (`lifesteal`)
검·쌍검·창·망치 Lv1 0.5% / Lv2 1.0% / Lv3 1.5% · **추적궁** Lv1 0.25% / Lv2 0.5% / Lv3 0.75%.

- 기준은 그 타격이 **실제로 깎은 적 체력**(`effective`)이다. 초과 피해는 애초에 그 값에 들어가지 않는다.
- 자격 판정은 자격표 어휘 한 곳(`PSupport.cause_of` → `CombatState.frost_cause_of`)만 쓴다.
  표는 `data/growth.json` `growth.LIFESTEAL`에 있다.

| 출처(자격표 어휘) | 흡혈 |
|---|---|
| 주무기 기본 타격 `main_direct` | **적격** |
| 주무기 개조가 만든 추가 타격 / 공용 메아리·연사 `main_extra` | 제외 (아래 사유) |
| 보조무기 직접 타격 `support_direct` | 제외 |
| 잔영 분신 `echo_direct` · 장판 `zone_tick` · 도트 `dot` · 반사 `reflect` | 제외 |
| 감전 후속·방전·복제 `shock_bonus`/`shock_discharge`/`shock_echo` | 제외 |
| 지뢰·인형 폭발 `mine_blast`/`doll_blast` · 파쇄 `frost_shatter`/`frost_shard` | 제외 |
| 불꽃 파열 `flare_burst` · 까마귀 폭발 `crow_burst` · 돌풍 충돌 `wind_slam` · 숙주 파열 `plague_burst` | 제외 |
| 수동 기술(감속장·돌풍·칼날 폭풍·낙뢰·중력핵·수호 결계) | 제외 |
| 장비 기술 여섯 `eq_slash`/`eq_meteor_core`/`eq_meteor_wave`/`eq_riposte`/`eq_retrace`/`eq_icetomb` | 제외 |

**`main_extra`를 제외한 이유(미확정 — 사용자 결정 필요).**
자격표의 이 한 칸에 두 가지가 함께 들어 있다: ① 주무기 **개조**가 만든 추가 타격(교차 검격·분열 창날 등)과
② 공용 증강 **메아리·연사**가 만든 추가 타격. 켜면 ②까지 조용히 자격을 얻는다 —
사용자가 경고한 "기존 출처 분류 오류 때문에 보조 폭발 등이 섞이는" 자리가 바로 여기다.
그래서 첫 구현은 껐고, 켜려면 `data/growth.json` `growth.LIFESTEAL.denied`에서 `"main_extra"`를 빼
`eligible`로 옮기면 된다(코드는 고치지 않는다). ①만 켜고 ②는 끄려면 자격표에 새 경로 이름을 하나 더
만들어야 하는데, 그 표는 `data/supports.json`이고 이번 작업의 소유 밖이라 손대지 않았다.

- **소수점을 버리지 않는다.** 6 피해 × 40회에서 1회 회복 0.030이 그대로 40번 쌓여 1.200이 된다.
- 최대 체력을 넘겨 회복하지 않고(`minf`), 체력이 0이면 회복하지 않는다(사망을 되돌리지 않는다).
- 시간당 자동 재생 없음 · 전투당 회복 상한 없음.

검사: `tests/main_weapon_tests.gd` `sec13_lifesteal()`.

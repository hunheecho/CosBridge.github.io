# 설계 변경 이력 (무엇을 언제 왜 바꿨는가)

기록일: 2026-09-07. 정확한 과거 날짜가 없는 항목은 버전·대화 순서로만 표시한다.
D 번호는 Codex가 2026-09-07 공유 초안에서 대화를 복원하며 부여한 식별자이며 당시의 발행 번호가 아니다. D01~D30 본문은 초안을 옮긴 것이고, 사용자 발언 인용은 초안의 복원문이다(구현자가 대화 원문을 다시 확인한 것은 아니다). "→ 이후" 줄은 저장소 최신 상태(godot-0.3.1, 2026-09-07)와 대조해 구현자가 덧붙였다.
초기 제안과 폐기안이 구현된 적이 있었다고 가정하지 않는다. 현재 규칙은 `prophecy_godot/docs/RULES.md`(Godot)·`prophecy_action_prototype/docs/GAME_SPEC.md`(HTML), 현재 수치는 각 `ASSUMPTIONS.md`를 따른다. 이 문서에 규칙·수치를 복제하지 않는다.

## 변경 기록 형식

향후 추가할 때: ID / 실제 결정일과 시간대 / 기록일 / 결정 주체 / 설계 상태 / 이전 → 이후 / 바꾼 이유와 사용자 발언 또는 검수 증거 / 대체하는 결정 ID / 적용 커밋·검증 커밋·미해결 항목. 날짜·근거·커밋을 모르면 미상으로 남긴다. 같은 결정이 구현되면 기존 기록에 적용 근거를 추가하고, 다른 결정으로 바뀌면 새 ID를 부여한다.
상태 축은 `docs/PROJECT_CONTEXT.md` §5(설계 상태 / 구현 상태, 사용자 결정 / 시험값 / 구현자 보고 / 독립 검증 구분).

## D01 — 옛 전투 → 실시간 액션
- 시점: 초기 액션 전환 논의·정확한 날짜 미상. 상태: 사용자 합의.
- 변경: 타임라인 중심 전투에서 자동 공격·이동·회피가 있는 액션으로 전환.
- 이유·근거: 타임라인을 파훼·우회하는 재미와 상태 가시성이 약했고 성장 기대도 없었다. 사용자가 "전투 자체를 뱀서라이크로 하는건 어때?" 제안 후 실제 액션판에 "일단 재미는 있어"라고 평가.
- 영향·검증: HTML 액션판 구현·사용자 플레이 확인. Godot에서도 핵심 전투 의도 보존(D29, D33).

## D02 — 첫 구현 도구로 HTML 선택
- 시점: 첫 액션 프로토타입·날짜 미상. 상태: 당시 구현 선택; D29로 대체됨.
- 변경: 원격 Linux 환경에서 Canvas·JavaScript·단일 HTML을 사용.
- 이유·근거: 기존 Windows 프로젝트에 접근할 수 없고 브라우저 실행·배포가 편하다는 구현자의 결정. 엔진 가격 때문이 아니었음(`TECH_DECISION.md` 기록과 일치).
- 영향: HTML은 비교 자료. 새 HTML 콘텐츠는 추가하지 않는다.

## D03 — 자동 공격 구성과 수동 슬롯

## D04 — 회피 성공 보상 중심 빌드 배제

- 영향: 다른 개조를 추가할 때 폐기된 축을 무심코 부활시키지 않음. Godot의 "회피!"(무적 중 피해 거부) 표시·집계는 내부 통계이며 보상과 연결하지 않는다.

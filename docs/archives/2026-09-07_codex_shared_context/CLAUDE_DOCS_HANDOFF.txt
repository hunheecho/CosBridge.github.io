이 첨부 묶음은 Codex가 현재 대화의 게임 설계·변경 이유·검수 상태를 복원한 공유 문서 초안이다.
원격 Claude가 사용자의 Windows 로컬 경로를 읽을 수 있다고 가정하지 말고, 실제 첨부된 파일 또는 저장소에서 자료를 읽어라.

목표:
매번 긴 대화를 다시 읽지 않고, 너와 Codex가 현재 규칙·왜 바뀌었는지·무엇이 실제 검증됐는지를 같은 문서로 파악하게 한다.
현재 승인된 Godot 첫 전투 준비 작업을 유지하면서, 문서 정리를 필요한 범위로 병행해라.

1. 이 묶음의 README → PROJECT_CONTEXT → CURRENT_DESIGN_DRAFT → DESIGN_DECISIONS → IMPLEMENTATION_STATUS를 읽어라.
evidence/V080_AUDIT.md는 해당 구현을 점검할 때 읽어라.

2. 현재 저장소의 GAME_SPEC.md, ASSUMPTIONS.md, TRACEABILITY.md, HANDOFF.md와 대조해라.
이 묶음은 7ec93cd까지의 검수 상태다. 이후 수정이 있으면 최신 커밋과 재현 결과로 상태를 갱신해라.
옛 상태로 최신 수정을 되돌리지 마라.

3. 공식 문서는 역할별 한 곳만 유지해라.
- PROJECT_CONTEXT: 의도·현재 초점·읽기 순서·문서 운영.
- GAME_SPEC: 현재 규칙.
- ASSUMPTIONS: 현재 시험값·이전값·근거·적용 버전.
- DESIGN_DECISIONS: 무엇을 언제 왜 바꿨는지, 폐기·대체 관계.
- TRACEABILITY: 요구별 구현 상태·구현자 검증·독립 검증.
- HANDOFF: 현재 상태·막힌 것·바로 다음 작업.
- 개별 검수/시뮬레이션은 별도 증거 파일.

실제 문서 위치는 기존 경로를 확인해서 한 번 정하고 PROJECT_CONTEXT에서 정확히 연결해라.
HTML과 Godot에 서로 다른 설계 정본을 복제하지 마라. 두 프로젝트가 같은 설계 문서를 참조하게 해라.
파일 이동이 기존 링크를 깨뜨린다면 당장 모두 이동하지 말고 공통 진입 문서에서 기존 정본으로 연결해도 된다.

4. CURRENT_DESIGN_DRAFT는 기존 GAME_SPEC와 ASSUMPTIONS에 병합해라.
IMPLEMENTATION_STATUS는 TRACEABILITY와 HANDOFF에 병합해라.
병합한 초안 파일을 두 번째 현재 명세로 계속 운영하지 마라.
보관할 경우 날짜가 붙은 archives 아래에 “과거 통합 초안, 현재 규칙 아님”으로 표시한다.

5. 변경 이력은 대화 전문을 복사하지 말고 중요한 결정을 기록해라.
형식:
ID / 결정일 / 기록일 / 결정 주체 / 상태 / 이전→이후 / 이유 / 근거 / 대체하는 ID / 적용·검증 커밋.
과거 날짜를 모르면 “날짜 미상, v0.7.2 이후”처럼 표시한다.
가정으로 정한 값을 “사용자 지정”으로 바꾸지 마라.
사용자 시험안 채택과 최종 밸런스 승인을 구분한다.

6. 기존 문서의 모순을 정리해라.
예:
- 회전 칼날 10/0.35가 이미 적용됐는데 다른 절에서 미적용이라고 적은 내용.
- 옛 기본값이 최신 기본값처럼 적힌 부분.
- 테스트 개수·실행 커밋이 서로 다른데 같은 검증 결과처럼 적은 내용.
- v0.8 완료 표시와 독립 검수 F1~F8 충돌.
- HANDOFF에 과거 버전 전체 일지가 쌓여 있는 문제.

과거 사실을 삭제하지 말고 변경 이력·보관 문서로 옮긴다.
현재 규칙은 현재 시제로 한 번만 적는다.

7. 작업 규칙에 다음 절차를 연결해라.
- 새 세션 시작: PROJECT_CONTEXT, 최신 HANDOFF, 관련 명세·시험값 읽기.
- 작업 시작: 적용 결정 ID와 미해결 이슈 확인.
- 작업 종료: 변경한 규칙·수치·구현·검증 상태와 다음 작업 갱신.
- 중요한 사용자 결정이 바뀌면 새 결정 ID와 이전 결정의 대체 관계 기록.
- 구현 완료와 독립 검증 완료는 별도 표시.
- 문서 업데이트를 위해 무관한 문서 전체를 매번 다시 작성하지 않음.

구현자용 진입 규칙(CLAUDE.md 등)의 기존 내용을 보존하며 짧은 읽기·갱신 안내를 추가해라.
Codex의 Independent Auditor Rules는 약화하거나 구현자 규칙으로 바꾸지 마라.
Codex는 저장소를 직접 수정하지 않고 검수 보고·변경 제안으로 참여한다.

8. 단순 문서 정리를 이유로 일반적인 확인 질문을 반복하지 마라.
명백히 합의한 내용은 통합한다.
진짜 결정이 필요한 미확정 정책은 열린 항목에 남기고 독립적으로 진행 가능한 작업을 계속해라.

9. 완료 시:
- 공통 진입 문서의 저장소 경로·커밋.
- 현재 규칙/변경 이력/시험값/검증 상태의 공식 위치.
- 발견한 충돌과 해결 근거.
- 아직 사용자 결정이 필요한 항목.
만 간결하게 보고해라.

이후 구현을 마칠 때마다 위 문서들을 작업의 일부로 갱신해라.
백그라운드 자동 감시를 등록했다거나 다른 에이전트가 자동으로 모든 대화를 기억한다고 주장하지 마라.

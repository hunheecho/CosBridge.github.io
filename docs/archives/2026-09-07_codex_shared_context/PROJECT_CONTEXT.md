## 어떤 게임인가

마검사가 제한된 준비 기간 동안 출격하고, 성장과 장비를 선택하며, 다가오는 보스 관문에 대비하는 2D 실시간 액션 게임이다.
자동기술 3개와 Q 감속장, E 수동기술, Space 회피를 조합한다.
세계관의 세부 설정은 이 대화에 확인된 범위 이상으로 새로 확정하지 않는다.

## 플레이어가 느껴야 할 재미

- 적의 예고를 보고 이동·회피·감속장으로 대응한다.
- 새 기술·개조·장비가 다음 전투에서 무엇을 바꿀지 기대한다.
- 오늘의 장소 2곳, 시간대 변화, 체력과 보상을 보고 하루를 계획한다.
- 더 깊이 들어갈 이익과 현재 전리품·남은 하루를 잃을 위험을 비교한다.
- 금화는 빌드와 대응 방식을 바꾸는 선택에 사용한다.
- 출격이 재료와 패시브 수치만 채우는 반복 노동이 되지 않게 한다.

사용자 관측: 액션 전투 방향 자체는 재미있다. 경험치 ×0.3의 속도는 유지할 가치가 있다고 직접 평가했다.
이 두 관측을 나머지 밸런스 전체의 승인으로 확대하지 않는다.

## 현재 작업 우선순위

1. 별도 Godot 4.x 안정판 GDScript 환경 준비.
2. 검격·늑대·이동·회피·감속장·장애물·승패가 있는 작은 전투 한 판.
3. 엔진 실행 검사, 가능한 실제 렌더링 확인, 프로젝트 ZIP·가능한 Windows 빌드.
4. 사용자가 첫 Godot 전투를 확인한 뒤 후속 이식 범위 결정.

전체 성장·경제·지역·3보스 설계는 목표로 보존하지만 Godot 첫 전투의 필수 완료 조건과 구분한다.
현재 HTML은 비교 기준이며 새 기능을 계속 양쪽에 동시에 추가하지 않는다.
기존 작업은 안전하게 보존한다.

## 되돌리지 말아야 할 방향

- 경험치 구슬·자석 없음. 처치 즉시 획득.
- 경험치 ×0.3을 과거 레벨업 횟수 목표 때문에 임의로 올리지 않음.
- 회피 성공 보상 획득을 핵심 성장 축으로 다시 만들지 않음.
- 장비 무기와 자동기술을 같은 슬롯·같은 개념으로 섞지 않음.
- 장비는 런 한정. 영구 장비 강화와 반복 재료 노가다를 새로 추가하지 않음.
- 정예 하나를 죽였다고 일반 전멸전을 끝내지 않음.
- 전투가 쉽다는 이유로 강제 보스 무적·피해 상한·숨은 플레이어 비례 스케일링을 넣지 않음.
- 그래픽 대량 제작은 후순위.
- 기본 화면에 개발용 설명과 문서를 길게 노출하지 않음.
- 테스트 통과나 봇 승률을 사람의 재미·밸런스 승인으로 표현하지 않음.

## 근거와 상태의 우선순위

의도한 규칙: 최신 명시적 사용자 결정 → 승인된 구현 지시문 → 현재 명세.
코드가 명세와 다르면 코드가 저절로 새로운 합의가 되는 것이 아니다.
동시에 실제 동작 판단은 해당 커밋의 실행 증거를 따른다. 합의했다고 구현됐다고 적지 않는다.

상태는 두 축으로 기록:
- 설계 상태: 제안 / 사용자 합의 / 시험 적용 / 보류 / 대체됨.
- 구현 상태: 미구현 / 구현자 보고 / 독립 확인 / 문제 재현 / 미검증.

시험값 채택 동의와 최종 밸런스 승인을 구분한다.
숲·습지 등의 구체적인 출격 비용이나 보상 배율을 구현자가 정했다면 그 사실을 기록한다. 일괄 “사용자 지정”으로 바꾸지 않는다.

## 새 세션 시작 절차

1. 이 문서, 최신 HANDOFF, 관련 GAME_SPEC·ASSUMPTIONS·TRACEABILITY를 읽는다.
2. 현재 브랜치·HEAD·작업 트리·실행 중인 작업을 확인한다.
3. 이식 기준과 최신 검수 커밋이 다르면 미검증 변경 범위를 확인한다.
4. 적용되는 결정 ID와 미해결 문제 ID를 적는다.
5. 이미 기록된 결정을 같은 이유로 반복 질문하지 않고 승인된 범위를 진행한다.
